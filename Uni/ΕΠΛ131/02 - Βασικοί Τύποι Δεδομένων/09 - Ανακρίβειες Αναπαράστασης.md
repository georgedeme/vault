# 09 - Ανακρίβειες Αναπαράστασης

Γιατί οι υπολογιστές κάνουν «λάθη» στους αριθμούς: τα τέσσερα είδη σφαλμάτων αναπαράστασης (διαφάνειες II-51 … II-54).

## 1. Λάθος αναπαράστασης (στρογγυλοποίησης)

> [!note] Ορισμός (II-52)
> **Λάθος αναπαράστασης**: λάθος που απορρέει από την κωδικοποίηση ενός πραγματικού αριθμού με χρήση **περιορισμένου αριθμού δυαδικών ψηφίων**.
> - Αναφέρονται και ως **λάθη στρογγυλοποίησης** (round-off errors).
> - Π.χ. ο αριθμός **0.1** έχει λάθος αναπαράστασης ως τιμή `double`.
> - Η επίδραση ενός μικρού λάθους **μεγεθύνεται σε επαναληπτικούς υπολογισμούς**.

```java
for (trial = 0.0; trial != 10.0; trial += 0.1) { … }   // ✗ μπορεί να μην τερματίσει ποτέ
for (trial = 0.0; trial <= 10.0; trial += 0.1) { … }   // ✓ καλύτερα
```

> [!example]- Γιατί ο πρώτος βρόχος δεν σταματά
> Το 0.1 στο δυαδικό είναι περιοδικό κλάσμα (όπως το 1/3 στο δεκαδικό) και κόβεται. Μετά από 10 προσθέσεις του 0.1 **δεν** παίρνεις ακριβώς 1.0:
> ```java
> double d = 0.0;
> for (int i = 0; i < 10; i++) d += 0.1;
> System.out.println(d);          // 0.9999999999999999
> System.out.println(d == 1.0);   // false
> ```
> Έτσι το `trial` «πηδάει» πάνω από το 10.0 χωρίς να γίνει ποτέ ακριβώς ίσο → το `!=` μένει για πάντα `true`.
> Άλλα κλασικά: `0.1 + 0.2` → `0.30000000000000004` · `(0.1 + 0.2) == 0.3` → `false`.

> [!important] Σύγκριση πραγματικών αριθμών (III-3)
> Ποτέ `==` / `!=` σε `double`. Σύγκρινε με **ανοχή** (epsilon):
> ```java
> 1.29999 == 1.2999                          // false
> Math.abs(1.29999 - 1.2999) < 0.0001        // true
> ```

> [!warning] Ο αριθμός επαναλήψεων με `double` είναι αναξιόπιστος ➕
> `for (double d = 0.0; d <= 1.0; d += 0.1)` εκτελείται **11** φορές (το τελευταίο `d` είναι 0.9999…, όχι 1.0). Με άλλο βήμα μπορεί να βγει μία λιγότερη. Προτίμησε **ακέραιο μετρητή**: `for (int i = 0; i <= 10; i++) { double d = i / 10.0; … }`.

## 2. Λάθος ακύρωσης

> [!note] Ορισμός (II-53)
> **Λάθος ακύρωσης**: λάθος που απορρέει από την εφαρμογή αριθμητικών τελεστών σε τελεστέους με **πολύ διαφορετικά μεγέθη** – επί της ουσίας **ο μικρότερος τελεστέος χάνεται**.

```java
double a = 1;
double b = a + 0.00000000000000001;   // 1e-17
System.out.print(a + " " + b);        // 1.0 1.0
```
Το `double` έχει ~15–16 σημαντικά ψηφία· το 1e-17 είναι πέρα από αυτά σε σχέση με το 1.

## 3. Λάθος υπορροής (underflow)

> [!note] Ορισμός (II-53)
> **Λάθος υπορροής** (underflow error): συμβαίνει όταν μία **πολύ μικρή** αριθμητική τιμή αναπαριστάται ως **το μηδέν**.

```java
double a = 0.01;
double b = a + 0.0000000000000000001;  // 1e-19
System.out.print(a + " " + b);          // 0.01 0.01
```

> [!warning] ⚠️ Σημείωση για το παράδειγμα της διαφάνειας
> Το παράδειγμα της διαφάνειας στην πραγματικότητα δείχνει **ακύρωση** (ο μικρός όρος χάνεται δίπλα στον μεγάλο), όχι υπορροή – το `1e-19` μόνο του αναπαρίσταται κανονικά. Καθαρό παράδειγμα υπορροής:
> ```java
> double u = 1e-200 * 1e-200;   // 1e-400 < ελάχιστου double (~4.9e-324)
> System.out.println(u);         // 0.0
> ```

## 4. Λάθος υπερχείλισης (overflow)

> [!note] Ορισμός (II-53)
> **Λάθος υπερχείλισης** (overflow error): συμβαίνει όταν η αριθμητική τιμή που χρειάζεται να αναπαρασταθεί είναι **πολύ μεγάλη**. Μπορεί να συμβεί **και με ακεραίους**.

```java
int a = 2147483647;
int b = a + 1;
System.out.print(a + " " + b);   // 2147483647 -2147483648
```

| Τύπος | Τι γίνεται στην υπερχείλιση |
|---|---|
| `int`, `long` | «τυλίγεται» σιωπηλά στην αρνητική πλευρά – **κανένα μήνυμα** |
| `double` | γίνεται `Infinity` (π.χ. `1e308 * 10`) |

> [!example]- Υπερχείλιση που δεν φαίνεται με την πρώτη ματιά ➕
> - Παραγοντικό σε `int`: `13!` βγαίνει `1932053504` (λάθος) – το σωστό 6227020800 δεν χωράει.
> - `long ms = 1000 * 60 * 60 * 24 * 365;` → λάθος αποτέλεσμα, οι πολλαπλασιασμοί γίνονται σε `int`. Σωστά: `1000L * 60 * …`.
> - Μέσο σημείο στη δυαδική αναζήτηση: `(lo + hi) / 2` μπορεί να υπερχειλίσει για τεράστιους πίνακες· ασφαλέστερα `lo + (hi - lo) / 2` → [[06 - Αναζήτηση και break|IV – Αναζήτηση]].

## 5. Σύνοψη (II-54)

> [!important] Σύνοψη Ενότητας II
> - Ένας τύπος δεδομένων είναι ένα **σύνολο τιμών και λειτουργιών** στις τιμές αυτές:
>   - `String` → επεξεργασία κειμένου
>   - `double`, `int` → μαθηματικοί υπολογισμοί
>   - `boolean` → αποφάσεις
> - **Προσοχή:**
>   - Οι τύποι των τιμών **δηλώνονται**.
>   - **Μετατρέπουμε** ανάμεσα σε τύπους όπου είναι αναγκαίο.
>   - Το 1996, ο πύραυλος **Ariane 5** εξερράγη μετά την απογείωση λόγω **κακής μετατροπής τύπου**.

> [!info]- Τι έγινε στο Ariane 5
> Μια τιμή (οριζόντια ταχύτητα) σε αριθμό κινητής υποδιαστολής 64 bit μετατράπηκε σε **ακέραιο 16 bit με πρόσημο**. Η τιμή ήταν μεγαλύτερη από 32.767 → υπερχείλιση → το σύστημα πλοήγησης έβγαλε σφάλμα και ο πύραυλος αυτοκαταστράφηκε ~37 δευτερόλεπτα μετά την εκτόξευση. Ο κώδικας είχε επαναχρησιμοποιηθεί από τον Ariane 4, όπου η τιμή δεν ξεπερνούσε ποτέ το όριο. (Ένα καλό παράδειγμα για την Ενότητα V: η επαναχρησιμοποίηση κώδικα προϋποθέτει ότι ισχύουν οι ίδιες υποθέσεις.)

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - `==` / `!=` σε `double` (ειδικά ως συνθήκη βρόχου → άπειρος βρόχος).
> - Χρήματα σε `double` (σε πραγματικές εφαρμογές: ακέραια λεπτά ή `BigDecimal`).
> - Να περιμένεις exception στην υπερχείλιση ακεραίων – η Java **δεν** προειδοποιεί.
