# 08 - Ασκήσεις

28 ασκήσεις στο ύφος των διαφανειών της Ενότητας IV. **Λύσε πρώτα, άνοιξε μετά.** Όλες οι απαντήσεις ελέγχθηκαν με `javac`/`java` 17.

> [!tip] Πώς να το χρησιμοποιήσεις
> Σχεδίαζε τον πίνακα ως σειρά από κουτάκια με τους δείκτες από κάτω. Στα ίχνη γράψε ολόκληρο τον πίνακα σε κάθε βήμα που αλλάζει.

## Μέρος Α — Δημιουργία και δείκτες

### Άσκηση 1

Κάνουν compile; Αν ναι, τι γίνεται στην εκτέλεση;
(α) `int[] a = new int[5];` (β) `int a[5];` (γ) `int[] a = {1, 2, 3}; a = {4, 5};` (δ) `int[] a = new int[] {1, 2};` (ε) `double[] d = new double[2.5];` (στ) `String[] s = new String[2]; int n = s[0].length();` (ζ) `int[] a = new int[-3];` (η) `int[] a; a[0] = 1;`

> [!success]- Λύση
>
> | | Compile | Εκτέλεση / σχόλιο |
> |---|---|---|
> | α | ✓ | 5 μηδενικά |
> | β | ✗ | το μέγεθος μπαίνει στο `new`, όχι στη δήλωση |
> | γ | ✗ | λίστα `{…}` μόνο στη δήλωση |
> | δ | ✓ | |
> | ε | ✗ | μέγεθος `double` |
> | στ | ✓ | ✗ `NullPointerException` – `s[0]` είναι `null` |
> | ζ | ✓ | ✗ `NegativeArraySizeException` |
> | η | ✗ | «might not have been initialized» – δεν έγινε `new` |

### Άσκηση 2

Τι τυπώνει;
```java
int[] a = new int[3];      boolean[] b = new boolean[2];   String[] s = new String[2];
double[] d = new double[1]; char[] c = new char[1];
System.out.println(a[0] + " " + b[1] + " " + s[0] + " " + d[0] + " " + (int) c[0]);
```

> [!success]- Λύση
> `0 false null 0.0 0` – οι προεπιλεγμένες τιμές. Το `(int) c[0]` είναι 0 (ο χαρακτήρας `'\u0000'`), **όχι** 48 (που θα ήταν το `'0'`).
> ➕ Παγίδα: το «σύντομο» `new int[3][0]` **δεν** σημαίνει «στοιχείο 0 ενός νέου πίνακα 3 θέσεων» – δημιουργεί **δισδιάστατο** πίνακα 3×0. Θα χρειαζόταν `(new int[3])[0]`.

### Άσκηση 3

Με `double[] x = {16.0, 12.0, 6.0, 8.0, 2.5, 12.0, 14.0, -54.3};` και `int i = 3;` δώσε (ανεξάρτητα): (α) `x[i]` (β) `x[i+4]` (γ) `x[2*i+2]` (δ) `x[(int) x[4]]` (ε) `x[x.length - 1]` (στ) `x[i--]` και την τιμή του `i` μετά (ζ) `x[(int) x[2]]`

> [!success]- Λύση
> (α) `8.0` (β) `x[7] = -54.3` (γ) `x[8]` → ✗ `ArrayIndexOutOfBoundsException` (μήκος 8) (δ) `x[2] = 6.0` (ε) `-54.3` (στ) `x[3] = 8.0`, μετά `i = 2` (ζ) `(int) 6.0 = 6` → `x[6] = 14.0`

### Άσκηση 4

Τι είναι το `args.length` στην εκτέλεση `java P a b c`; Και στο `java P`; Τι γίνεται αν το πρόγραμμα κάνει `args[0]` στη δεύτερη περίπτωση;

> [!success]- Λύση
> `3` · `0` (ο `args` **υπάρχει**, είναι απλά κενός – όχι `null`) · `ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0`.

### Άσκηση 5

Βρες το λάθος: `int sum = 0; for (int i = 0; i <= a.length; i++) sum += a[i];`

> [!success]- Λύση
> `i <= a.length` → στην τελευταία επανάληψη `i == a.length` → `ArrayIndexOutOfBoundsException`. Σωστά `i < a.length`.

## Μέρος Β — Επεξεργασία

### Άσκηση 6

Τι αφήνει ο κώδικας στον `c = {1, 2, 3, 4, 5}`;
```java
for (int i = 0; i < c.length; i++) {
    int tmp = c[i];
    c[i] = c[c.length - 1 - i];
    c[c.length - 1 - i] = tmp;
}
```

> [!success]- Λύση
> **`{1, 2, 3, 4, 5}`** – αμετάβλητος! Μέχρι τη μέση ο πίνακας αντιστρέφεται, από τη μέση και μετά κάθε ζεύγος ανταλλάσσεται **ξανά** και επιστρέφει στη θέση του. Σωστά: `i < c.length / 2`.

### Άσκηση 7

Τι τυπώνει και πώς διορθώνεται;
```java
int[] d = {-5, -2, -9};
int max = 0;
for (int i = 0; i < d.length; i++) if (d[i] > max) max = d[i];
System.out.println(max);
```

> [!success]- Λύση
> `0` ✗ (το σωστό είναι `-2`). Διόρθωση: `int max = d[0];` (και βρόχος από `i = 1`) ή `int max = Integer.MIN_VALUE;`.

### Άσκηση 8

Με `int[] v = {1, 2, 3, 4};` και `int s = 10` (το άθροισμα), τι δίνουν: (α) `s / v.length` (β) `(double) s / v.length` (γ) `(double) (s / v.length)` (δ) `s / (double) v.length`

> [!success]- Λύση
> (α) `2` (β) `2.5` (γ) `2.0` (δ) `2.5`

### Άσκηση 9

Θέλουμε ολίσθηση δεξιά κατά μία θέση στον `a = {1, 2, 3, 4}` (το `a[0]` μένει ίδιο). Τι βγάζει ο κώδικας; Διόρθωσέ τον.
```java
for (int i = 1; i < a.length; i++) a[i] = a[i-1];
```

> [!success]- Λύση
> `{1, 1, 1, 1}` – η τιμή του `a[0]` «σέρνεται» παντού. Σωστά από το τέλος:
> ```java
> for (int i = a.length - 1; i > 0; i--) a[i] = a[i-1];   // {1, 1, 2, 3}
> ```

### Άσκηση 10

Τι τυπώνει;
```java
int[] a = {1, 2, 3};
for (int v : a) v = v * 10;
for (int v : a) System.out.print(v + " ");
```

> [!success]- Λύση
> `1 2 3` – το `v` είναι **αντίγραφο** του στοιχείου· η ανάθεση σε αυτό δεν αλλάζει τον πίνακα. Για αλλαγή: `for (int i = 0; i < a.length; i++) a[i] *= 10;`

### Άσκηση 11

Γράψε κώδικα που, για πίνακα `int[] a`, υπολογίζει: (α) πόσα άρτια στοιχεία έχει (β) τη **θέση** του ελάχιστου (γ) αν είναι ταξινομημένος σε αύξουσα σειρά.

> [!success]- Λύση
> ```java
> // (α)
> int evens = 0;
> for (int v : a) if (v % 2 == 0) evens++;
>
> // (β) – προϋποθέτει a.length > 0
> int minPos = 0;
> for (int i = 1; i < a.length; i++)
>     if (a[i] < a[minPos]) minPos = i;
>
> // (γ)
> boolean sorted = true;
> for (int i = 1; i < a.length && sorted; i++)   // από 1: συγκρίνουμε με τον προηγούμενο
>     if (a[i-1] > a[i]) sorted = false;
> ```
> Στο (α) `v % 2 == 0` δουλεύει και για αρνητικούς (το πρόβλημα είναι μόνο με `== 1`).


> [!success]- Λύση

> true
> false
> true
> ```

### Άσκηση 13

Τι τυπώνει;
```java
static void change(int[] a)   { a[0] = 99; }
static void reassign(int[] a) { a = new int[] {7, 7, 7}; }
static void inc(int x)        { x++; }

// στη main:
int[] arr = {1, 2, 3};
int v = 1;
change(arr);   System.out.println(arr[0]);
reassign(arr); System.out.println(arr[0]);
inc(v);        System.out.println(v);
inc(arr[1]);   System.out.println(arr[1]);
```

> [!success]- Λύση
> ```
> 99
> 99
> 1
> 2
> ```
> Το `inc(arr[1])` περνά την **τιμή** του στοιχείου (ένα `int`), όχι τον πίνακα – άρα δεν αλλάζει τίποτα.

### Άσκηση 14

Γιατί η γραμμή της IV-75 `System.out.println(x == t + " " + x.length == t.length);` δεν κάνει compile; Διόρθωσέ την.

> [!success]- Λύση
> Το `+` προηγείται του `==` → `x == (t + " " + x.length) == t.length` → σύγκριση `int[]` με `String` («incomparable types»). Διόρθωση: `System.out.println((x == t) + " " + (x.length == t.length));`

### Άσκηση 15

Γράψε μέθοδο `static int[] reversed(int[] a)` που επιστρέφει **νέο** πίνακα με τα στοιχεία του `a` ανάποδα, **χωρίς** να αλλάξει τον `a`.

> [!success]- Λύση
> ```java
> static int[] reversed(int[] a) {
>     int[] r = new int[a.length];
>     for (int i = 0; i < a.length; i++)
>         r[i] = a[a.length - 1 - i];
>     return r;
> }
> ```
> Εδώ ο βρόχος πάει μέχρι το τέλος (δεν κάνουμε ανταλλαγές, απλά αντιγραφή σε νέο πίνακα).

## Μέρος Δ — Τράπουλα

### Άσκηση 16

Ποιο χαρτί είναι στις θέσεις 13, 27, 51 (πριν το ανακάτεμα) (α) στην κατασκευή της IV-16 (`deck[i*13 + j]`, εξωτερικός = suit) (β) στην IV-24 (`deck[4*i + j]`, εξωτερικός = rank);

> [!success]- Λύση
>
> | Θέση | IV-16: `suit[k/13]`, `rank[k%13]` | IV-24: `rank[k/4]`, `suit[k%4]` |
> |---|---|---|
> | 13 | 2 of Diamonds | 5 of Diamonds |
> | 27 | 3 of Hearts | 8 of Spades |
> | 51 | Ace of Spades | Ace of Spades |

### Άσκηση 17

Τι κάνει αυτό το «ανακάτεμα»;
```java
for (int i = 0; i < N; i++) {
    int r = i + (int) Math.random() * (N-i);
    String t = deck[r]; deck[r] = deck[i]; deck[i] = t;
}
```

> [!success]- Λύση
> **Τίποτα.** Το cast εφαρμόζεται μόνο στο `Math.random()` → `(int) 0.xx = 0` → `r = i + 0 * (N-i) = i` → κάθε χαρτί ανταλλάσσεται με τον εαυτό του. Χρειάζεται `(int) (Math.random() * (N-i))`.

### Άσκηση 18

Τι πάει στραβά στην ανταλλαγή `deck[r] = deck[i]; deck[i] = deck[r];`;

> [!success]- Λύση
> Μετά την πρώτη εντολή και οι δύο θέσεις έχουν το `deck[i]`· το αρχικό `deck[r]` **χάθηκε**. Η τράπουλα καταλήγει με διπλά χαρτιά και χαμένα άλλα. Χρειάζεται βοηθητική `t`.

### Άσκηση 19

Γιατί στο σωστό ανακάτεμα το `r` διαλέγεται από `[i, N−1]` και όχι από `[0, N−1]`;

> [!success]- Λύση
> Οι θέσεις `0 … i−1` είναι ήδη «τελικές». Διαλέγοντας μόνο από τα υπόλοιπα, κάθε θέση παίρνει ένα χαρτί **ομοιόμορφα** από όσα δεν έχουν τοποθετηθεί → και οι 52! διατάξεις είναι ισοπίθανες. Με `[0, N−1]` υπάρχουν Nᴺ ισοπίθανες ακολουθίες επιλογών που δεν μοιράζονται ισόποσα στις N! διατάξεις → **μεροληψία**.

### Άσκηση 23

Στη γραμμική αναζήτηση με **αντεστραμμένη** συνθήκη `item != x[pos] && pos < x.length`, για ποιες τιμές του `item` σκάει το πρόγραμμα;

### Άσκηση 26

Στη δυαδική αναζήτηση αλλάζουμε `while (Min <= Max)` σε `while (Min < Max)`. Στον `{1, 3, 5, 7, 9, 11, 13, 15}`, ποια στοιχεία δεν βρίσκει πια;

> [!success]- Λύση
> Τα **1, 5, 9, 15** (τα 3, 7, 11, 13 βρίσκονται ακόμα). Είναι όσα καταλήγουν σε διάστημα **ενός** στοιχείου (Min == Max) χωρίς να έχουν «πετύχει» ως μέσο νωρίτερα – π.χ. για το 1: [0,7] → pos 3 → [0,2] → pos 1 → [0,0] → ο βρόχος σταματά χωρίς να ελέγξει τη θέση 0.
> Το λάθος είναι ύπουλο: για τα μισά στοιχεία ο κώδικας «δουλεύει».

### Άσκηση 27

Εφάρμοσε τον έλεγχο πρώτου με `break` (IV-55) για `N = 1, 25, 29`. Τι τυπώνει και πού έχει λάθος;

> [!success]- Λύση
>
> | N | Τελικό `i` | `i*i > N` | Έξοδος |
> |---|---|---|---|
> | 1 | 2 (ο βρόχος δεν τρέχει) | 4 > 1 ✓ | «1 is prime» ✗ **λάθος** |
> | 25 | 5 (`break`: 25 % 5 == 0) | 25 > 25 ✗ | τίποτα ✓ |
> | 29 | 6 (36 > 29, έξοδος χωρίς `break`) | ✓ | «29 is prime» ✓ |
>
> Το 25 δείχνει γιατί η συνθήκη είναι `i*i <= N` (με το ίσο). Διόρθωση για το 1: `if (N > 1 && i*i > N)`.

### Άσκηση 28

Γράψε μέθοδο `static int binarySearch(int[] a, int item)` που επιστρέφει τη θέση του `item` ή `-1`. Δώσε πρώτα ψευδοκώδικα.

> [!success]- Λύση
> ```
> lo ← 0; hi ← n − 1
> while lo ≤ hi:
>     mid ← lo + (hi − lo) / 2
>     if a[mid] = item: return mid
>     if a[mid] < item: lo ← mid + 1
>     else:             hi ← mid − 1
> return −1
> ```
> ```java
> static int binarySearch(int[] a, int item) {
>     int lo = 0, hi = a.length - 1;
>     while (lo <= hi) {
>         int mid = lo + (hi - lo) / 2;     // αποφεύγει υπερχείλιση του lo + hi
>         if (a[mid] == item) return mid;
>         if (a[mid] < item) lo = mid + 1;
>         else               hi = mid - 1;
>     }
>     return -1;
> }
> ```
> Το `return` μέσα στον βρόχο αντικαθιστά το `break` + έλεγχο μετά τον βρόχο.
