# 07 - Εντολή do-while και Ισοδυναμίες Βρόχων

Ο βρόχος που εκτελείται **τουλάχιστον μία φορά**, πώς μετατρέπεται ένας βρόχος στον άλλο, και τα κοινά λάθη σε βρόχους (διαφάνειες III-59 … III-67, III-73 … III-77).

## 1. Εντολή `do-while` (III-59)

> [!note] Σύνταξη
> ```
> do εντολή while (συνθήκη);          do S while (C);
> ```
> ```
>  ──► ┌───┐
>   ┌─►│ S │
>   │  └───┘
>   │    ▼
>   │  ┌────┐  όχι
>   └──│ C? │──────►
>  ναι └────┘
> ```

> [!important] Σημασιολογία
> - **Καταρχήν εκτελείται η εντολή `S`** και **μετά** δοκιμάζεται η συνθήκη `C`.
> - Ενόσω η `C` επαληθεύεται, η εκτέλεση της `S` επαναλαμβάνεται.
> - Επομένως η `S` εκτελείται **τουλάχιστον μία φορά**.
> - Προς αποφυγή άπειρου βρόχου, η `S` πρέπει να οδηγεί σε κατάσταση όπου η `C` **δεν υφίσταται** πλέον.

> [!warning] Το ερωτηματικό στο τέλος
> Το `do-while` **τελειώνει με `;`** μετά την παρένθεση: `} while (A >= B);`. Είναι η **μόνη** εντολή επανάληψης που το θέλει. Αντίθετα, `while (…);` είναι λάθος (κενό σώμα).

## 2. Έλεγχος εγκυρότητας δεδομένων (III-60)

> [!tip] Η `do-while` είναι συνήθως η **πιο κατάλληλη** δομή για τον **έλεγχο εγκυρότητας** δεδομένων
> Πρέπει να διαβάσεις **πρώτα** για να ελέγξεις – άρα το σώμα εκτελείται τουλάχιστον μία φορά.

```java
Scanner in = new Scanner(System.in);
int A, B;
do {
    System.out.print("Enter values for A and B where A < B");
    A = in.nextInt();
    B = in.nextInt();
} while (A >= B);           // επανάλαβε ΟΣΟ τα δεδομένα είναι ΑΚΥΡΑ
```

> [!important] Η συνθήκη του `do-while` είναι το **συμπλήρωμα** της εγκυρότητας
> Θέλουμε `A < B` (έγκυρο) → επαναλαμβάνουμε όσο `!(A < B)`, δηλαδή `A >= B` (βλ. [[01 - Συνθήκες και Λογικές Εκφράσεις|συμπλήρωμα συνθηκών]]).

## 3. Παράδειγμα: Μέσος όρος 10 αριθμών στο [0.0, 10.0] (III-61, III-62)

```java
double sum = 0.0, num;
for (int i = 1; i <= 10; ++i) {
    do
        num = StdIn.readDouble();
    while (num < 0.0 || num > 10.0);     // άκυρος → ξαναδιάβασε
    sum += num;
}
StdOut.println("The average is " + sum/10);
```

**Εναλλακτικός ορισμός** (χωρίς `do-while`):
```java
double sum = 0.0, num;
int count = 0;
while (count < 10) {
    num = StdIn.readDouble();
    if (num >= 0.0 && num <= 10.0) {    // έγκυρος → μέτρα τον
        count++;
        sum += num;
    }
}
StdOut.println("The average is " + sum/10);
```

> [!note] Σύγκριση
> - Στην 1η εκδοχή: φωλιασμένος βρόχος – ο εξωτερικός μετρά **έγκυρους** αριθμούς, ο εσωτερικός επιμένει μέχρι να δοθεί έγκυρος.
> - Στη 2η εκδοχή: ένας βρόχος, οι άκυροι απλά **αγνοούνται**.
> - Άκυρη συνθήκη = `num < 0.0 || num > 10.0` · έγκυρη = `num >= 0.0 && num <= 10.0` – De Morgan η μία της άλλης.
> - Το `StdIn`/`StdOut` είναι από τη βιβλιοθήκη του βιβλίου (βλ. [[Uni/ΕΠΛ131/ΕΠΛ131 II Βασικοί Τύποι Δεδομένων/01 - Δομή Προγράμματος Java|II – 01]]).

## 4. Ακραίες περιπτώσεις (III-63)

```java
do System.out.println("I cannot stop!");
while (true);                                      // άπειρος βρόχος

do System.out.println("I will stop immediately!");
while (false);
// ≡ System.out.println("I will stop immediately!");
```

> [!warning] ⚠️ Σημείωση: πού είναι το «Unreachable code – compile error»;
> Η διαφάνεια σημειώνει «Unreachable code – compile error» δίπλα στο `do … while (true);`. Ο ίδιος ο βρόχος **κάνει compile** κανονικά· το σφάλμα εμφανίζεται μόνο αν υπάρχει **οποιαδήποτε εντολή μετά** από αυτόν (στο ίδιο μπλοκ), γιατί δεν μπορεί ποτέ να εκτελεστεί. Το `do … while (false);` κάνει compile και εκτελεί το σώμα **ακριβώς μία** φορά.

## 5. Ισοδυναμίες `while`, `do`, `for` (III-64 … III-67)

> [!important] Οι τρεις βρόχοι είναι **ισοδύναμοι** – ο καθένας γράφεται με τους άλλους
>
> | Βρόχος | Ισοδύναμο 1 | Ισοδύναμο 2 |
> |---|---|---|
> | `while (σ) { β }` | `if (σ) do { β } while (σ);` | `for ( ; σ; ) { β }` |
> | `do { β } while (σ);` | `{ β } while (σ) { β }` | `{ β } for ( ; σ; ) { β }` |
> | `for (α; σ; ε) { β }` | `α; if (σ) do { β; ε } while (σ);` | `α; while (σ) { β; ε }` |
>
> Συμβολισμός: **α** = αρχικοποίηση, **σ** = συνθήκη, **ε** = ενημέρωση, **β** = σώμα.

> [!example]- Γιατί ισχύουν
> - `while` → `do`: το `do` εκτελεί το σώμα τουλάχιστον μία φορά, οπότε χρειάζεται «φρουρό» `if (σ)` για την περίπτωση που η `σ` είναι ψευδής από την αρχή.
> - `do` → `while`: εκτέλεσε το σώμα μία φορά «χειροκίνητα», μετά βρόχος `while` – **αντιγραφή** του `β` (παραβιάζει το DRY, γι' αυτό υπάρχει το `do`).
> - `for` → `while`: η ενημέρωση `ε` μπαίνει στο **τέλος** του σώματος.

> [!warning] Οι ισοδυναμίες έχουν «ψιλά γράμματα» ➕
> 1. **`continue`**: στο `for` το `continue` πηγαίνει στην ενημέρωση `ε`. Στο `α; while (σ) { β; ε }` το `continue` **παρακάμπτει** την `ε` → πιθανός άπειρος βρόχος.
>    ```java
>    for (int i = 0; i < 5; i++) { if (i == 2) continue; … }       // τερματίζει
>    int i = 0; while (i < 5) { if (i == 2) continue; …; i++; }   // κολλάει στο i == 2
>    ```
> 2. **Εμβέλεια**: στο `for (int i = 0; …)` το `i` δεν υπάρχει μετά τον βρόχο· στο `int i = 0; while (…)` υπάρχει.
> 3. Η ισοδυναμία `if (σ) do {β} while (σ);` προϋποθέτει ότι η αποτίμηση της `σ` **δεν έχει παρενέργειες** (αλλιώς αποτιμάται μία επιπλέον φορά).

### Πότε ποιος βρόχος;

| Βρόχος | Όταν |
|---|---|
| `for` | ξέρεις **πόσες** επαναλήψεις (μετρητής, διάσχιση πίνακα) |
| `while` | επαναλαμβάνεις **όσο** ισχύει κάτι, πιθανώς **0** φορές |
| `do-while` | το σώμα πρέπει να εκτελεστεί **τουλάχιστον μία** φορά (είσοδος + έλεγχος εγκυρότητας) |

## 6. Κοινά λάθη σε βρόχους (III-73 … III-77)

> [!warning] Κοινά Λάθη (III-73)
> - Σύγχυση ανάμεσα στις εντολές `if` και `while`: `if (συνθήκη) εντολή` / `while (συνθήκη) εντολή`.
> - Παράλειψη των **παρενθέσεων γύρω από τις συνθήκες** στις `while` και `do-while`.
> - Στην `for`, παράλειψη του χαρακτήρα **`;`** μετά την έκφραση αρχικοποίησης και μετά τη συνθήκη.
> - Σε κάθε περίπτωση, το σώμα της επανάληψης θεωρείται **μία και μοναδική εντολή** – κοινό λάθος η παράλειψη των `{ }` όταν επαναλαμβάνεται ακολουθία εντολών:
>   ```java
>   while (x > x_big) x -= z; ++x_big;      // σώμα: μόνο το x -= z;
>   while (x > x_big) { x -= z; ++x_big; }  // σώμα: η ακολουθία των δύο
>   ```

> [!warning] Περιττό `if` γύρω από `do-while` (III-75)
> ```java
> if (συνθήκη1) do { . . . } while (συνθήκη1);
> ```
> θα πρέπει να **απλοποιηθεί** σε
> ```java
> while (συνθήκη1) { . . . }
> ```
> (είναι ακριβώς η πρώτη ισοδυναμία του §5.)

> [!warning] Μη ισότητα με `double` (III-76)
> ```java
> while (balance != 0.0) . . .    // ✗ πολύ πιθανώς άπειρος βρόχος
> while (balance > 0.0)  . . .    // ✓ νοουμένου ότι η balance δεν παραμένει συνεχώς θετική
> ```
> Η τιμή 0.0 μπορεί να μην καταχωρηθεί **επακριβώς** στη `balance` λόγω λαθών στρογγυλοποίησης.

> [!warning] Παρερμήνευση των σύνθετων τελεστών ανάθεσης (III-77)
> `M τ= E` σημαίνει `M = M τ (E)` και **όχι** `M = M τ E`. Π.χ. `a *= b + c;` ≡ `a = a * (b + c);`, **όχι** `a = a * b + c;`. Λεπτομέρειες: [[05 - Εντολή while και Σύνθετοι Τελεστές Ανάθεσης]].
