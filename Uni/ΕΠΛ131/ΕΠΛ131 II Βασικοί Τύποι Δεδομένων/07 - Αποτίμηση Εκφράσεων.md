# 07 - Αποτίμηση Εκφράσεων

Με ποια σειρά υπολογίζει η Java μια έκφραση: παρενθέσεις, προτεραιότητα, εταιρικότητα (διαφάνειες II-40 … II-45).

## 1. Μοναδιαίοι και δυαδικοί τελεστές (II-40)

> [!note] Ορισμοί
> - **Μοναδιαίος** τελεστής (unary operator): έχει **ένα** τελεστέο. Τα `-` και `+` ως **πρόσημο**: `x = -y;` · `p = +x * y;`
> - **Δυαδικός** τελεστής (binary operator): έχει **δύο** τελεστέους: `x = y + z;` · `z = y - x;`
>
> Το ίδιο σύμβολο `-` είναι μοναδιαίο ή δυαδικό ανάλογα με τη θέση του (ακόμη μια μορφή **υπερφόρτωσης**).

## 2. Κανόνες Αποτίμησης Εκφράσεων (II-41, II-42)

> [!important] 1. Κανόνας Παρενθέσεων
> - Κάθε έκφραση σε παρένθεση αποτιμάται **ξεχωριστά**.
> - Φωλιασμένες παρενθετικές εκφράσεις `((..))` αποτιμούνται **από τα μέσα προς τα έξω**.

> [!important] 2. Κανόνας Προτεραιότητας Τελεστών
> Τελεστές στην ίδια έκφραση αποτιμώνται σύμφωνα με τις προτεραιότητές τους. Αριθμητικοί τελεστές, σε **φθίνουσα** σειρά:
>
> | Προτεραιότητα | Τελεστές |
> |---|---|
> | υψηλότερη | μοναδιαίοι `+`, `-` |
> | ενδιάμεση | `*`, `/`, `%` |
> | χαμηλότερη | δυαδικοί `+`, `-` |

> [!important] 3. Κανόνας Εταιρικότητας
> Για τελεστές **ίδιας προτεραιότητας** στην ίδια υπο-έκφραση:
> - **Μοναδιαίοι** → από τα **δεξιά προς τα αριστερά** (δεξιά εταιρικότητα): `- - x` = `-(-x)`
> - **Δυαδικοί** → από τα **αριστερά προς τα δεξιά** (αριστερή εταιρικότητα): `a - b - c` = `(a - b) - c`
> - ➕ Εξαίρεση: η **ανάθεση** `=` είναι δεξιά εταιρική: `a = b = 5` = `a = (b = 5)` → και τα δύο 5.

> [!tip] Ο πλήρης πίνακας προτεραιοτήτων (με συγκριτικούς/λογικούς τελεστές) είναι στο [[Uni/ΕΠΛ131/ΕΠΛ131 III Επιλογή και Επανάληψη/01 - Συνθήκες και Λογικές Εκφράσεις|III – 01 Συνθήκες]] (διαφάνεια III-8).

## 3. Παράδειγμα – δέντρο έκφρασης (II-43)

Η έκφραση `x * y * z + a / b - c * d` ερμηνεύεται ως

**`(((x * y) * z) + (a / b)) - (c * d)`**

```
                 −
              /     \
            +         *
          /   \      / \
         *     /    c   d
        / \   / \
       *   z a   b
      / \
     x   y
```

> [!example]- Αποτίμηση βήμα-βήμα με x=2, y=3, z=4, a=10, b=3, c=5, d=2
>
> | Βήμα | Υπολογισμός | Κανόνας |
> |---|---|---|
> | 1 | `x * y` = 6 | `*` πριν το `+`· αριστερή εταιρικότητα |
> | 2 | `6 * z` = 24 | αριστερή εταιρικότητα |
> | 3 | `a / b` = 10 / 3 = **3** | ακέραια διαίρεση |
> | 4 | `c * d` = 10 | `*` πριν το `-` |
> | 5 | `24 + 3` = 27 | `+` και `-` ίδια προτεραιότητα → αριστερά πρώτα |
> | 6 | `27 - 10` = **17** | |

> [!tip] Όπου υπάρχει αμφιβολία για τη σειρά αποτίμησης, να χρησιμοποιούνται **παρενθέσεις** – με μέτρο φυσικά.

## 4. Συντακτικά ορθές και λανθασμένες εκφράσεις (II-44)

| Ορθές | Γιατί ✓ |
|---|---|
| `x + y / 2` | = `x + (y / 2)` |
| `(-x / y) * 2` | |
| `((3))` | περιττές αλλά έγκυρες παρενθέσεις |
| `+(9 + z)` | μοναδιαίο `+` |
| `5 - - x` | = `5 - (-x)` = `5 + x` |

| Λανθασμένες | Γιατί ✗ |
|---|---|
| `((3 + z) / 2` | **ασύμμετρες** παρενθέσεις |
| `- 2x / y` | **δεν υπάρχει** σιωπηρός πολλαπλασιασμός· θέλει `2 * x` |
| `5 +* 9` | δύο δυαδικοί τελεστές στη σειρά |
| `6 ^ 4` | δεν υπάρχει τελεστής δύναμης (βλ. ⚠️ πιο κάτω) |

> [!warning] ⚠️ Σημείωση: το `6 ^ 4` στην πραγματικότητα κάνει compile!
> Η διαφάνεια έχει δίκιο ότι **δεν υπάρχει τελεστής ύψωσης σε δύναμη** (χρησιμοποιούμε `Math.pow`). Όμως το `^` **υπάρχει** στη Java: είναι το **αποκλειστικό ή (XOR) bit προς bit**. Άρα `6 ^ 4` κάνει compile και δίνει **`2`** (`110 XOR 100 = 010`), όχι 1296.
> Είναι λογικό λάθος, όχι συντακτικό – και γι' αυτό πιο επικίνδυνο. Στις εξετάσεις, αν ρωτηθεί «όπως στη διάλεξη», η αναμενόμενη απάντηση είναι «λάθος, δεν υπάρχει τελεστής δύναμης».

> [!warning] Μοναδιαίο μείον δίπλα σε μείον ➕
> - `5 - - x` ✓ (με κενό) και `5 - -x` ✓ → `5 + x`
> - `5 --x` ✗ compile: το `--` διαβάζεται ως τελεστής **μείωσης** → [[Uni/ΕΠΛ131/ΕΠΛ131 III Επιλογή και Επανάληψη/06 - Εντολή for και Τελεστές ++ --|++/--]]
> - `5 - --x` ✓ αλλά **αλλάζει** το `x` (μειώνεται κατά 1 πριν χρησιμοποιηθεί).

## 5. Διατύπωση εκφράσεων σε Java (II-45)

| Μαθηματικά | Java |
|---|---|
| m² − n² | `m*m - n*n` ή `(m*m) - (n*n)` |
| ax² + bx + c | `a*x*x + b*x + c` |
| −b + 4ac | `-b + 4*a*c` |
| 2ab / (c + d) | `(2*a*b)/(c+d)` |
| ((−a)b) + ((−c)d) | `-a*b + -c*d` |

> [!warning] Κλασικά λάθη μετάφρασης ➕
>
> | Μαθηματικά | ✗ Λάθος | ✓ Σωστό | Γιατί |
> |---|---|---|---|
> | (a + b) / 2 | `a + b / 2` | `(a + b) / 2` | το `/` προηγείται |
> | a / (bc) | `a / b * c` | `a / (b * c)` | αριστερή εταιρικότητα: `(a/b)*c` |
> | 1/2 · x | `1 / 2 * x` | `0.5 * x` ή `x / 2.0` | `1/2 = 0` σε ακεραίους |
> | x³ | `x ^ 3` | `x*x*x` ή `Math.pow(x, 3)` | `^` = XOR |
> | √(b² − 4ac) | `Math.sqrt(b*b) - 4*a*c` | `Math.sqrt(b*b - 4*a*c)` | παρενθέσεις ορίσματος |

## 6. Ειδικές περιπτώσεις ➕

| Έκφραση | Τιμή | Παρατήρηση |
|---|---|---|
| `2 * 3 % 4` | `2` | `*` και `%` ίδια προτεραιότητα → αριστερά: `6 % 4` |
| `2 * (3 % 4)` | `6` | |
| `3 / 2 * 2.0` | `2.0` | `3/2 = 1` (ακέραια) πριν εμφανιστεί το `2.0` |
| `3 / 2.0 * 2` | `3.0` | |
| `-7 / 2 * 2` | `-6` | `-7/2 = -3` |
| `7 / 2 * 2 + 7 % 2` | `7` | η ταυτότητα `(a/b)*b + a%b == a` |
| `10 - 2 - 3 + " " + 10 - 2` | ✗ compile | μετά το `" "` έχουμε `String - int` |
| `-x++` (x = 3) | `-3`, x → 4 | το postfix `++` προηγείται του μοναδιαίου `-` |

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Να «πολλαπλασιάζεις σιωπηρά»: `2x`, `(a+b)(c+d)` ✗.
> - Να θεωρείς ότι το `+` προηγείται του `-` (ή το `*` του `/`): έχουν **ίδια** προτεραιότητα → αριστερά προς δεξιά.
> - Να ξεχνάς ότι η ακέραια διαίρεση γίνεται **τη στιγμή** που αποτιμάται, όχι «στο τέλος».
