# 06 - Ασκήσεις

20 ασκήσεις στο ύφος των διαφανειών και των εξετάσεων της Ενότητας XI. **Λύσε πρώτα, άνοιξε μετά.**

> [!tip] Πώς να το χρησιμοποιήσεις

## Μέρος Α — Βασικές έννοιες, `static` και ορατότητα

### Άσκηση 1

Ποια είναι τα **τρία στοιχεία** (τρίπτυχο) από τα οποία αποτελείται ένα αντικείμενο, και ποιες οι **τρεις κατηγορίες μεθόδων αναφοράς**; Δώσε από ένα παράδειγμα μεθόδου από την ενότητα για κάθε κατηγορία.

> [!success]- Λύση
> **Τρίπτυχο (XI-9):**
> 1. **Ταυτότητα** — η διεύθυνσή του στη μνήμη (μέσω μεταβλητής αναφοράς).
> 2. **Εσωτερική κατάσταση** — τα (συνήθως `private`) πεδία του.
> 3. **Συμπεριφορά (τρόπος επεξεργασίας)** — οι `public` μέθοδοι αναφοράς (API).
>
> **3 κατηγορίες μεθόδων αναφοράς (XI-12):**
> 1. **Κατασκευαστές (constructors)** — π.χ. `DeckObj()`, `Color(r, g, b)`, `Picture(w, h)`.
> 2. **Ανακτητές (getters/retrievers)** — π.χ. `toString()`, `getRed()`, `width()`, `get(i, j)`.
> 3. **Μεταλλάκτες (mutators/setters)** — π.χ. `shuffle()`, `evolve()`, `Game()`, `set(i, j, c)`.

### Άσκηση 2

Ταξινόμησε καθεμία από τις παρακάτω κλήσεις/αναφορές ως **στατική (`static`)** ή **αναφοράς (instance)**, και πες αν αφορά **μέθοδο** ή **μεταβλητή/πεδίο**:
(α) `Luminance.lum(c)` · (β) `c.getBlue()` · (γ) `Math.PI` · (δ) `pic.set(0, 0, c)` · (ε) `StdDraw.setPenColor(c)` · (στ) `Color.RED`

> [!success]- Λύση
> - (α) `Luminance.lum(c)` → **στατική μέθοδος** (`public static`, καλείται από το όνομα της κλάσης).
> - (β) `c.getBlue()` → **μέθοδος αναφοράς** (instance method, καλείται σε αντικείμενο `c`).
> - (γ) `Math.PI` → **στατική μεταβλητή** (`public static` class variable).
> - (δ) `pic.set(0, 0, c)` → **μέθοδος αναφοράς** (μεταλλάκτης).
> - (ε) `StdDraw.setPenColor(c)` → **στατική μέθοδος**.
> - (στ) `Color.RED` → **στατική μεταβλητή** (`public static final Color`).

### Άσκηση 3

Ποια από τις παρακάτω δηλώσεις σε μια κλάση `C` είναι **η ορθή πρακτική** για την αποθήκευση της εσωτερικής κατάστασης κάθε αντικειμένου, και ποια **πρέπει να αποφεύγεται**;
1. `private int x;`
2. `public int x;`
3. `private static int x;`
4. `public static int x;`

> [!success]- Λύση
> - **Ορθή πρακτική**: **1 (`private int x;`)** — ιδιωτικό πεδίο αντικειμένου (instance variable), εξασφαλίζει ενθυλάκωση και ξεχωριστή κατάσταση ανά αντικείμενο (XI-23).
> - **Να αποφεύγεται**: **2 (`public int x;`)** — δημόσιο instance variable, παραβιάζει την απόκρυψη πληροφοριών (XI-23).
> - Τα 3 και 4 είναι μεταβλητές **κλάσης** (`static`) — υπάρχει μόνο ένα κοινό αντίγραφο για όλη την κλάση, όχι ξεχωριστό ανά αντικείμενο.

### Άσκηση 4

Γιατί οι μέθοδοι `brighter()` και `darker()` της `java.awt.Color` **δεν** είναι μεταλλάκτες; Τι επιστρέφουν;

> [!success]- Λύση
> Επειδή **δεν τροποποιούν** την εσωτερική κατάσταση του αντικειμένου `Color` πάνω στο οποίο καλούνται. Αντίθετα, κατασκευάζουν και επιστρέφουν ένα **νέο** αντικείμενο `Color`. Γι' αυτό η `Color` δεν έχει κανέναν μεταλλάκτη και είναι **αμετάβλητη (immutable)** (XI-33).

### Άσκηση 5

Τι συμβαίνει αν εκτελέσουμε:
```java
String[] deck = new String[52];
System.out.println(deck);
```
Θα τυπωθούν τα 52 φύλλα; Τι θα τυπωθεί περίπου; Τι θα συνέβαινε αν είχαμε `DeckObj mydeck = new DeckObj(); System.out.println(mydeck);`;

> [!success]- Λύση
> - Για το `String[] deck`, **όχι**, δεν τυπώνονται τα στοιχεία του πίνακα· τυπώνεται κάτι της μορφής **`[Ljava.lang.String;@2b2fa4f7`** (οι πίνακες δεν έχουν χρήσιμη `toString()`). *(Σημείωση: το `[I@...` της XI-16 αφορά πίνακα `int[]`.)*
> - Για το `DeckObj mydeck`, η `println` καλεί **αυτόματα** τη μέθοδο αναφοράς **`mydeck.toString()`** και τυπώνει την εκτυπώσιμη μορφή της τράπουλας (XI-16).

## Μέρος Β — Ιχνηλάτηση, Αναφορές, `==` vs `equals()` και Παγίδες

### Άσκηση 6

Δίνεται η επέκταση της `DeckObj` (XI-27) με copy constructor `DeckObj(DeckObj d)` και `equals(DeckObj d)`. Τι τυπώνει ο παρακάτω κώδικας;
```java
DeckObj a = new DeckObj();
DeckObj b = new DeckObj(a);
DeckObj c = a;
System.out.println((a == b) + " " + a.equals(b));
System.out.println((a == c) + " " + a.equals(c));
c.shuffle();
System.out.println((a == c) + " " + a.equals(c));
System.out.println((a == b) + " " + a.equals(b));
```

> [!success]- Λύση
> ```
> false true
> true true
> true true
> false false
> ```
> - Πριν το `shuffle()`: `a` και `b` είναι διαφορετικά αντικείμενα με ίδιο περιεχόμενο (`false true`), ενώ `a` και `c` είναι aliases (`true true`).
> - Μετά το `c.shuffle()`: αλλάζει το κοινό αντικείμενο των `a` και `c` (παραμένουν `true true`), ενώ η `b` μένει ανέπαφη, άρα `a.equals(b)` γίνεται `false` (με αμελητέα πιθανότητα $1/52!$ να ξαναβγεί η ίδια σειρά).

### Άσκηση 7

Τι τυπώνει το παρακάτω απόσπασμα; Προσοχή!
```java
Color c1 = new Color(200, 100, 50);
Color c2 = c1;
c2.darker();
System.out.println((c1 == c2) + " " + c1.getRed() + " " + c2.getRed());
c2 = c2.darker();
System.out.println((c1 == c2) + " " + c1.getRed() + " " + c2.getRed());
```

> [!success]- Λύση
> - **1η γραμμή**: **`true 200 200`**. Η `c2.darker();` χωρίς ανάθεση φτιάχνει νέο `Color` και το πετάει — η `c2` συνεχίζει να δείχνει στο ίδιο αντικείμενο με τη `c1`!
> - **2η γραμμή**: **`false 200 140`**. Με την ανάθεση `c2 = c2.darker();`, η `c2` δείχνει στο νέο σκοτεινότερο αντικείμενο (`(int)(200 * 0.7) = 140`), ενώ η `c1` μένει ανέπαφη (`200`) και πλέον `c1 != c2`.

### Άσκηση 8

Τι τυπώνει ο παρακάτω κώδικας;
```java
Color a = new Color(10, 20, 30);
Color b = new Color(10, 20, 30);
System.out.println(a == b);
System.out.println(a.equals(b));
```

> [!success]- Λύση
> ```
> false
> true
> ```
> Δύο ξεχωριστές κλήσεις `new Color(...)` δημιουργούν **δύο διαφορετικά αντικείμενα** σε διαφορετικές διευθύνσεις (`a == b` → `false`), αλλά με τις ίδιες RGB τιμές (`a.equals(b)` → `true`).

### Άσκηση 9

Ποια από τις παρακάτω λογικές προτάσεις είναι **πάντα αληθής** (υποθέτοντας `x != null` και `y != null` και σωστή υλοποίηση της `equals()`);
- (Α) Αν `x.equals(y)` τότε `x == y`.
- (Β) Αν `x != y` τότε `!x.equals(y)`.
- (Γ) Αν `!x.equals(y)` τότε `x != y`.
- (Δ) Αν `x == y` τότε `x.equals(y)`.

Και τι συμβαίνει στην (Δ) αν `x == null` και `y == null`;

> [!success]- Λύση
> - **Πάντα αληθείς**: **(Γ)** και **(Δ)** (XI-27).
> - **Ψευδείς γενικά**: **(Α)** και **(Β)** — δύο ξεχωριστά αντικείμενα (π.χ. `new Color(0,0,0)` και `new Color(0,0,0)`) έχουν `x.equals(y) == true` και `x != y`.
> - Αν **`x == null` και `y == null`**: το `x == y` είναι `true`, αλλά η κλήση `x.equals(y)` πετά **`NullPointerException`**!

### Άσκηση 10

Εντόπισε **όλα** τα σφάλματα (μεταγλώττισης ή εκτέλεσης) στο παρακάτω πρόγραμμα:
```java
public class TestColor {
   public static void main(String[] args) {
      Color[] arr = new Color[3];
      System.out.println(arr[0].getRed());
   }
}
```

> [!success]- Λύση
> 1. **Σφάλμα μεταγλώττισης**: λείπει το **`import java.awt.Color;`** στην αρχή του αρχείου.
> 2. **Σφάλμα εκτέλεσης (`NullPointerException`)**: αφού προστεθεί το `import`, η `new Color[3]` δημιουργεί πίνακα με 3 **`null`** αναφορές, όχι αντικείμενα `Color`. Η `arr[0].getRed()` καλεί μέθοδο πάνω σε `null` → `NullPointerException`.

### Άσκηση 11

Γιατί δεν μεταγλωττίζεται το παρακάτω απόσπασμα και πώς διορθώνεται (XI-40 … XI-42);
```java
do {
   Color c1 = new Color((int)(Math.random()*256), 0, 0);
   Color c2 = new Color(0, (int)(Math.random()*256), 0);
} while (!Luminance.compatible(c1, c2));
StdDraw.setPenColor(c1);
```

> [!success]- Λύση
> Οι μεταβλητές `c1` και `c2` δηλώθηκαν **μέσα** στο σώμα του `do { ... }`, οπότε η εμβέλειά τους λήγει στο `}`. Έτσι δεν είναι ορατές ούτε στη συνθήκη `while(...)` ούτε στην `StdDraw.setPenColor(c1)` (`error: cannot find symbol`).
>
> **Διόρθωση**: δήλωσε `Color c1, c2;` **πριν** το `do`, και μέσα στον βρόχο κάνε μόνο ανάθεση (`c1 = new Color(...);`, `c2 = new Color(...);`).

### Άσκηση 12

Πόσα αντικείμενα `Color` είναι **υποψήφια για garbage collection** αμέσως μετά την εκτέλεση της γραμμής 5;
```java
Color a = new Color(255, 0, 0);   // (1) Red
Color b = new Color(0, 255, 0);   // (2) Green
Color c = a;                      // (3)
a = b;                            // (4)
c = new Color(0, 0, 255);         // (5) Blue
```

> [!success]- Λύση
> **Ακριβώς 1** — το `Red` (`new Color(255, 0, 0)`).
> - Στη γραμμή 3: `a` και `c` δείχνουν στο `Red`, `b` στο `Green`.
> - Στη γραμμή 4: `a` δείχνει πλέον στο `Green`· το `Red` έχει ακόμα τη `c`.
> - Στη γραμμή 5: `c` δείχνει στο `Blue`· το `Red` μένει με **0 αναφορές** → υποψήφιο για garbage collection! (Το `Green` έχει `a` και `b`, το `Blue` έχει `c`.)

### Άσκηση 13

Τι θα εμφανιστεί στην οθόνη αν εκτελέσουμε την `AlbersS` (XI-46) αλλά στον βρόχο σχεδίασης αντικαταστήσουμε το `r = 0.3; ... r = r - rs;` με `r = 0.3 / N; ... r += 0.3 / N;` (XI-47);

> [!success]- Λύση
> Θα φαίνεται **μόνο ένα τετράγωνο** — το τελευταίο (`cs[N-1]`) με ακτίνα `0.3` (το μεγαλύτερο). Επειδή τα γεμάτα τετράγωνα (`filledSquare`) σχεδιάζονται από το μικρότερο προς το μεγαλύτερο με το ίδιο κέντρο `(x0, y0)`, κάθε νέο τετράγωνο σκεπάζει πλήρως όλα τα προηγούμενα.

### Άσκηση 14

Τι συμβαίνει με το αρχείο `photo.jpg` στον δίσκο και τι με την εικόνα `p1` στη μνήμη μετά από αυτόν τον κώδικα;
```java
Picture p1 = new Picture("photo.jpg");
Picture p2 = p1;
p2.set(0, 0, new Color(255, 0, 0));
p1.show();
```

> [!success]- Λύση
> - **Στη μνήμη**: επειδή `p2 = p1` (aliasing) και η `Picture` είναι **τροποποιήσιμη (mutable)**, το pixel `(0, 0)` της **`p1` έγινε κόκκινο**! Άρα η `p1.show()` θα δείξει την εικόνα με κόκκινο το πάνω-αριστερό pixel.
> - **Στον δίσκο**: το αρχείο `photo.jpg` **δεν άλλαξε καθόλου**, γιατί δεν κλήθηκε `save("photo.jpg")` (XI-55).

### Άσκηση 15

Στην κλάση `Scale` (XI-59), ένας φοιτητής αντικαθιστά τις γραμμές:
```java
int si = ti * source.width()  / w;
int sj = tj * source.height() / h;
```
με:
```java
int si = (ti / w) * source.width();
int sj = (tj / h) * source.height();
```
Τι εικόνα `target` θα παραχθεί; Γιατί;

> [!success]- Λύση
> Μια **μονόχρωμη εικόνα**, όπου **κάθε** pixel της `target` θα έχει το χρώμα του πάνω-αριστερού pixel `(0, 0)` της `source`!
> Επειδή `ti` και `w` είναι `int` με `0 ≤ ti < w`, η ακέραια διαίρεση `ti / w` δίνει **πάντα `0`** (το ίδιο και `tj / h = 0`), άρα `si = 0` και `sj = 0` για κάθε `(ti, tj)`.

## Μέρος Γ — Προγραμματισμός με `Color`, `Luminance` και `Picture`

### Άσκηση 16

Υπολόγισε «με το χέρι» τη φωτεινότητα `Luminance.lum(c)` και την απόχρωση του γκρι `Luminance.toGray(c)` για τα χρώματα:
(α) `Color(255, 0, 0)` · (β) `Color(0, 255, 0)` · (γ) `Color(0, 0, 255)` · (δ) Είναι συμβατό το κόκκινο με το πράσινο; Είναι συμβατό το κόκκινο με το μπλε;

> [!success]- Λύση
> - (α) Κόκκινο: $Y = 0.299 \times 255 = 76.245$ → `toGray` = `Color(76, 76, 76)`.
> - (β) Πράσινο: $Y = 0.587 \times 255 = 149.685$ → `toGray` = `Color(150, 150, 150)`.
> - (γ) Μπλε: $Y = 0.114 \times 255 = 29.070$ → `toGray` = `Color(29, 29, 29)`.
> - (δ) Κόκκινο & πράσινο: $|76.245 - 149.685| = 73.44 < 128.0$ → **`false`** (όχι συμβατά).
>   Κόκκινο & μπλε: $|76.245 - 29.070| = 47.175 < 128.0$ → **`false`** (όχι συμβατά).
>   *(Πράσινο & μπλε: $|149.685 - 29.070| = 120.615 < 128.0$ → επίσης `false`!)*

### Άσκηση 17

Γράψε μια στατική μέθοδο `public static Color invert(Color c)` που επιστρέφει το **αρνητικό (συμπληρωματικό)** χρώμα του `c`, δηλαδή `(255 - r, 255 - g, 255 - b)`. Στη συνέχεια γράψε τη μέθοδο `public static Picture invertPicture(Picture pic)` που επιστρέφει μια **νέα** εικόνα (χωρίς να τροποποιήσει την `pic`) με ανεστραμμένα όλα τα χρώματα.

> [!success]- Λύση
> ```java
> public static Color invert(Color c) {
>    return new Color(255 - c.getRed(), 255 - c.getGreen(), 255 - c.getBlue());
> }
>
> public static Picture invertPicture(Picture pic) {
>    int w = pic.width(), h = pic.height();
>    Picture res = new Picture(w, h);
>    for (int col = 0; col < w; col++) {
>       for (int row = 0; row < h; row++) {
>          res.set(col, row, invert(pic.get(col, row)));
>       }
>    }
>    return res;
> }
> ```

### Άσκηση 18

Γράψε μια στατική μέθοδο `public static Picture flipHorizontal(Picture pic)` που επιστρέφει μια **νέα** εικόνα η οποία είναι ο **οριζόντιος καθρέφτης** (αριστερά ↔ δεξιά) της `pic`, χωρίς να τροποποιεί την `pic`.

> [!success]- Λύση
> ```java
> public static Picture flipHorizontal(Picture pic) {
>    int w = pic.width(), h = pic.height();
>    Picture flipped = new Picture(w, h);
>    for (int col = 0; col < w; col++) {
>       for (int row = 0; row < h; row++) {
>          flipped.set(w - 1 - col, row, pic.get(col, row));
>       }
>    }
>    return flipped;
> }
> ```
> *Σημείωση:* οι `pic` και `flipped` μοιράζονται τις ίδιες αναφορές `Color` — απόλυτα ασφαλές επειδή η `Color` είναι αμετάβλητη!

### Άσκηση 19

Γράψε μια στατική μέθοδο `public static boolean samePicture(Picture a, Picture b)` που ελέγχει αν δύο εικόνες έχουν **τις ίδιες διαστάσεις** και **το ίδιο χρώμα σε κάθε pixel**. Πρόσεξε να χρησιμοποιήσεις `equals()` (όχι `==`) στη σύγκριση χρωμάτων!

> [!success]- Λύση
> ```java
> public static boolean samePicture(Picture a, Picture b) {
>    if (a.width() != b.width() || a.height() != b.height()) return false;
>    for (int col = 0; col < a.width(); col++) {
>       for (int row = 0; row < a.height(); row++) {
>          if (!a.get(col, row).equals(b.get(col, row))) return false;
>       }
>    }
>    return true;
> }
> ```
> Αν είχαμε γράψει `a.get(col, row) != b.get(col, row)`, δύο εικόνες με πανομοιότυπα χρώματα που φορτώθηκαν ξεχωριστά θα έδιναν `false` (διαφορετικές διευθύνσεις `Color`).

### Άσκηση 20

Γράψε μια στατική μέθοδο `public static Color blend(Color c1, Color c2, double alpha)` (με `0.0 <= alpha <= 1.0`) που επιστρέφει τη γραμμική ανάμειξη (fade) των δύο χρωμάτων, όπου κάθε συνιστώσα είναι $\text{round}((1 - \alpha) c_1 + \alpha c_2)$. Τι επιστρέφει για `alpha = 0.0` και τι για `alpha = 1.0`;

> [!success]- Λύση
> ```java
> public static Color blend(Color c1, Color c2, double alpha) {
>    int r = (int) Math.round((1 - alpha) * c1.getRed()   + alpha * c2.getRed());
>    int g = (int) Math.round((1 - alpha) * c1.getGreen() + alpha * c2.getGreen());
>    int b = (int) Math.round((1 - alpha) * c1.getBlue()  + alpha * c2.getBlue());
>    return new Color(r, g, b);
> }
> ```
> - Για `alpha = 0.0` επιστρέφει χρώμα ίσο με `c1` (`blend(c1, c2, 0.0).equals(c1)` → `true`, αλλά `==` → `false` γιατί είναι νέο αντικείμενο).
> - Για `alpha = 1.0` επιστρέφει χρώμα ίσο με `c2`.
