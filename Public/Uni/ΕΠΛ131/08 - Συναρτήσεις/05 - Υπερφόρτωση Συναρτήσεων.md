# 05 - Υπερφόρτωση Συναρτήσεων

**Διάσπαση και σύνθεση** με συναρτήσεις, και **function overloading**: πολλές εκδοχές μιας συνάρτησης με το ίδιο όνομα, που ξεχωρίζουν από τις παραμέτρους τους (διαφάνειες VIII-33 … VIII-36).

## 1. Διάσπαση και σύνθεση – Διαίρει και Βασίλευε (VIII-33)

> [!important] Βασική επιδίωξη
> Ακόμη και για απλά προβλήματα, βασική επιδίωξη είναι η δημιουργία **αρθρωτών λύσεων** αξιοποιώντας συναρτήσεις: σπάμε το πρόβλημα σε υπο-προβλήματα (**διάσπαση**), λύνουμε το καθένα με μια συνάρτηση, και τις συνδυάζουμε (**σύνθεση**).

Η `min3` (min τριών) **συντίθεται** από δύο κλήσεις της `min2`. Οι βιβλιοθήκες `DrawGraph` και `SortLib` ([[06 - Βιβλιοθήκες DrawGraph και SortLib|06]]), το tic-tac-toe ([[03 - Tic-Tac-Toe, Διάσπαση και Σύνθεση|IX – 03]]) και το παιχνίδι της ζωής ([[05 - Το Παιχνίδι της Ζωής|IX – 05]]) εφαρμόζουν την ίδια ιδέα σε μεγαλύτερη κλίμακα.

## 2. Function Overloading (VIII-34)

> [!note] Υπερφόρτωση συναρτήσεων
> Μπορούμε να ορίσουμε **εναλλακτικές εκδοχές** μιας συνάρτησης, οι οποίες διακρίνονται βάσει του **signature** τους (πλήθος, τύποι και σειρά παραμέτρων).
> - Κάποιες εκδοχές μπορεί να είναι `private`.
> - Το function overloading ικανοποιεί την αρχή **«open for extension»** ([[03 - Σχεδιασμός Μονάδων|Open/Closed]]), αφού με ευκολία μπορούν να προστίθενται νέες εκδοχές συναρτήσεων που ήδη αξιοποιούνται, **χωρίς επηρεασμό** της/των υφιστάμενης/ων εκδοχής/ών τους.

## 3. Το API της Math: τρεις εκδοχές της min (VIII-35)

| `public class Math` | |
|---|---|
| `int min(int, int)` | |
| `float min(float, float)` | |
| `double min(double, double)` | |

```java
int a,b,x;
float c,d,y;
double e,f,z;
//above variables initalized

x=min(a,b); // calls int
y=min(c,d); // calls float
z=min(e,f); // calls double
z=min(a,f); // calls double - casts automatically a to double
```

> [!tip] ➕ Λεπτομέρειες
> - Στην πραγματικότητα η `Math` έχει **τέσσερις** εκδοχές της `min`: υπάρχει και η `long min(long, long)`. Η διαφάνεια δείχνει τις τρεις.
> - Ο τύπος του **αποτελέσματος** ακολουθεί την εκδοχή που επιλέχθηκε: `Math.min(5, 2.5f)` καλεί την `float` εκδοχή και επιστρέφει `2.5` (`float`) · `int z = Math.min(5, 2.5f);` ✗ `possible lossy conversion from float to int` · `Math.min(3, 4L)` επιστρέφει `long` (ελέγχθηκαν).
> - Οι κλήσεις στη διαφάνεια γράφονται `min(a,b)`· έξω από την κλάση `Math` χρειάζεται `Math.min(a,b)`.

## 4. Υπερφόρτωση στον δικό μας κώδικα (VIII-36)

Η `MinThreeIntegers` ([[03 - Κλήση, Ορίσματα, Binding και Εμβέλεια#1. Ροή ελέγχου: κλήση και επιστροφή (VIII-15)|03 §1]]) ξαναγραμμένη: οι `min2` και `min3` παίρνουν **το ίδιο όνομα** `min`.

```java
public class MinThreeIntegers{
    // function that returns minimum of two integers parameters
    public static int min(int a, int b){
      int min;
      if (a <= b) min = a; else min = b;
      return min;
    }

    // function that returns minimum of three integers parameters
    // use min function
    public static int min(int a, int b, int c){
      return min(a, min(b,c));
    }

    // test min2 and min3
    public static void main(String []args){
      int x=3,y=4,z=2; // given three integers find their minimum
      System.out.println("The minimum of " + x + ", " + y + ", " + z + " is: " +
                    min(x,y,z));
    }
}
```

Η `min(x,y,z)` (3 ορίσματα) επιλέγει την εκδοχή 3 παραμέτρων· μέσα της, η `min(b,c)` (2 ορίσματα) την εκδοχή 2 παραμέτρων. Ο μεταγλωττιστής αποφασίζει **από το πλήθος και τους τύπους των ορισμάτων**.

> [!note] Τοπική μεταβλητή με το ίδιο όνομα με τη μέθοδο
> Μέσα στη `min(int a, int b)` υπάρχει `int min;`. Επιτρέπεται: τα ονόματα μεταβλητών και μεθόδων είναι σε **διαφορετικούς** «χώρους». Το `min` σκέτο είναι η μεταβλητή· το `min(…)` με παρενθέσεις είναι κλήση. Συχνά όμως μπερδεύει τον αναγνώστη ([[02 - Αναγνωσιμότητα και Συντήρηση|V – 02]]).

## 5. ➕ Πώς διαλέγει ο μεταγλωττιστής εκδοχή

> [!important] Ο κανόνας σε τρία βήματα
> 1. Κρατά τις εκδοχές με το **σωστό πλήθος** παραμέτρων.
> 2. Αν υπάρχει **ακριβές ταίριασμα** τύπων, το διαλέγει.
> 3. Αλλιώς, διαλέγει την εκδοχή που χρειάζεται τις **«μικρότερες»** αυτόματες διευρύνσεις (`char → int` πριν από `char → double`). Αν δύο εκδοχές είναι εξίσου καλές → **λάθος μεταγλώττισης** (`ambiguous`). Αν καμία δεν ταιριάζει → λάθος.
>
> Η επιλογή γίνεται **στη μεταγλώττιση**, από τους **τύπους** των ορισμάτων, όχι από τις τιμές τους.

![[Συναρτήσεις - Επιλογή Εκδοχής.png|800]]

> [!example]- Πίνακας κλήσεων (ελέγχθηκαν)
> Με `static void f(int a)` και `static void f(double a)`:
>
> | Κλήση | Εκδοχή | Γιατί |
> |---|---|---|
> | `f(3)` | `int` | ακριβές |
> | `f(3.0f)` | `double` | `float → double` (δεν υπάρχει `float → int`) |
> | `f(3L)` | `double` | `long → double` επιτρέπεται, `long → int` όχι |
> | `f('A')` | `int` | `char → int` είναι πιο «κοντά» από `char → double` |
> | `byte b = 1; f(b);` | `int` | `byte → int` |
>
> Με **μόνο** `static void g(double a)`: `g(5)` και `g('x')` δουλεύουν (διεύρυνση). Με **μόνο** `static void h(int a)`: `h(3L)` και `h(2.0)` ✗ `possible lossy conversion`.

> [!warning] Τι **δεν** είναι υπερφόρτωση (ελέγχθηκαν)
>
> | Κώδικας | Αποτέλεσμα |
> |---|---|
> | `int f(int a)` + `double f(int a)` | ✗ `method f(int) is already defined` – μόνο ο **τύπος επιστροφής** διαφέρει |
> | `int f(int a)` + `int f(int b)` | ✗ ίδιο – μόνο το **όνομα** της παραμέτρου διαφέρει |
> | `f(int a, double b)` + `f(double a, int b)`, κλήση `f(1, 1)` | ✗ `reference to f is ambiguous` – καμία δεν είναι καλύτερη |
> | `p(int[] a)` + `p(double[] a)`, κλήση `p(null)` | ✗ `ambiguous` – το `null` ταιριάζει και στα δύο |
> | `f(int a, double b)` + `f(double a, int b)`, κλήση `f(1, 2.0)` | ✓ – μόνο η πρώτη ταιριάζει |

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Προσπάθεια υπερφόρτωσης **μόνο** με διαφορετικό τύπο επιστροφής.
> - Αναμονή ότι `Math.min(int, float)` επιστρέφει `int`: επιστρέφει `float`.
> - Ασαφείς κλήσεις (`f(1,1)` με `f(int,double)`/`f(double,int)`).
> - Πίστη ότι η εκδοχή επιλέγεται στην εκτέλεση από την τιμή: επιλέγεται στη μεταγλώττιση από τον **τύπο**.
