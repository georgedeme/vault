# 02 - Παράμετροι, Τιμές Επιστροφής και return

Πώς οι **παράμετροι** κάνουν μια συνάρτηση γενική, ποια η διαφορά συναρτήσεων που **επιστρέφουν τιμή** και `void`, και οι κανόνες της **`return`** (διαφάνειες VIII-9 … VIII-14, VIII-17).

## 1. Συναρτήσεις με παραμέτρους (VIII-9)

> [!note] Γιατί παράμετροι
> - Παρέχουν **μεγαλύτερη αφαιρετικότητα** από συναρτήσεις χωρίς παραμέτρους.
> - Οι παράμετροι ενσωματώνουν τα σημεία που **διαφοροποιούν** τις κλήσεις μιας συνάρτησης.
>
> Η `Math.random()` κάνει κάτι πολύ συγκεκριμένο: επιστρέφει αριθμό στο `[0.0, 1.0)`. Αυτό **δεν μπορεί να διαφοροποιηθεί** ανάμεσα στις κλήσεις της. Με παραμέτρους `a`, `b` φτιάχνουμε μια πιο γενική συνάρτηση.

```java
// returns a random integer from interval [a,b]
public static int myRandom (int a, int b){
   return a + (int)(Math.random() * (b-a+1));
}
```

| Βήμα | `myRandom(3, 7)` |
|---|---|
| `Math.random()` | `[0, 1)` |
| `* (b-a+1)` = `* 5` | `[0, 5)` |
| `(int)` (αποκοπή) | `0, 1, 2, 3, 4` |
| `a + …` = `3 + …` | **`3, 4, 5, 6, 7`** |

> [!warning] ➕ Παγίδες της `myRandom` (ελέγχθηκαν)
> - Το `+1` χρειάζεται για να συμπεριληφθεί το `b`. Χωρίς αυτό, το `7` δεν βγαίνει ποτέ.
> - Οι παρενθέσεις `(int)(Math.random() * …)` είναι απαραίτητες: `(int)Math.random() * 5` είναι **πάντα 0** (το cast εφαρμόζεται πρώτα, στο `[0,1)`).
> - `myRandom(5, 5)` → πάντα `5` (σωστό: διάστημα ενός στοιχείου).
> - `myRandom(7, 3)` (ανάποδα) **δεν** δίνει `[3,7]`: `b-a+1 = -3`, άρα το γινόμενο είναι στο `(-3, 0]`, η αποκοπή δίνει `-2, -1, 0` και το αποτέλεσμα είναι `5, 6, 7`. Η συνάρτηση **υποθέτει** `a ≤ b` χωρίς να το ελέγχει.

## 2. Συναρτήσεις που επιστρέφουν τιμές και `void` (VIII-10)

> [!note] Δύο κατηγορίες
> - **Επιστρέφουν τιμή**: δίνουν πίσω στο σημείο κλήσης μια απάντηση. Η απάντηση αναμένεται να **αξιοποιηθεί**: να ανατεθεί σε μεταβλητή ή να δοθεί ως όρισμα σε άλλη κλήση.
> - **Δεν επιστρέφουν** ρητά τιμή (**`void`**): οι κλήσεις τους αποτελούν **standalone εντολές**.

```java
public static int min2 (int a, int b){
   if (a <= b) return a;
   else return b;
}
```

```java
int small = min2(x, y);
int smallest = min2(z, min2(x,y));
               // = min2(z,small);
```

> [!important] Φωλιασμένες κλήσεις: πρώτα η εσωτερική
> Στο `min2(z, min2(x,y))` τα ορίσματα αποτιμώνται **πριν** κληθεί η εξωτερική `min2`, **από αριστερά προς τα δεξιά**: πρώτα `z`, μετά `min2(x,y)`. Με `x=3, y=4, z=2`: καλείται `min2(3,4)` → `3`, και μετά `min2(2,3)` → `2` (ελέγχθηκε με εκτύπωση μέσα στη `min2`). Η κλήση `min2(x,y)` **αντικαθίσταται** από την τιμή της, όπως μια μεταβλητή.

![[Συναρτήσεις - Φωλιασμένες Κλήσεις.png|800]]

> [!example]- ➕ Η σειρά αποτίμησης ορισμάτων φαίνεται με παρενέργειες (ελέγχθηκε)
> ```java
> static int add(int x, int y) { return x*100 + y; }
> int i = 1;
> System.out.println(add(i++, i*10));   // 120
> ```
> Το πρώτο όρισμα αποτιμάται πρώτο: `i++` δίνει `1` και κάνει το `i` ίσο με `2`· το δεύτερο βλέπει `i = 2` → `20`. Άρα `add(1, 20)` = `120`. Η Java **εγγυάται** σειρά αριστερά → δεξιά (σε άλλες γλώσσες, π.χ. C, δεν ισχύει). Ωστόσο τέτοιος κώδικας είναι κακή πρακτική.

## 3. Συναρτήσεις που καλούν συναρτήσεις (VIII-11)

```java
public static int min3 (int a, int b, int c){
   return min2(a, min2(b,c));
}

public static double minT (double[] table) {
   double res = Double.POSITIVE_INFINITY;
   for (double n : table){
      if (n < res) res = n;
   }
   return res;
}

public static void displayMin (double[] array){
   System.out.println(minT(array));
}
```

```java
double[] T = {5.9, 1.0, 7.9, 10, 3.1};
displayMin(T); // standalone function call
```

Έξοδος: `1.0`. Η `min3` **επαναχρησιμοποιεί** τη `min2` αντί να ξαναγράψει συγκρίσεις (DRY). Η `displayMin` είναι `void`, άρα καλείται ως αυτόνομη εντολή.

> [!tip] Γιατί `Double.POSITIVE_INFINITY` ως αρχική τιμή
> Κάθε πραγματικός αριθμός είναι `<` από το `+∞`, άρα το πρώτο στοιχείο θα αντικαταστήσει σίγουρα το `res`. Εναλλακτικά `res = table[0]` και ο βρόχος από το `1`.
> - ➕ Κενός πίνακας: `minT(new double[0])` επιστρέφει **`Infinity`** (δεν σκάει), ενώ η εκδοχή με `table[0]` θα έδινε `ArrayIndexOutOfBoundsException` (ελέγχθηκε).
> - ➕ `NaN` στον πίνακα αγνοείται: `n < res` είναι πάντα `false` για `NaN`. `minT({NaN, 2})` → `2.0`.
> - ➕ Το `10` στον πίνακα `double[]` είναι `int` κυριολεκτικό που μετατρέπεται αυτόματα σε `10.0`.

## 4. Επισημάνσεις: κλήσεις που αγνοούν την τιμή (VIII-12)

> [!warning] Παράλογες standalone κλήσεις
> Θα ήταν **παράλογο** συναρτήσεις όπως `myRandom`, `min2`, `min3` και `minT`, που έχουν ρητές τιμές εξόδου, να καλούνται ως standalone εντολές, **παρόλο που η Java το επιτρέπει**:
> ```java
> min2(1, 2);          // κάνει compile· η απάντηση χάνεται
> ```
> Τέτοιες κλήσεις δικαιολογούνται **μόνο** όταν η συνάρτηση παρέχει λειτουργικότητα **πέρα** από τον υπολογισμό της τιμής (η οποία απλά αγνοείται). Διαφορετικά αποτελούν **πλεονασμό**, παραβιάζοντας αρχές ορθού προγραμματισμού.

> [!warning] ➕ Το αντίστροφο δεν επιτρέπεται (ελέγχθηκε)
> Μια `void` συνάρτηση **δεν έχει τιμή**, άρα δεν μπαίνει σε έκφραση:
> - `double x = displayMin(T);` → `error: incompatible types: void cannot be converted to double`
> - `System.out.println(displayMin(T));` → `error: 'void' type not allowed here`

## 5. Παράδειγμα όπου η τιμή εξόδου μπορεί να αγνοηθεί: `swap` (VIII-13)

```java
// Function swap gets a two-element table xs
// (i.e. the table's address) and if the elements are not
// already in ascending order, they are swapped.
// Through its return value, the function signifies
// whether the swapping was necessary or not.

public static boolean swap (int[] xs){
   if (xs[0] <= xs[1]) return false;
   else {int temp = xs[0]; xs[0] = xs[1]; xs[1] = temp;
      return true; }
}
```

Εδώ η **κύρια** δουλειά είναι η **παρενέργεια** (η αντιμετάθεση μέσα στον πίνακα του καλούντα). Η τιμή `boolean` είναι πληροφορία «έγινε αλλαγή;», που ο καλών μπορεί να τη χρησιμοποιήσει ή να την αγνοήσει. Άρα η standalone κλήση `swap(b);` είναι **δικαιολογημένη**.

| Κλήση | Πίνακας πριν | Επιστρέφει | Πίνακας μετά |
|---|---|---|---|
| `swap(b)` | `{9, 3}` | `true` | `{3, 9}` |
| ξανά `swap(b)` | `{3, 9}` | `false` | `{3, 9}` |

(ελέγχθηκε) Η αλλαγή φαίνεται στον καλούντα επειδή περνάει η **διεύθυνση** του πίνακα ([[04 - Πίνακες ως Παράμετροι Συναρτήσεων|04]]). Με δύο `int` παραμέτρους η αντιμετάθεση **δεν** θα δούλευε ([[03 - Κλήση, Ορίσματα, Binding και Εμβέλεια#4. Binding – δέσμευση (VIII-20, VIII-21)|03 §4]]).

## 6. Η εντολή return (VIII-14)

> [!note] Τι κάνει
> - Ο κώδικας του «πώς» μιας συνάρτησης μπορεί να χρησιμοποιεί **όλες** τις αλγοριθμικές δομές (ακολουθίες, επιλογές, επαναλήψεις, κλήσεις συναρτήσεων), όπως στη `main`.
> - Όταν εκτελείται η **`return`**, η ροή του ελέγχου **επιστρέφει πίσω στο σημείο κλήσης**. Ό,τι ακολουθεί δεν εκτελείται.
> - Συνάρτηση **με τιμή εξόδου** πρέπει να περιλαμβάνει **τουλάχιστον μία** `return <τιμή εξόδου>`.
> - Συνάρτηση **`void`** μπορεί να περιλαμβάνει `return;` χωρίς τιμή, όπου χρειάζεται ο τερματισμός της (ίσως πρόωρα, αλλά όχι αναγκαστικά).

> [!warning] ➕ Οι κανόνες του μεταγλωττιστή (ελέγχθηκαν)
>
> | Κώδικας | Αποτέλεσμα |
> |---|---|
> | `int f(int x){ if (x>0) return 1; }` | ✗ `missing return statement` – για `x ≤ 0` δεν επιστρέφει τίποτα |
> | `int f(int x){ if (x>0) return 1; else if (x<=0) return 2; }` | ✗ `missing return statement` – ο μεταγλωττιστής **δεν** καταλαβαίνει ότι οι δύο συνθήκες καλύπτουν τα πάντα |
> | `int f(int x){ if (x>0) return 1; else return 2; }` | ✓ |
> | `int f(int x){ return 1; x++; }` | ✗ `unreachable statement` – κώδικας μετά το `return` |
> | `void f(int x){ return x; }` | ✗ `incompatible types: unexpected return value` |
> | `int f(int x){ return; }` | ✗ `incompatible types: missing return value` |
> | `int g(int x){ while(true){} }` | ✓ – ο βρόχος δεν τελειώνει ποτέ, άρα δεν «φτάνει» στο τέλος χωρίς `return` |
>
> Ο κανόνας: **κάθε** δρόμος εκτέλεσης που φτάνει στο τέλος της συνάρτησης πρέπει να περνά από `return τιμή`, και ο μεταγλωττιστής το ελέγχει **συντακτικά** (δεν αποτιμά συνθήκες).

## 7. `return` χωρίς τιμή: `drawSquare` (VIII-17)

```java
// Displays a square - returns if size < 1

public static void drawSquare (int size){
  if (size < 1) return;
  for (int i = 1; i <= size; i++){
    System.out.println();
    for (int j = 1; j <= size; j++){
       System.out.print("*");
    }
  }
}
```

- `drawSquare(0)` δεν κάνει τίποτα (πρόωρη `return`).
- `drawSquare(5)` δημιουργεί το «διακριτό τετράγωνο» 5×5 από `*`.

> [!warning] ⚠️ Σημείωση για τη VIII-17
> - Στη διαφάνεια το `"*"` είναι γραμμένο με **τυπογραφικά** εισαγωγικά (`“*”`) που δεν κάνουν compile.
> - Η έξοδος **δεν** είναι ακριβώς αυτή της διαφάνειας: το `println()` είναι **πριν** από κάθε γραμμή, άρα βγαίνει πρώτα μια **κενή γραμμή**, και μετά την τελευταία γραμμή αστεριών **δεν** αλλάζει γραμμή (ελέγχθηκε: `drawSquare(3)` και μετά `print("|END")` δίνει `***|END` στην τελευταία γραμμή).
>
> Σωστή σειρά: πρώτα τα αστέρια της γραμμής, **μετά** η αλλαγή γραμμής:
> ```java
> for (int i = 1; i <= size; i++){
>    for (int j = 1; j <= size; j++) System.out.print("*");
>    System.out.println();
> }
> ```

![[Συναρτήσεις - drawSquare Έξοδος.png|800]]

> [!tip] Πρόωρη `return` ως «φύλακας»
> Το `if (size < 1) return;` στην αρχή ελέγχει τις μη έγκυρες τιμές και φεύγει, ώστε ο υπόλοιπος κώδικας να γράφεται χωρίς επιπλέον φωλιασμένο `if`. Ακόμη και χωρίς αυτό, για `size ≤ 0` ο βρόχος δεν θα εκτελούνταν· εδώ η `return` κάνει την πρόθεση **ρητή**.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - `(int)Math.random() * n` αντί για `(int)(Math.random() * n)` → πάντα 0.
> - Ξεχασμένο `+1` στο `b-a+1` → το άνω άκρο δεν βγαίνει ποτέ.
> - `if … return …; else if … return …;` χωρίς τελικό `else` → `missing return statement`.
> - Κώδικας μετά από `return` → `unreachable statement`.
> - Χρήση της τιμής μιας `void` συνάρτησης σε έκφραση.
> - Κλήση συνάρτησης με τιμή ως standalone εντολή **χωρίς** λόγο (πλεονασμός): η απάντηση χάνεται.
> - `println()` στη λάθος θέση σε σχέση με τον εσωτερικό βρόχο (VIII-17).
