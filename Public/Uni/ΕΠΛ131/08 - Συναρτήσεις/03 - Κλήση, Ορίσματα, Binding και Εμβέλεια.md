# 03 - Κλήση, Ορίσματα, Binding και Εμβέλεια

Τι γίνεται **ακριβώς** όταν καλείται μια συνάρτηση: πού πηγαίνει ο έλεγχος, πώς τα **ορίσματα** αντιγράφονται στις **παραμέτρους** (binding, πέρασμα δια τιμής), ποιοι κανόνες αντιστοίχισης ισχύουν, και πού «ζει» κάθε μεταβλητή (**εμβέλεια**) (διαφάνειες VIII-15, VIII-16, VIII-18 … VIII-24).

## 1. Ροή ελέγχου: κλήση και επιστροφή (VIII-15)

> [!important] Σημείο κλειδί
> Οι συναρτήσεις παρέχουν **έναν νέο τρόπο** για να ελέγχουν τη ροή εκτέλεσης (εκτός από ακολουθία, επιλογή, επανάληψη).

```java
public class MinThreeIntegers{
    // function that returns minimum of two integers parameters
    public static int min2 (int a, int b){
      int min;
      if (a <= b) min = a; else min = b;
      return min;
    }

    // function that returns minimum of three integers parameters
    // use min2 function
    public static int min3 (int a, int b, int c){
      return min2(a, min2(b,c));
    }

    // test min2 and min3
    public static void main(String []args){
      int x=3,y=4,z=2;// given three integers find their minimum
      System.out.println("The minimum of " + x + ", " + y + ", " + z + " is: " +
                         min3(x,y,z));
    }
}
```

```
The minimum of 3, 4, 2 is: 2
```

| Βήμα | Πού είναι ο έλεγχος | Τι γίνεται |
|---|---|---|
| 1 | `main` | φτιάχνει το string μέχρι το `" is: "`, συναντά `min3(x,y,z)` |
| 2 | `min3(3, 4, 2)` | πρέπει να αποτιμήσει τα ορίσματα της εξωτερικής `min2`: `a = 3`, μετά `min2(b,c)` |
| 3 | `min2(4, 2)` | `4 <= 2` ψευδές → `min = 2` → `return 2` **πίσω στη `min3`** |
| 4 | `min3` | τώρα καλεί `min2(3, 2)` |
| 5 | `min2(3, 2)` | `return 2` πίσω στη `min3` |
| 6 | `min3` | `return 2` πίσω στη `main` |
| 7 | `main` | ολοκληρώνει τη συνένωση και τυπώνει |

## 2. Τι συμβαίνει όταν καλείται μια συνάρτηση (VIII-16)

> [!note] Σύνοψη
> 1. Ο **έλεγχος μεταφέρεται** στον κώδικα της συνάρτησης.
> 2. Στις μεταβλητές παραμέτρων **ανατίθενται οι τιμές** που δίνονται στην κλήση.
> 3. Ο κώδικας της συνάρτησης **εκτελείται**.
> 4. Η επιστρεφόμενη τιμή **ανατίθεται στη θέση του ονόματος** της συνάρτησης στον κώδικα που καλείται.
> 5. Ο έλεγχος **επιστρέφει** πίσω στον καλούντα κώδικα.
>
> Αυτό είναι γνωστό ως **«πέρασμα δια τιμής»** (pass by value).

## 3. Καλώντας συναρτήσεις και ορίσματα (VIII-18, VIII-19)

Μια συνάρτηση για να αξιοποιηθεί πρέπει να **κληθεί**. Σε κάθε κλήση δίνονται οι τιμές για τις παραμέτρους της (τα λεγόμενα **ορίσματα** – arguments) και στη συνέχεια αναμένεται η απάντησή της, εάν και εφόσον υπάρχει τιμή εξόδου.

```java
Class.name(arg1, arg2, arg3);
```

Εάν η συνάρτηση βρίσκεται **στην ίδια κλάση** με τον καλούντα κώδικα, δεν χρειάζεται το όνομα της κλάσης: `min3(x, y, z)` αντί για `MinThreeIntegers.min3(x, y, z)`.

> [!tip] ➕ Από άλλη κλάση
> Από άλλο πρόγραμμα, στον ίδιο φάκελο: `MinThreeIntegers.min3(1, 2, 3)`. Έτσι καλούμε `Math.sqrt`, `StdIn.readInt`, `Integer.parseInt`. Μια **`private`** μέθοδος **δεν** καλείται από άλλη κλάση· μόνο από μεθόδους της ίδιας ([[06 - Βιβλιοθήκες DrawGraph και SortLib|06]]).

> [!note] Ορίσματα (πραγματικές παράμετροι) – Arguments (actual parameters)
> Είναι **τιμές** (values), οι οποίες μπορεί να διατυπωθούν ως **οποιαδήποτε έκφραση**:
> - απόλυτη τιμή (`3`, `2.6758`), μεταβλητή, κλήση συνάρτησης, διεύθυνση (πίνακα/αντικειμένου), κτλ.,
> - που αποτιμάται σε τιμή **συμβατή** με τον τύπο της αντίστοιχης **τυπικής παραμέτρου** (formal parameter).

| Όρος | Πού | Παράδειγμα στο `add(5, a)` → `add(int x, int y)` |
|---|---|---|
| Όρισμα / πραγματική παράμετρος | στην **κλήση** | `5`, `a` |
| Παράμετρος / τυπική παράμετρος | στον **ορισμό** | `x`, `y` |

## 4. Binding – δέσμευση (VIII-20, VIII-21)

> [!note] Binding
> - Μια διαδικασία που ονομάζεται **binding** **αντιγράφει** τις τιμές (ορίσματα) από τον καλούμενο κώδικα στις παραμέτρους της συνάρτησης. Η αντιστοιχία ανάμεσα σε ορίσματα και παραμέτρους είναι **ένα-προς-ένα**.
> - Η κλήση μπορεί να χρησιμοποιήσει ως ορίσματα μεταβλητές με **το ίδιο όνομα** με τις παραμέτρους, με **διαφορετικά** ονόματα, ή ακόμα και **απόλυτες τιμές** (όπως `3` ή `2.6758`).
> - Η συνάρτηση **δεν αλλάζει** τις τιμές των μεταβλητών στον αρχικό κώδικα – έχει μόνο **αντίγραφα** των τιμών.

```java
int a = 10;
int x = 3;
int y = add( 5, a ); //το y περιέχει 15 τώρα
```

```java
public static int add(int x, int y){
     int z = x + y; //5 + 10
     return z;
}
```

**Σημ.:** Δεν υπάρχει καμία σχέση ανάμεσα στα δύο διαφορετικά `x` και `y`. Το `x = 3` της κλήσης **δεν** παίζει κανέναν ρόλο: η παράμετρος `x` παίρνει το `5` (πρώτο όρισμα), η `y` το `10` (τιμή του `a`).

![[Συναρτήσεις - Πέρασμα δια Τιμής.png|800]]

> [!example]- ➕ Η κλασική παγίδα: `swap` με δύο ακεραίους (ελέγχθηκε)
> ```java
> static void swap(int a, int b) { int t = a; a = b; b = t; }
>
> int x = 1, y = 2;
> swap(x, y);
> System.out.println(x + " " + y);   // 1 2  – τίποτα δεν άλλαξε
> ```
> Η `swap` αντιμεταθέτει τα **αντίγραφά** της `a`, `b`. Όταν τελειώσει, τα αντίγραφα χάνονται· τα `x`, `y` της `main` δεν άγγιξαν ποτέ. Γι' αυτό η `swap` της [[02 - Παράμετροι, Τιμές Επιστροφής και return#5. Παράδειγμα όπου η τιμή εξόδου μπορεί να αγνοηθεί: swap (VIII-13)|VIII-13]] παίρνει **πίνακα**: αντιγράφεται η διεύθυνση, αλλά δείχνει στον **ίδιο** πίνακα ([[04 - Πίνακες ως Παράμετροι Συναρτήσεων|04]]).

## 5. Αντιστοιχία ορισμάτων με παραμέτρους (VIII-22)

> [!important] Τρεις κανόνες
> 1. Ο **αριθμός ορισμάτων** σε δεδομένη κλήση πρέπει να είναι ο ίδιος με τον αριθμό παραμέτρων στον ορισμό.
> 2. Η αντιστοιχία αποφασίζεται από τη **σειρά** των ορισμάτων: το πρώτο όρισμα στην πρώτη παράμετρο, το δεύτερο στη δεύτερη, κτλ.
> 3. Ο **τύπος** κάθε ορίσματος πρέπει να είναι **συμβατός** με τον τύπο της αντίστοιχης παραμέτρου: να μπορεί να καταχωρηθεί χωρίς **απροσδόκητη** απώλεια πληροφορίας. Π.χ. `int` μπορεί να ανατεθεί σε `double` χωρίς απώλεια· ένα `double` μπορεί να ανατεθεί σε `int` μόνο με ρητή μετατροπή, με **αναμενόμενη** απώλεια των δεκαδικών.
>
> **Σημ.:** Η Java επιτρέπει να δοθεί η τιμή `int` μεταβλητής ως όρισμα σε παράμετρο `double`, αλλά **όχι** το ανάποδο.

> [!example]- ➕ Τι περνά και τι όχι (ελέγχθηκαν)
>
> | Παράμετρος | Όρισμα | Αποτέλεσμα |
> |---|---|---|
> | `double` | `5` (`int`) | ✓ γίνεται `5.0` |
> | `double` | `'x'` (`char`) | ✓ γίνεται `120.0` |
> | `int` | `'A'` (`char`) | ✓ γίνεται `65` |
> | `long` | `3` | ✓ |
> | `int` | `3L` (`long`) | ✗ `possible lossy conversion from long to int` |
> | `int` | `2.0` (`double`) | ✗ `possible lossy conversion from double to int` |
> | `int` | `(int) 2.7` | ✓ γίνεται `2` (ρητή μετατροπή, αναμενόμενη απώλεια) |
> | `double[]` | `int[]` | ✗ `int[] cannot be converted to double[]` – οι **πίνακες δεν** μετατρέπονται αυτόματα |
> | `double[]` | `{1.0, 2.0}` | ✗ συντακτικό λάθος· γράφεις `new double[]{1.0, 2.0}` |
>
> Η αυτόματη μετατροπή ακολουθεί την αλυσίδα `byte → short → int → long → float → double` (και `char → int`), όπως στην [[08 - Μετατροπή Τύπων|ανάθεση]].

## 6. Εμβέλεια μεταβλητών (VIII-23, VIII-24)

> [!note] Εμβέλεια (scope)
> **Εμβέλεια** (ενός ονόματος): ο κώδικας ο οποίος αναφέρεται σε αυτό το όνομα. Π.χ. η εμβέλεια μιας μεταβλητής είναι ο κώδικας που ακολουθεί τη δήλωση **στο μπλοκ** της.
> - Οι μεταβλητές από έξω από μια συνάρτηση **δεν υπάρχουν** μέσα της αν δεν έχουν περαστεί ως παράμετροι.
> - Ανεξάρτητα από το πόσο πολύπλοκο είναι ένα πρόγραμμα, μέσα στη `add` υπάρχουν **μόνο** οι `x`, `y` και `z`.

```java
public class Newton {
   public static double sqrt(double c) {
      double epsilon = 1e-15;
      if (c < 0) return Double.NaN;
      double t = c;
      while (Math.abs(t - c/t) > epsilon * t)
         t = (c/t + t) / 2.0;
      return t;
   }

   public static void main(String[] args) {
      double[] a = new double[args.length];
      for (int i = 0; i < args.length; i++)
         a[i] = Double.parseDouble(args[i]);
      for (int i = 0; i < a.length; i++) {
         double x = sqrt(a[i]);
         StdOut.println(x);
      }
   }
}
```

| Όνομα | Εμβέλεια |
|---|---|
| `c` | όλο το σώμα της `sqrt` (παράμετρος) |
| `epsilon` | από τη δήλωσή του μέχρι το τέλος της `sqrt` |
| `t` | από τη δήλωσή του (μετά τον έλεγχο `c < 0`) μέχρι το τέλος της `sqrt` |
| `a` | από τη δήλωσή του μέχρι το τέλος της `main` |
| `i` (1ο) | μόνο ο **πρώτος** `for` |
| `i` (2ο) | μόνο ο **δεύτερος** `for` – **2 διαφορετικές μεταβλητές με το ίδιο όνομα** |
| `x` | μόνο το σώμα του δεύτερου `for` |

> [!important] Η καλύτερη πρακτική
> **Δηλώστε μεταβλητές για να περιορίσετε την εμβέλειά τους**: όσο πιο κοντά στο σημείο χρήσης, στο μικρότερο δυνατό μπλοκ. Λιγότερος κώδικας «βλέπει» τη μεταβλητή → λιγότερα σημεία όπου μπορεί να αλλάξει κατά λάθος.

> [!example]- ➕ Η `sqrt` με ακραίες τιμές (ελέγχθηκε)
> `sqrt(0)` → `0.0` · `sqrt(1)` → `1.0` · `sqrt(2)` → `1.414213562373095` · `sqrt(-4)` → `NaN` · `sqrt(1e10)` → `100000.0` · `sqrt(0.25)` → `0.5`.
> Για `c = 0`: `t = 0`, `c/t` = `0.0/0.0` = `NaN`, και `NaN > …` είναι `false`, άρα ο βρόχος δεν εκτελείται και επιστρέφεται `0.0` – σωστό, αλλά «από τύχη».

> [!warning] ➕ Οι κανόνες εμβέλειας της Java (ελέγχθηκαν)
>
> | Κώδικας | Αποτέλεσμα |
> |---|---|
> | `int x=1; { int x=2; }` | ✗ `variable x is already defined` – η Java **δεν** επιτρέπει ίδιο όνομα σε εσωτερικό μπλοκ |
> | `int i=0; for (int i=0; …)` | ✗ ίδιο λάθος |
> | `for (int i…){} for (int i…){}` | ✓ – διαδοχικά μπλοκ, όχι φωλιασμένα (όπως στη `Newton`) |
> | `{ int z=1; } { int z=2; }` | ✓ |
> | `int add(int x, int y){ int x=3; … }` | ✗ – η παράμετρος είναι ήδη τοπική μεταβλητή της μεθόδου |
> | `add(1,2); System.out.println(z);` στη `main` | ✗ `cannot find symbol` – το `z` υπάρχει μόνο μέσα στη `add` |
>
> Αντίθετα, μια **παράμετρος** μπορεί να έχει ίδιο όνομα με μεταβλητή **άλλης** μεθόδου ή με **στατική μεταβλητή της κλάσης** (`static int x = 10;`): μέσα στη μέθοδο το όνομα αναφέρεται στην παράμετρο («επισκιάζει» την κλάσης).

> [!tip] ➕ Στατικές μεταβλητές κλάσης
> Μια μεταβλητή δηλωμένη **έξω** από κάθε μέθοδο, μέσα στην κλάση (`private static int counter = 0;`), είναι ορατή σε **όλες** τις μεθόδους της κλάσης και **κρατά την τιμή της** ανάμεσα στις κλήσεις. Τη χρησιμοποιεί π.χ. ο πίνακας `memo` της [[05 - Τρίγωνο του Pascal και Memoization|Ενότητας X]]. Είναι η εξαίρεση στο «ό,τι δεν περνά ως παράμετρος δεν υπάρχει» – και ακριβώς γι' αυτό χρησιμοποιείται με φειδώ (αυξάνει τη σύζευξη, [[03 - Σχεδιασμός Μονάδων|V – 03]]).

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Πίστη ότι η αλλαγή μιας παραμέτρου (`a = b;`) αλλάζει τη μεταβλητή του καλούντα: το πέρασμα είναι **δια τιμής**.
> - Σύγχυση ονομάτων: το `x` του καλούντα και το `x` της συνάρτησης είναι **διαφορετικές** μεταβλητές· η αντιστοίχιση γίνεται με τη **σειρά**, όχι με το όνομα.
> - Λάθος πλήθος ή σειρά ορισμάτων (`add(int, double)` κληθείσα ως `add(2.5, 1)` → λάθος τύπου).
> - Όρισμα `double` σε παράμετρο `int` χωρίς cast.
> - Χρήση τοπικής μεταβλητής μιας μεθόδου μέσα σε άλλη.
> - Επαναδήλωση μεταβλητής σε εσωτερικό μπλοκ (επιτρέπεται σε C, όχι σε Java).
