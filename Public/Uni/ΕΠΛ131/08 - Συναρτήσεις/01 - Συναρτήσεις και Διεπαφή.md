# 01 - Συναρτήσεις και Διεπαφή

Τι είναι μια συνάρτηση, γιατί τη χρειαζόμαστε, και η **διεπαφή** της: τι παίρνει, τι επιστρέφει, και πώς γράφεται στη Java ως **στατική μέθοδος** (διαφάνειες VIII-1 … VIII-8).

## 1. Γιατί συναρτήσεις (VIII-1 … VIII-4)

> [!note] Ορισμός
> Μια **συνάρτηση** (function) είναι ένα κομμάτι κώδικα με όνομα που:
> - **δέχεται ορίσματα** (έχει **παραμέτρους**),
> - **επιστρέφει μια τιμή** (προαιρετικά),
> - **απομονώνει** την επίλυση ενός υπο-προβλήματος.
>
> Είναι θεμελιώδης για τον **δομημένο** προγραμματισμό και σχετίζεται με τις περισσότερες [[Uni/ΕΠΛ131/05 - Αρχές Ορθού Προγραμματισμού/00 - Ευρετήριο|αρχές ορθού προγραμματισμού]] (αφαιρετικότητα, DRY, αρθρωτότητα).

![[Συναρτήσεις - Μαύρο Κουτί.png|800]]

> [!important] Καθαρές συναρτήσεις (pure functions)
> Ιδανικά μια συνάρτηση **δεν επηρεάζει τίποτα άλλο** στο πρόγραμμα πέρα από αυτό που φαίνεται στη διεπαφή της: παίρνει ορίσματα, επιστρέφει τιμή. Καμία **παρενέργεια** (side effect), δηλαδή κανένα «πλευρικό φαινόμενο».
> - Καθαρή: `Math.abs(x)`, `min2(a, b)` – ίδια ορίσματα δίνουν πάντα ίδιο αποτέλεσμα και δεν αλλάζουν τίποτα.
> - Με παρενέργειες: `System.out.println(…)` (γράφει στην οθόνη), `StdIn.readInt()` (καταναλώνει είσοδο), μια `sort(table)` που αλλάζει τον πίνακα του καλούντα, `Math.random()` (δεν δίνει ίδιο αποτέλεσμα).

| Πλεονέκτημα (VIII-4) | Τι σημαίνει |
|---|---|
| **Αρθρωτός σχεδιασμός** | το πρόγραμμα σπάει σε ξεχωριστές εργασίες· κάθε εργασία μπορεί να ανατεθεί σε άλλον προγραμματιστή |
| **Επαναχρησιμοποίηση κώδικα** | ο ίδιος κώδικας χρησιμοποιείται ξανά και ξανά· βιβλιοθήκες όπως η `Math` · λιγότερη επικάλυψη |
| **Αναγνωσιμότητα** | κάθε συνάρτηση κάνει λίγες, ξεκάθαρες εργασίες με διαφανή λειτουργικότητα |

## 2. Γενικά: τιμές, διευθύνσεις και έξοδοι (VIII-5)

1. Η συνάρτηση `f` **λαμβάνει τιμές** και **επιστρέφει τιμή**.
2. Οι τιμές μπορεί να είναι **διευθύνσεις**, π.χ. πινάκων ή αντικειμένων.
3. Αν λαμβάνει διευθύνσεις, αυτές μπορούν **έμμεσα** να λειτουργήσουν ως **(επιπρόσθετες) έξοδοι**: η συνάρτηση γράφει μέσα στον πίνακα και ο καλών βλέπει την αλλαγή ([[04 - Πίνακες ως Παράμετροι Συναρτήσεων|04]]).

Παράδειγμα της διαφάνειας: συνάρτηση που παίρνει πίνακα ακεραίων και επιστρέφει το πλήθος των αρνητικών.

```java
public static int negative (int[] table) {
   int count = 0;
   for (int v : table)
      if (v < 0) count++;
   return count;
}
```

Η διαφάνεια δίνει μόνο την επικεφαλίδα `{..}`· το σώμα είναι ➕. `negative(new int[]{-1, 0, 3, -7})` → `2` · `negative(new int[0])` → `0` · `negative(null)` → `NullPointerException` (ελέγχθηκαν).

## 3. Η διεπαφή μιας συνάρτησης (VIII-5)

> [!note] Διεπαφή (interface) – ταυτότητα (signature)
> Η διεπαφή/επικοινωνία της συνάρτησης με το υπόλοιπο πρόγραμμα:
> - **ποια** είναι η λειτουργία της: τι λαμβάνει, τι επιστρέφει, άρα τι λειτουργικότητα παρέχει.
> - Αυτή είναι η **ουσία**: **το τι** παρέχει, όχι **το πώς** υλοποιείται. Διαχωρισμός ανάμεσα στο **«τι»** και στο **«πώς»**.

Ο χρήστης της `Math.sqrt` ξέρει «δίνω `double`, παίρνω τη ρίζα του». Δεν ξέρει (ούτε χρειάζεται να ξέρει) αν υλοποιείται με τη μέθοδο του Newton ([[03 - Κλήση, Ορίσματα, Binding και Εμβέλεια#6. Εμβέλεια μεταβλητών (VIII-23, VIII-24)|03 §6]]) ή αλλιώς. Αν αλλάξει το «πώς», ο κώδικας που την καλεί δεν αλλάζει. Είναι η αρχή [[03 - Σχεδιασμός Μονάδων|«απόκρυψη υλοποίησης»]] της Ενότητας V.

> [!warning] ➕ Τι ακριβώς είναι το signature για τον μεταγλωττιστή
> Στη Java το **signature** μιας μεθόδου είναι **όνομα + λίστα τύπων παραμέτρων** (με τη σειρά τους). **Δεν** περιλαμβάνει:
> - τον **τύπο επιστροφής**,
> - τα **ονόματα** των παραμέτρων,
> - τα `public`/`private`/`static`.
>
> Γι' αυτό `int f(int a)` και `double f(int a)` στην ίδια κλάση **δεν** επιτρέπονται: `error: method f(int) is already defined` (ελέγχθηκε). Το ίδιο και `int f(int a)` με `int f(int b)`. Αυτό μετράει στην [[05 - Υπερφόρτωση Συναρτήσεων|υπερφόρτωση]].
>
> Οι διαφάνειες χρησιμοποιούν «διεπαφή» και «signature» με την ευρύτερη έννοια (μαζί με τον τύπο επιστροφής)· η διάκριση χρειάζεται μόνο όταν ρωτηθεί «ποιες δύο μέθοδοι μπορούν να συνυπάρχουν».

## 4. Είσοδοι και έξοδοι: τέσσερις συνδυασμοί (VIII-6)

Πέρα από τη γενική διεπαφή «είσοδοι → έξοδος», μπορεί να έχουμε:

| Είδος | Παράδειγμα της διαφάνειας | Γιατί |
|---|---|---|
| Είσοδοι **και** έξοδος | `public static int negative(int[] table)` | η γενική περίπτωση |
| **Μόνο είσοδοι** (που μπορεί να είναι διευθύνσεις) | `public static void sort(int[] table)` | ταξινομεί τον πίνακα **επί τόπου**· ο καλών βλέπει τον ταξινομημένο πίνακα μέσω της διεύθυνσης |
| **Μόνο έξοδος** (που μπορεί να είναι διεύθυνση) | `public static double[] create()` | φτιάχνει πίνακα με τυχαίους από το `[0, 1.0)`· όπως η `Math.random()` |
| **Ούτε είσοδοι ούτε έξοδος** | `public static void displayMenu()` | απλώς τυπώνει ένα μενού επιλογών |

![[Συναρτήσεις - Είσοδοι και Έξοδοι.png|800]]

> [!example]- ➕ Υλοποίηση της `create` (ελέγχθηκε)
> Η διαφάνεια δεν λέει πόσα στοιχεία· με παράμετρο πλήθους γίνεται «είσοδος και έξοδος»:
> ```java
> public static double[] create(int n) {
>    double[] t = new double[n];
>    for (int i = 0; i < n; i++)
>       t[i] = Math.random();
>    return t;                    // επιστρέφει τη ΔΙΕΥΘΥΝΣΗ του νέου πίνακα
> }
> ```
> `double[] r = create(3);` → πίνακας 3 στοιχείων στο `[0, 1)`. `create(0)` → κενός πίνακας (`length == 0`), όχι `null`. Ο πίνακας ζει στον σωρό (heap): **δεν** χάνεται όταν τελειώσει η `create` – χάνεται μόνο η τοπική μεταβλητή `t`.

## 5. Συναρτήσεις στη Java: στατικές μέθοδοι (VIII-7)

> [!note] Java συνάρτηση
> - Παίρνει **καμία ή περισσότερες** παραμέτρους εισόδου.
> - Επιστρέφει **μία** τιμή εξόδου – **δεν είναι υποχρεωτικό** (`void`).
>
> Στη Java κάθε συνάρτηση ανήκει σε μια **κλάση**· όσες δεν χρειάζονται αντικείμενο δηλώνονται **`static`** («στατικές μέθοδοι»).

| Εφαρμογή | |
|---|---|
| Επιστήμονες | μαθηματικές συναρτήσεις για υπολογισμό μαθηματικών τύπων |
| Προγραμματιστές | συναρτήσεις για **αρθρωτά** προγράμματα |
| Εσείς | και τα δύο |

| Παραδείγματα | |
|---|---|
| Ενσωματωμένες | `Math.random()`, `Math.abs()`, `Integer.parseInt()` |
| Βιβλιοθήκες Ε/Ε | `StdIn.readInt()`, `StdDraw.line()`, `StdAudio.play()` |
| Ορισμένες από τον χρήστη | `main()` |

> [!tip] Η `main` είναι κι αυτή συνάρτηση
> `public static void main(String[] args)`: μία παράμετρος (πίνακας `String`), καμία τιμή εξόδου. Την καλεί το `java` όταν τρέχεις το πρόγραμμα, με τα ορίσματα της γραμμής εντολής ([[01 - Ορίσματα Γραμμής Εντολής και printf|VII – 01]]).

## 6. Ανατομία της σύνταξης (VIII-8)

```java
public static type name(type arg1, ..., type argn)
{
     statement1;
     statement2;
     ...
     statementm;
}
```

| Κομμάτι | Ρόλος |
|---|---|
| `public static` | απαιτούμενη σύνταξη (μπορεί να είναι και `private static`) |
| `type` (πριν το όνομα) | **τύπος τιμής εξόδου** (`int`, `double[]`, …, ή `void`) |
| `name` | όνομα συνάρτησης |
| `type arg1, …, type argn` | **τιμές εισόδου**: για κάθε παράμετρο τύπος και όνομα |
| `{ statement1; … }` | κώδικας που εκτελείται από τη συνάρτηση (σώμα) |

> [!important] Η εντολή `return`
> - Μπορεί να κληθεί **ακόμη και όταν δεν υπάρχει τιμή εξόδου**.
> - Σε συνάρτηση τύπου **`void`** μπορεί να κληθεί **μόνο χωρίς έκφραση**: `return;`
> - Λεπτομέρειες και κανόνες του μεταγλωττιστή: [[02 - Παράμετροι, Τιμές Επιστροφής και return#6. Η εντολή return (VIII-14)|02 §6]].

> [!warning] ➕ Κανόνες σύνταξης που ξεχνιούνται (ελέγχθηκαν)
> - **Χωρίς τύπο επιστροφής** δεν είναι μέθοδος: `public static main(String[] args)` → `error: invalid method declaration; return type required`. Ακόμη κι όταν δεν επιστρέφει τίποτα, γράφεις `void`.
> - **Μέθοδος μέσα σε μέθοδο** δεν επιτρέπεται: όλες οι μέθοδοι γράφονται **δίπλα-δίπλα** μέσα στην κλάση.
> - Η **σειρά** των μεθόδων στην κλάση **δεν έχει σημασία**: η `main` μπορεί να καλεί μέθοδο που ορίζεται πιο κάτω.
> - Κάθε παράμετρος θέλει **δικό της τύπο**: `(int a, int b)`, όχι `(int a, b)`.
> - Καμία παράμετρος → κενές παρενθέσεις, και στον ορισμό και στην κλήση: `displayMenu()`.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Παράλειψη του `void` σε μέθοδο που δεν επιστρέφει τιμή (το κάνει και η VIII-28).
> - Σύγχυση «τι» και «πώς»: ο χρήστης μιας συνάρτησης πρέπει να χρειάζεται **μόνο** τη διεπαφή της.
> - Πίστη ότι ο τύπος επιστροφής ή τα ονόματα παραμέτρων αρκούν για να ξεχωρίσουν δύο μεθόδους με το ίδιο όνομα.
> - `(int a, b)` αντί για `(int a, int b)`.
> - Πίστη ότι μια `void` συνάρτηση «δεν κάνει τίποτα»: μπορεί να αλλάζει πίνακα που της δόθηκε (`sort`) ή να τυπώνει.
