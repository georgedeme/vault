# 02 - Συμβολοσειρές ως Δείκτες και Σύγκριση

Γιατί ένα `String` δεν αλλάζει ποτέ, γιατί οι μεταβλητές `String` είναι δείκτες όπως οι πίνακες, και πώς συγκρίνουμε σωστά (διαφάνειες VI-6 … VI-15).

## 1. Δημιουργία αλλά όχι τροποποίηση (VI-6)

> [!important] Περιορισμός: τα `String` είναι αμετάβλητα (immutable)
> Από τις παρεχόμενες λειτουργίες προκύπτει ότι:
> - Αφού κατασκευάσουμε (μια περίπτωση) `String` **δεν μπορούμε** να αλλάξουμε κάποιο στοιχείο του (κάποιο χαρακτήρα του): **καμία** λειτουργία δεν μας δίνει αυτή τη δυνατότητα.
> - Μπορούμε να το «αλλάξουμε» μόνο **ξαναδημιουργώντας** το.
> - Και βεβαίως μπορούμε να δημιουργήσουμε/κατασκευάσουμε **άλλα** strings από αυτό.

```java
String s = "This is a string";
s = s.substring(0,1) + s.charAt(s.length()-1);   // "T" + 'g' → s = "Tg" (ΝΕΟ string)

String s1 = "Another string";
String s2 = s1.substring(0,8);                   // "Another " – προσοχή: με το κενό στο τέλος!
```

> [!warning] ⚠️ Σημείωση: «έξυπνα» εισαγωγικά στις διαφάνειες
> Στις VI-6, VI-12 και VI-30 ο κώδικας έχει τυπογραφικά εισαγωγικά (`“This is a string”`, `‘ ‘`) αντί για τα απλά `"` και `'`. Αυτό είναι θέμα του προγράμματος παρουσίασης· στη Java δίνει `error: illegal character: '“'`. Στον κώδικα γράφεις **πάντα** `"…"` και `'…'`.

> [!example]- Πώς «αλλάζεις» τον χαρακτήρα στη θέση `i`
> ```java
> String s = "cat";
> s.charAt(0) = 'b';                                   // ✗ compile: unexpected type
> s = 'b' + s.substring(1);                            // ✓ "bat" – νέο string
> s = s.substring(0, i) + c + s.substring(i + 1);      // γενικά, για θέση i και χαρακτήρα c
> ```
> Το `'b' + s.substring(1)` δουλεύει επειδή ο δεύτερος τελεστέος είναι `String`. Το `'b' + 'a'` θα έδινε `int` (`195`)!

## 2. Οι περιπτώσεις `String` είναι δείκτες (VI-7, VI-8)

> [!important] Επιπρόσθετα, όπως οι πίνακες, και οι περιπτώσεις αντικειμένων είναι **δείκτες**
> Μια μεταβλητή `String` **δεν περιέχει** τους χαρακτήρες· περιέχει τη **διεύθυνση** του αντικειμένου (όπως στους [[03 - Πίνακες ως Αναφορές και Μέθοδοι|πίνακες, IV – 03]]).

```java
String s1 = "some string";   // s1 ──► [some string]
String s2;                   // s2 ──┤   (δεν δείχνει πουθενά)
```

## 3. `new String(s1)` vs `s2 = s1` (VI-9 … VI-11)

![[Δείκτες - new String και Ανάθεση.excalidraw|800]]

| Κώδικας | Αντικείμενα | `s1 == s2` | `s1.equals(s2)` |
|---|---|---|---|
| `s2 = new String(s1);` (copy constructor) | **δύο**, με ίδιους χαρακτήρες | `false` | `true` |
| `s2 = s1;` | **ένα** – και οι δύο δείχνουν σε αυτό | `true` | `true` |

> [!important] `==` συγκρίνει δείκτες, `equals` συγκρίνει ακολουθίες χαρακτήρων
> - `s1 == s2`: είναι **το ίδιο** αντικείμενο (ίδια διεύθυνση);
> - `s1.equals(s2)`: έχουν **τους ίδιους χαρακτήρες**;
> - Η `equals` είναι **συμμετρική**: `s1.equals(s2)` == `s2.equals(s1)` (εκτός αν κάποιο είναι `null`, §6).

```java
public class StringTest {

 public static void main(String[] args){
   String s1 = "some string";
   String s2; // null pointer
   s2 = new String(s1); // copy constructor

   if (s1==s2) System.out.println("Same instance");
   else System.out.println("Not same instance");
   if (s1.equals(s2)) System.out.println("Same value");
   else System.out.println("Not same value");

   s2 = s1;

   if (s1==s2) System.out.println("Same instance");
   else System.out.println("Not same instance");
   if (s1.equals(s2)) System.out.println("Same value");
   else System.out.println("Not same value");
 }
}
```
```
$ java StringTest
Not same instance
Same value
Same instance
Same value
```

Μετά το `s2 = s1;` το αντίγραφο που έφτιαξε το `new String(s1)` δεν το δείχνει πια **καμία** μεταβλητή: είναι «σκουπίδι» και η Java θα ελευθερώσει τη μνήμη του αυτόματα (garbage collection).

## 4. Μη αρχικοποιημένες μεταβλητές και επαναδημιουργία (VI-12, VI-13)

```java
String s1 = "some string"; // initialized
String s2; // null pointer - not initialized

s2 += "some value";        // error - s2 not initialized
if (s2.equals(s1)) {..}    // error - s2 not initialized

s1 += s1; // s1 is recreated!
```

> [!warning] ⚠️ Σημείωση: το σχόλιο «null pointer» δεν ισχύει για **τοπική** μεταβλητή
> Μια τοπική μεταβλητή (μέσα σε μέθοδο) που δηλώθηκε χωρίς τιμή **δεν** είναι `null` – δεν έχει **καμία** τιμή, και ο compiler απαγορεύει να τη διαβάσεις: `error: variable s2 might not have been initialized`. Το «λάθος» της διαφάνειας είναι λοιπόν **σφάλμα μεταγλώττισης**, όχι εκτέλεσης (και το `javac` το αναφέρει μία φορά, στην πρώτη χρήση).
>
> Η συμπεριφορά αλλάζει αν η μεταβλητή **είναι** `null`:
>
> | Δήλωση | `s2 += "some value";` | `s2.equals(s1)` |
> |---|---|---|
> | τοπική: `String s2;` | ✗ compile error | ✗ compile error |
> | τοπική: `String s2 = null;` | ✓ `s2` γίνεται **`"nullsome value"`** (!) | ✗ `NullPointerException` στην εκτέλεση |
> | πεδίο κλάσης: `static String s2;` (προεπιλογή `null`) | ✓ `"nullsome value"` | ✗ `NullPointerException` |
>
> Το ίδιο ισχύει για στοιχεία πίνακα: `new String[3]` περιέχει τρία `null` ([[03 - Πίνακες ως Αναφορές και Μέθοδοι|IV – 03 §5]]).

### `s1 += s1;` – το `s1` ξαναδημιουργείται

![[Δείκτες - Επαναδημιουργία με +=.excalidraw|800]]

> [!important] `s += t` σημαίνει `s = s + t`: **νέο** αντικείμενο
> Το παλιό `"some string"` **δεν** αλλάζει. Δημιουργείται νέο `"some stringsome string"` και το `s1` δείχνει πλέον εκεί. Το παλιό, αν δεν το δείχνει κανείς άλλος, γίνεται σκουπίδι.

> [!example]- «Μοιάζει ίδιο, δεν είναι»: alias σε `String` vs alias σε πίνακα
> ```java
> String a = "x";  String b = a;        // alias
> a += "y";                             // a ΞΑΝΑΔΗΜΙΟΥΡΓΕΙΤΑΙ
> System.out.println(a + " " + b);      // xy x   – το b δεν είδε την αλλαγή
>
> char[] p = {'x'};  char[] q = p;      // alias
> p[0] = 'y';                           // αλλαγή ΜΕΣΑ στον πίνακα
> System.out.println(q[0]);             // y      – το q την είδε
> ```
> Με πίνακες μπορείς να αλλάξεις τα περιεχόμενα του κοινού αντικειμένου· με `String` δεν μπορείς, οπότε το aliasing είναι **ακίνδυνο**. Γι' αυτό μια μέθοδος που παίρνει `String` **δεν** μπορεί ποτέ να αλλάξει το string του καλούντα.

## 5. Λεξικογραφική σύγκριση με compareTo (VI-14)

```java
String s1 = "xy1";
String s2 = "xy1";
String s3 = "xy1a";
String s4 = "wa";

s1.compareTo(s2); // 0
s1.compareTo(s3); // <0
s1.compareTo(s4); // >0

//λεξικογραφική σύγκριση
```

> [!note] Πώς υπολογίζεται η `s.compareTo(t)`
> 1. Βρες την **πρώτη θέση** `k` όπου διαφέρουν οι χαρακτήρες. Αν υπάρχει → αποτέλεσμα `s.charAt(k) - t.charAt(k)` (διαφορά **κωδικών**).
> 2. Αν δεν υπάρχει (το ένα είναι **πρόθεμα** του άλλου) → αποτέλεσμα `s.length() - t.length()`.
>
> | Αποτέλεσμα | Σημαίνει |
> |---|---|
> | `< 0` | το `s` είναι **πριν** το `t` («μικρότερο») |
> | `0` | ίδιοι χαρακτήρες (όπως `equals`) |
> | `> 0` | το `s` είναι **μετά** το `t` |

| Κλήση | Τιμή | Εξήγηση |
|---|---|---|
| `"xy1".compareTo("xy1")` | `0` | ίδια |
| `"xy1".compareTo("xy1a")` | `-1` | πρόθεμα: `3 − 4` |
| `"xy1".compareTo("wa")` | `1` | `'x' − 'w'` (το μήκος **δεν** μετράει) |
| `"cat".compareTo("car")` | `2` | `'t' − 'r'` |
| `"b".compareTo("aaaa")` | `1` | ο πρώτος χαρακτήρας αποφασίζει, όχι το μήκος |
| `"abc".compareTo("abcde")` | `-2` | πρόθεμα: `3 − 5` |
| `"apple".compareTo("Apple")` | `32` | `'a'`(97) − `'A'`(65): **κεφαλαία πριν** από πεζά |
| `"Zebra".compareTo("apple")` | `-7` | `'Z'`(90) < `'a'`(97): το `"Zebra"` είναι **πριν** το `"apple"`! |
| `"10".compareTo("9")` | `-8` | `'1'` − `'9'`: σύγκριση **χαρακτήρων**, όχι αριθμών |
| `"".compareTo("a")` | `-1` | το κενό είναι πριν από όλα |

> [!warning] Παγίδες σύγκρισης
> - `if (s1 < s2)` ✗ compile: `bad operand types for binary operator '<'`. Για σειρά: `s1.compareTo(s2) < 0`.
> - Μην ελέγχεις `== -1` ή `== 1`: εγγυημένο είναι μόνο το **πρόσημο**.
> - «Λεξικογραφική» ≠ «αλφαβητική όπως στο λεξικό»: τα κεφαλαία είναι όλα πριν τα πεζά, και οι αριθμοί σε μορφή κειμένου ταξινομούνται ψηφίο-ψηφίο (`"10" < "9"`). Για αλφαβητική χωρίς διάκριση: `compareToIgnoreCase`. Οι κωδικοί: [[05 - String και char#5. Κωδικοποίηση χαρακτήρων – ASCII (II-37, II-38)|II – 05]].

## 6. Κυριολεκτικά και ==: γιατί μερικές φορές «δουλεύει» ➕

Στο παράδειγμα της VI-14, `s1` και `s2` γράφτηκαν ως **ίδιο κυριολεκτικό** `"xy1"`. Η Java κρατά **ένα** αντικείμενο για κάθε διαφορετικό κυριολεκτικό (δεξαμενή κυριολεκτικών, string pool), οπότε εκεί `s1 == s2` είναι **`true`**!

![[Δείκτες - Κυριολεκτικά και ==.excalidraw|800]]

| Κώδικας | `==` με `a = "java"` | Γιατί |
|---|---|---|
| `String b = "java";` | `true` | ίδιο κυριολεκτικό → ίδιο αντικείμενο |
| `String b = "ja" + "va";` | `true` | συνένωση **σταθερών**: γίνεται στη μεταγλώττιση |
| `String b = new String(a);` | `false` | το `new` φτιάχνει **πάντα** νέο αντικείμενο |
| `String e = "ja"; e += "va";` | `false` | συνένωση **στην εκτέλεση** → νέο αντικείμενο |
| `"ATGC".substring(0, 3) == "ATG"` | `false` | η `substring` δημιουργεί νέο αντικείμενο |

> [!warning] Συμπέρασμα: πάντα `equals`
> Το αν το `==` «πετυχαίνει» εξαρτάται από το **πώς** δημιουργήθηκαν τα strings, κάτι που συνήθως δεν φαίνεται (π.χ. strings από `args`, `StdIn`, `substring`). Ένα πρόγραμμα που δοκιμάστηκε με κυριολεκτικά μπορεί να «σπάσει» με δεδομένα από είσοδο. Παράδειγμα: στο [[04 - Εύρεση Γονιδίου|GeneFind]] το `codon == start` δεν θα έβρισκε **ποτέ** γονίδιο.

> [!tip] `equals` και `null`
> - `"hi".equals(null)` → `false` (καμία εξαίρεση).
> - `s.equals("hi")` με `s == null` → **`NullPointerException`**.
> - Ασφαλής μορφή: `"hi".equals(s)` – το κυριολεκτικό δεν είναι ποτέ `null`.
> - Χωρίς διάκριση πεζών/κεφαλαίων: `s.equalsIgnoreCase(t)`.

## 7. Αναπαράσταση στη μνήμη (VI-15)

```java
String genome = "aacaagtttacaagc";
String s = genome.substring(1, 5);    // "acaa"
String t = genome.substring(9, 13);   // "acaa"
```

Πιθανή αναπαράσταση της μνήμης για μία συμβολοσειρά: ο πίνακας χαρακτήρων στις διευθύνσεις `D0 … DE`, και η μεταβλητή `genome` κρατά (**διεύθυνση μνήμης** `D0`, **μήκος** `15`). Τα `s` και `t` είναι **ξεχωριστές** συμβολοσειρές (`s` = (`D1`, 4), `t` = (`D9`, 4)), οι οποίες απλά μοιράζονται την ίδια τιμή, `"acaa"`.

> [!important] `(s == t)` είναι `false`, αλλά `(s.equals(t))` είναι `true`
> Ο τελεστής `==` συγκρίνει **δείκτες**, ενώ η μέθοδος `equals` συγκρίνει **ακολουθίες χαρακτήρων**.

![[Δείκτες - substring στη Μνήμη.excalidraw|800]]

> [!warning] ⚠️ Σημείωση: η σημερινή Java δεν μοιράζεται τους χαρακτήρες
> Το μοντέλο της διαφάνειας (η `substring` επιστρέφει νέο ζεύγος «διεύθυνση, μήκος» μέσα στον **ίδιο** πίνακα χαρακτήρων) είναι το πώς δούλευε η Java μέχρι την έκδοση 7u6 (2012). Από τότε η `substring` **αντιγράφει** τους χαρακτήρες σε νέο πίνακα. Το «τι» (τιμή, `==`, `equals`) είναι **ίδιο** και στα δύο μοντέλα· άλλαξε μόνο το «πώς» – ακριβώς η ευελιξία του [[01 - Το String ως Αφηρημένος Τύπος Δεδομένων#3. Αφηρημένοι vs Συγκεκριμένοι Τύποι (VI-3)|αφηρημένου τύπου]]. Στις εξετάσεις χρησιμοποίησε το μοντέλο της διαφάνειας αν ζητηθεί σχήμα.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - `s1 == s2` για σύγκριση περιεχομένου (και «πετυχαίνει» στις δοκιμές με κυριολεκτικά).
> - `s.toUpperCase();` χωρίς ανάθεση – τα strings δεν αλλάζουν.
> - `s.charAt(i) = 'x';` ✗ compile.
> - Περιμένεις ένα alias `String` να «δει» αλλαγή μετά από `+=`.
> - Χρήση τοπικής μεταβλητής `String` χωρίς αρχικοποίηση (`String s; s += …`) → compile error. Ξεκίνα με `String s = "";`.
> - `String s = null; s += "x";` → `"nullx"`, όχι `"x"`.
> - `s1 < s2` ✗ – χρησιμοποίησε `compareTo`. Και μην ξεχνάς ότι `"Zebra" < "apple"`.
