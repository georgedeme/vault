# 06 - Πίνακες με Στοιχεία Συμβολοσειρές

Μια μικρή βιβλιοθήκη (`TabLib`) για πίνακες `String[]` που «μεγαλώνουν»: προσθήκη, φιλτράρισμα, εμφάνιση και αντιστροφή, εφαρμοσμένη στις γραμμές ενός αρχείου (διαφάνειες VI-32 … VI-35).

## 1. Η ιδέα

Ένας πίνακας έχει **σταθερό** μέγεθος ([[01 - Πίνακες στη Java|IV – 01]]). Όταν διαβάζουμε γραμμές από την είσοδο **δεν ξέρουμε πόσες θα είναι**. Η `TabLib` λύνει το πρόβλημα φτιάχνοντας κάθε φορά **νέο πίνακα κατά ένα μεγαλύτερο**.

Συμβάσεις της βιβλιοθήκης:
- Ο «κενός» πίνακας αναπαρίσταται με **`null`** (όχι με πίνακα μήκους 0).
- Οι `add`, `remove`, `select` **δεν αλλάζουν** τον πίνακα που παίρνουν: **επιστρέφουν νέο**.
- Οι `display`, `reverse` επιστρέφουν `void`: η `reverse` αλλάζει τον πίνακα **επιτόπου**.

## 2. `add`: προσθήκη στην αρχή (VI-32)

**Ψευδοκώδικας**
```
add(ts, s):
    αν ts είναι null:
        επίστρεψε νέο πίνακα [s]
    nts ← νέος πίνακας μήκους ts.length + 1
    nts[0] ← s
    για i = 0 … ts.length − 1:
        nts[i+1] ← ts[i]                 // μετατόπιση κατά μία θέση δεξιά
    επίστρεψε nts
```

```java
public static String[] add(String[] ts, String s){
  if (ts == null) {
    ts = new String[1];
    ts[0] = s;
    return ts;}
  String[] nts = new String[ts.length+1];
  nts[0] = s;
  for (int i = 0; i < ts.length; i++){
     nts[i+1] = ts[i];
  }
  return nts;
}
```

![[Πίνακες String - add.png|800]]

> [!important] Τρία πράγματα που πρέπει να προσέξεις
> 1. Το νέο στοιχείο μπαίνει στη θέση **0**: η σειρά των στοιχείων είναι η **αντίστροφη** της σειράς προσθήκης.
> 2. Η κλήση χρειάζεται **ανάθεση**: `tab = add(tab, s);`. Σκέτο `add(tab, s);` δεν αλλάζει τίποτα (ο νέος πίνακας χάνεται).
> 3. Μέσα στην `add`, το `ts = new String[1];` αλλάζει μόνο την **τοπική** παράμετρο. Γι' αυτό η μέθοδος **επιστρέφει** τον νέο πίνακα: ο καλών δεν θα τον έβλεπε αλλιώς ([[03 - Πίνακες ως Αναφορές και Μέθοδοι#4. Πίνακες ως παράμετροι και τιμές επιστροφής (IV-26 … IV-31)|IV – 03 §4]]).

## 3. `remove` και `select`: φιλτράρισμα (VI-32, VI-33)

```java
public static String[] remove(String[] ts, String s){
   String[] nts = null;
   for (String s2 : ts){
    if (!s2.contains(s)) nts = add(nts, s2);
   }
   return nts;
}

public static String[] select(String[] ts, String s){
  String[] nts = null;
  for (String s2 : ts){
   if (s2.contains(s)) nts = add(nts, s2);
  }
  return nts;
}
```

| Μέθοδος | Κρατά τα στοιχεία που… | Αρχικός πίνακας |
|---|---|---|
| `select(ts, s)` | **περιέχουν** το `s` | ανέγγιχτος |
| `remove(ts, s)` | **δεν** περιέχουν το `s` | ανέγγιχτος |

> [!warning] Παγίδες
> - «Περιέχει» = `contains`: **υπο**συμβολοσειρά, με διάκριση πεζών/κεφαλαίων. Το `select(tab, "null")` βρίσκει και τη γραμμή `display(nullLines);`.
> - Αν **κανένα** στοιχείο δεν ταιριάζει, επιστρέφεται **`null`**, όχι κενός πίνακας.
> - Με `ts == null` (π.χ. κενή είσοδος) ο `for (String s2 : ts)` δίνει **`NullPointerException`**.
> - `remove(tab, "")` → **`null`**: το `""` περιέχεται σε **κάθε** string, άρα αφαιρούνται όλα (ελέγχθηκε).
> - Επειδή χρησιμοποιούν την `add`, **αντιστρέφουν** τη σειρά (§5).

## 4. `display` και `reverse` (VI-33)

```java
public static void display (String[] ts){
  for (String s : ts) System.out.println(s);
}

public static void reverse (String[] ts){
  for (int i=0, j=ts.length-1; i < j; i++, j--){
    String s = ts[i]; ts[i] = ts[j]; ts[j] = s;
  }
}
```

> [!note] Ο βρόχος με δύο μεταβλητές
> `for (int i=0, j=ts.length-1; i < j; i++, j--)`: το κόμμα επιτρέπει **δύο** αρχικοποιήσεις και **δύο** ενημερώσεις. Το `i` ανεβαίνει από την αρχή, το `j` κατεβαίνει από το τέλος, και σταματούν όταν συναντηθούν. Ίδιο αποτέλεσμα με το `for (i = 0; i < N/2; i++)` swap `ts[i]`, `ts[N-1-i]` ([[02 - Βασική Επεξεργασία Πινάκων|IV – 02]]).

| Κλήση | Αποτέλεσμα |
|---|---|
| `reverse` σε πίνακα μήκους 0 ή 1 | τίποτα (`i < j` ψευδές από την αρχή) |
| `reverse` με `i <= j` | σωστό ακόμα: απλώς ανταλλάσσει το μεσαίο με τον εαυτό του |
| `reverse` με `j = ts.length` | ✗ `ArrayIndexOutOfBoundsException` |
| `display(null)`, `reverse(null)` | ✗ `NullPointerException` |

> [!tip] Δύο διαφορετικές διεπαφές στην ίδια βιβλιοθήκη
> `add`/`select`/`remove` **επιστρέφουν νέο** πίνακα (`String[] f(...)`), ενώ η `reverse` **αλλάζει** αυτόν που της δίνουμε (`void f(String[] ts)`). Η `reverse` μπορεί να είναι `void` επειδή αλλάζει **στοιχεία** του κοινού πίνακα· η `add` δεν μπορεί, επειδή χρειάζεται **μεγαλύτερο** πίνακα. Ίδια διάκριση με τις δύο εκδοχές της `createDeck` στο [[03 - Πίνακες ως Αναφορές και Μέθοδοι|IV – 03]].

## 5. Το κύριο πρόγραμμα (VI-34, VI-35)

```java
public static void main(String[] args){
  String[] tab = null;
  while (!StdIn.isEmpty()){
     tab = add(tab, StdIn.readLine());
  }
  String[] nullLines = select(tab, "null");
  String[] returnLines = select(tab, "return");
  display(nullLines);
  System.out.println();
  display(returnLines);
}
```

Το πρόγραμμα διαβάζει τον **δικό του** πηγαίο κώδικα και τυπώνει τις γραμμές που περιέχουν `null`, μια κενή γραμμή, και τις γραμμές που περιέχουν `return`:

> [!important] Γιατί οι γραμμές βγαίνουν με τη **σωστή** σειρά
> Η `add` βάζει κάθε στοιχείο **μπροστά**, άρα ο `tab` κρατά το αρχείο **ανάποδα**. Η `select` σαρώνει τον ανάποδο `tab` και κάνει **πάλι** `add` (μπροστά), οπότε αντιστρέφει **ξανά**. Δύο αντιστροφές = αρχική σειρά.
>
> ![[Πίνακες String - Διπλή Αντιστροφή.png|800]]
>
> Ο ίδιος ο `tab` όμως **μένει** ανάποδος: `display(tab)` θα τύπωνε το αρχείο από την τελευταία γραμμή προς την πρώτη. Για τη σωστή σειρά: `reverse(tab); display(tab);`.

> [!note] Παρατηρήσεις στην έξοδο
> - Η **στοίχιση** (κενά στην αρχή) διατηρείται: η `readLine()` επιστρέφει ολόκληρη τη γραμμή.
> - Η `display(nullLines);` εμφανίζεται στις «null» γραμμές επειδή το `nullLines` **περιέχει** `null`. Το ίδιο για το `display(returnLines);` στις «return».
> - Η γραμμή `if (ts == null) {` βγαίνει πρώτη: είναι η πρώτη γραμμή του αρχείου που περιέχει `null`.

> [!example]- ➕ Κόστος και η «σωστή» λύση στη Java
> Κάθε `add` δημιουργεί νέο πίνακα και αντιγράφει **όλα** τα προηγούμενα στοιχεία. Για N γραμμές: 0 + 1 + … + (N−1) ≈ **N²/2** αντιγραφές. Για 10.000 γραμμές αυτό είναι ~50 εκατομμύρια αντιγραφές.
> Η βιβλιοθήκη της Java έχει τη δομή `ArrayList<String>`, που μεγαλώνει **διπλασιάζοντας** τον εσωτερικό πίνακα, οπότε το συνολικό κόστος είναι ανάλογο του N. Θα τη δεις στα επόμενα μαθήματα.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - `add(tab, s);` χωρίς `tab = …`.
> - Περιμένεις ο `tab` να έχει τις γραμμές με τη σειρά του αρχείου.
> - `display(select(tab, "x"))` όταν καμία γραμμή δεν περιέχει `"x"` → `NullPointerException`. Προστασία: `if (ts == null) return;` στην αρχή της `display`.
> - Σύγχυση `select` (κρατά όσα **περιέχουν**) με `remove` (κρατά όσα **δεν** περιέχουν).
> - `s2 == s` αντί για `s2.contains(s)` ή `s2.equals(s)` – διαφορετικά πράγματα όλα.
