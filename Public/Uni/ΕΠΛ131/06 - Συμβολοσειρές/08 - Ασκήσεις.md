> `152` και `195c`. Στο `' ' + c` και στο `'a' + 'b'` κανένας τελεστέος δεν είναι `String`, άρα γίνεται **αριθμητική** πρόσθεση κωδικών (32 + 120, 97 + 98). Διορθώσεις: `s += " " + c;` και `"" + 'a' + 'b' + "c"` (ή `"ab" + "c"`).

### Άσκηση 27

Γράψε με τη `pyrRow` (α) `invPyr(h, c)` – ανεστραμμένη πυραμίδα, (β) `diamond(h, c)` – ρόμβος (πυραμίδα ύψους `h` και από κάτω ανεστραμμένη χωρίς τη μεγάλη γραμμή δεύτερη φορά).

> [!success]- Λύση
> ```java
> public static String invPyr(int h, char c) {
>     String s = "";
>     for (int r = h; r >= 1; r--) s += pyrRow(h, r, c) + "\n";
>     return s;
> }
>
> public static String diamond(int h, char c) {
>     String s = "";
>     for (int r = 1; r <= h; r++)     s += pyrRow(h, r, c) + "\n";
>     for (int r = h - 1; r >= 1; r--) s += pyrRow(h, r, c) + "\n";   // h−1: η βάση μία φορά
>     return s;
> }
> ```
> `diamond(3, 'o')`:
> ```
>   o
>  ooo
> ooooo
>  ooo
>   o
> ```
> Καμία αλλαγή στις `line`/`pyrRow`: αυτό είναι η επαναχρησιμοποίηση της VI-28.

### Άσκηση 28

Γράψε `twoPyr(h1, h2, c)` που τυπώνει δύο πυραμίδες διαφορετικού ύψους **δίπλα-δίπλα**, με τις βάσεις στην **ίδια** γραμμή. Π.χ. `twoPyr(2, 3, 'x')`:
```
     x
 x  xxx
xxxxxxxx
```

> [!success]- Λύση
> Η πιο κοντή πυραμίδα «ξεκινά» `H − h` γραμμές πιο κάτω (`H` = το μεγαλύτερο ύψος). Πριν από αυτό γεμίζουμε το πλάτος της (`2h − 1`) με κενά:
> ```java
> public static String twoPyr(int h1, int h2, char c) {
>     int H = Math.max(h1, h2);
>     String s = "";
>     for (int r = 1; r <= H; r++) {
>         String left  = (r > H - h1) ? pyrRow(h1, r - (H - h1), c) : line(2*h1 - 1, ' ');
>         String right = (r > H - h2) ? pyrRow(h2, r - (H - h2), c) : line(2*h2 - 1, ' ');
>         s += left + right + "\n";
>     }
>     return s;
> }
> ```
> Δουλεύει **μόνο** επειδή η `pyrRow` βάζει κενά και δεξιά (σταθερό πλάτος). Με τη μη αρθρωτή εκδοχή της VI-29 θα έπρεπε να γραφτεί από την αρχή – η απάντηση στην ερώτηση της VI-31.

### Άσκηση 31

Τι επιστρέφει το `remove(tab, "")`; Και γιατί η έξοδος της VI-35 εμφανίζει τις γραμμές με τη σειρά του αρχείου, παρόλο που η `add` αντιστρέφει;

### Άσκηση 32

Γράψε (α) `addLast(ts, s)` που προσθέτει στο **τέλος** (ώστε ο `tab` να κρατά τη σειρά του αρχείου) και (β) `count(ts, s)` που μετρά τα στοιχεία που περιέχουν το `s` (με `0` για `ts == null`).

> [!success]- Λύση
> ```java
> public static String[] addLast(String[] ts, String s) {
>     if (ts == null) return new String[] {s};
>     String[] nts = new String[ts.length + 1];
>     for (int i = 0; i < ts.length; i++) nts[i] = ts[i];   // ίδια θέση, όχι i+1
>     nts[ts.length] = s;                                     // η νέα, τελευταία θέση
>     return nts;
> }
>
> public static int count(String[] ts, String s) {
>     if (ts == null) return 0;
>     int n = 0;
>     for (String s2 : ts) if (s2.contains(s)) n++;
>     return n;
> }
> ```
> Με `addLast` για `"x"`, `"y"`, `"z"` → `{"x", "y", "z"}`. Αν όμως η `select` συνεχίσει να χρησιμοποιεί την `add`, η έξοδός της θα βγαίνει πλέον **ανάποδα**: πρέπει να αλλάξουν και οι δύο μαζί.

### Άσκηση 33

Στη `reverse` της VI-33, τι γίνεται αν η συνθήκη γίνει (α) `i <= j` (β) `i < j` αλλά με `j = ts.length`; Τι κάνει η `reverse` σε πίνακα μήκους 1;

> [!success]- Λύση
> (α) Σωστό αποτέλεσμα: σε περιττό μήκος γίνεται μία επιπλέον «ανταλλαγή» του μεσαίου με τον εαυτό του (`{"a","b","c"}` → `{"c","b","a"}`).
