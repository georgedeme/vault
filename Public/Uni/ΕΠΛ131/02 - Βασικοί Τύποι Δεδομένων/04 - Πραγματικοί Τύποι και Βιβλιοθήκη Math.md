# 04 - Πραγματικοί Τύποι και Βιβλιοθήκη Math

Οι τύποι `float` και `double`, πώς γράφονται οι τιμές τους, πώς αναπαριστούνται εσωτερικά και η βιβλιοθήκη `Math` (διαφάνειες II-15 … II-24).

## 1. Δύο τύποι για πραγματικούς αριθμούς (II-15)

| Τύπος | Μέγεθος | Τυπικό πεδίο τιμών | Δεκαδικά ψηφία ακρίβειας |
|---|---|---|---|
| `float` | 4 bytes | 10⁻³⁷ … 10³⁸ | 6 |
| `double` | 8 bytes | 10⁻³⁰⁷ … 10³⁰⁸ | 15 |

> [!note] `float` – κινητής υποδιαστολής μονής ακρίβειας (II-16)
> - Αναπαριστά τους πραγματικούς αριθμούς · μέγεθος 4 bytes.
> - Πράξεις: `+`, `-`, `*`, `/`, κτλ.
> - **Εκθετική σημειογραφία** για κυριολεκτικές τιμές:
>   - `1258000.0 = 1.258 × 10⁶ = 1.258e6 = 1.258E6`
>   - `0.00089 = 8.9 × 10⁻⁴ = 8.9e-4`

> [!note] `double` – κινητής υποδιαστολής διπλής ακρίβειας (II-18)
> Ίδιος τύπος με το `float` αλλά με **μεγαλύτερη ακρίβεια** · μέγεθος 8 bytes. Είναι ο τύπος που χρησιμοποιούμε **πάντα** στην πράξη.

> [!warning] Κάθε πραγματικό κυριολεκτικό είναι `double` ➕
> `float f = 1.5;` ✗ compile error (lossy conversion από `double`). Σωστά: `float f = 1.5f;`
> Γι' αυτό στο μάθημα χρησιμοποιούμε σχεδόν μόνο `double`.

## 2. Ορθές και λανθασμένες τιμές (II-17)

| Ορθές Τιμές | Ισοδύναμο | | Λανθασμένες Τιμές | Γιατί ✗ |
|---|---|---|---|---|
| `3.14159` | | | `.12345e` | λείπει ο εκθέτης μετά το `e` |
| `0.005` | | | `15e-0.3` | ο εκθέτης πρέπει να είναι **ακέραιος** |
| `12345.0` | | | `12.5e.3` | ο εκθέτης πρέπει να είναι ακέραιος |
| `15.0e-04` | 0.0015 | | `34,500.99` | δεν επιτρέπεται **κόμμα** |
| `2.345e2` | 234.5 | | | |
| `1.15e-3` | 0.00115 | | | |
| `12e+5` | 1200000 | | | |

➕ Επίσης ορθά στη Java: `.5` (= 0.5), `5.` (= 5.0), `1e3` (= 1000.0, **`double`** παρόλο που «μοιάζει» ακέραιο).

> [!note] Υπερφόρτωση (overloading) (II-17)
> Το ίδιο σύμβολο έχει **διαφορετικές ερμηνείες σε διαφορετικά συμφραζόμενα**, π.χ. τα `*`, `/`, `-`, `+`:
> - `5 / 3` → ακέραια διαίρεση → `1`
> - `5.0 / 3.0` → πραγματική διαίρεση → `1.6666666666666667`
> - `"5" + 3` → συνένωση → `"53"`

## 3. Πράξεις με `double` (II-19)

| Έκφραση | Τιμή |
|---|---|
| `3.141 + .03` | `3.171` |
| `3.141 - .03` | `3.111` |
| `6.02e23 / 2` | `3.01e23` |
| `5.0 / 3.0` | `1.6666666666666667` |
| `10.0 % 3.141` | `0.577` |
| `1.0 / 0.0` | `Infinity` |
| `Math.sqrt(2.0)` | `1.4142135623730951` |
| `Math.sqrt(-1.0)` | `NaN` |

> [!important] `int` vs `double` σε «αδύνατες» πράξεις
>
> | Πράξη | `int` | `double` |
> |---|---|---|
> | `x / 0` | ✗ `ArithmeticException` (runtime) | `Infinity` ή `-Infinity` |
> | `0 / 0` | ✗ `ArithmeticException` | `NaN` (0.0/0.0) |
> | `x % 0` | ✗ `ArithmeticException` | `NaN` |
> | Υπερχείλιση | «τυλίγεται» σε αρνητικό | `Infinity` |
>
> Το `%` δουλεύει και σε `double` (`10.0 % 3.141`) – κάτι που δεν έχουν όλες οι γλώσσες.

> [!warning] Το `NaN` δεν ισούται με τίποτα – ούτε με τον εαυτό του ➕
> `Math.sqrt(-1) == Math.sqrt(-1)` → **`false`**. Για έλεγχο: `Double.isNaN(x)`.

## 4. Εσωτερική αναπαράσταση (II-23, II-24)

| Μορφή | Τι αποθηκεύεται |
|---|---|
| `int` | δυαδικός αριθμός – π.χ. το 13 αναπαριστάται ως `01101` |
| `double` | **mantissa** και **εκθέτης** |

> [!note] Μορφή κινητής υποδιαστολής (floating-point format)
> - Ανάλογη της **επιστημονικής σημειογραφίας**.
> - Η **mantissa** είναι ένας δυαδικός κλασματικός αριθμός από **0.5 μέχρι 1.0** για θετικούς (και από −0.5 μέχρι −1.0 για αρνητικούς).
> - Ο **εκθέτης** είναι ακέραιος.
> - **πραγματικός αριθμός = mantissa × 2^εκθέτης**
>
> Συνέπειες: οι τιμές `double` μπορούν να έχουν δεκαδικά, ενώ του `int` όχι· το πεδίο τιμών του `double` είναι **πολύ μεγαλύτερο** από του `int`· τα ακριβή πεδία διαφέρουν από υλοποίηση σε υλοποίηση.

> [!info]- ⚠️ Σημείωση: το μοντέλο των διαφανειών vs IEEE 754
> Οι διαφάνειες χρησιμοποιούν το «διδακτικό» μοντέλο με mantissa στο [0.5, 1). Η Java στην πράξη ακολουθεί το πρότυπο **IEEE 754**, όπου η mantissa κανονικοποιείται στη μορφή `1.xxx…` (δηλ. στο [1, 2)) και ο εκθέτης μετατοπίζεται κατά 1. Είναι **η ίδια ιδέα** – απλά άλλη σύμβαση. Στις εξετάσεις απάντα με το μοντέλο των διαφανειών.
> Επίσης το πεδίο τιμών του `double` στη Java είναι σταθερό (±1.8 × 10³⁰⁸), δεν «διαφέρει από υλοποίηση σε υλοποίηση» όπως σε C.

## 5. Η βιβλιοθήκη `Math` (II-20)

| Μέθοδος | Επιστρέφει | Περιγραφή |
|---|---|---|
| `Math.abs(a)` | ίδιο τύπο με το `a` | απόλυτη τιμή |
| `Math.max(a, b)` / `Math.min(a, b)` | ίδιο τύπο | μέγιστο / ελάχιστο |
| `Math.sin(θ)` `Math.cos(θ)` `Math.tan(θ)` | `double` | τριγωνομετρικές (γωνία σε **ακτίνια**) |
| `Math.asin` `Math.acos` `Math.atan` | `double` | αντίστροφες |
| `Math.toDegrees(r)` / `Math.toRadians(d)` | `double` | μετατροπή γωνιών |
| `Math.exp(a)` | `double` | eᵃ |
| `Math.log(a)` | `double` | **φυσικός** λογάριθμος ln a |
| `Math.pow(a, b)` | `double` | aᵇ |
| `Math.round(a)` | **`long`** | στρογγυλοποίηση στον πλησιέστερο ακέραιο |
| `Math.random()` | `double` | τυχαίος αριθμός στο **[0, 1)** |
| `Math.sqrt(a)` | `double` | τετραγωνική ρίζα |
| `Math.E`, `Math.PI` | `double` | οι σταθερές e και π (**χωρίς** παρενθέσεις) |

➕ Επίσης χρήσιμα: `Math.floor(a)` (προς τα κάτω), `Math.ceil(a)` (προς τα πάνω) – επιστρέφουν **`double`**· `Math.log10(a)`.

> [!warning] Παγίδες της `Math`
> - **Δεν υπάρχει τελεστής δύναμης.** Το `2 ^ 3` **δεν** είναι 8 – βλ. [[07 - Αποτίμηση Εκφράσεων]]. Χρησιμοποίησε `Math.pow(2, 3)` → `8.0` (**double**!).
> - `int x = Math.pow(2, 3);` ✗ compile (double → int). Θέλει `(int) Math.pow(2, 3)`.
> - `int r = Math.round(2.7);` ✗ compile – το `round(double)` επιστρέφει **`long`**. Θέλει `(int) Math.round(2.7)`.
> - `Math.round(2.5)` → `3`, αλλά `Math.round(-2.5)` → **`-2`** (στρογγυλοποιεί «προς τα πάνω» στο .5).
> - `Math.log` είναι ln, όχι log₁₀.
> - `Math.random()` **ποτέ** δεν επιστρέφει 1.0 (αλλά μπορεί 0.0).
> - `Math.PI()` ✗ – είναι σταθερά, όχι μέθοδος.

## 6. Παράδειγμα: Ρίζες δευτεροβάθμιας εξίσωσης (II-21)

Για `x² + bx + c = 0`: ρίζες = (−b ± √(b² − 4c)) / 2

**Σχέδιο λύσης (ψευδοκώδικας):**
```
read from input b and c
rdiscr = (b² – 4c)^0.5
x1 = (-b + rdiscr) / 2
x2 = (-b - rdiscr) / 2
print x1 and x2
```

```java
public class Quadratic {
    public static void main(String[] args) {
        // parse coefficients from command-line
        double b = Double.parseDouble(args[0]);
        double c = Double.parseDouble(args[1]);

        // calculate roots
        double discriminant = b*b - 4.0*c;
        double d = Math.sqrt(discriminant);
        double root1 = (-b + d) / 2.0;
        double root2 = (-b - d) / 2.0;

        // print them out
        System.out.println(root1);
        System.out.println(root2);
    }
}
```

### Δοκιμή προγράμματος (II-22)

> [!important] Η δοκιμή περιλαμβάνει **έγκυρες και μη έγκυρες** περιπτώσεις

| Εκτέλεση | Εξίσωση | Έξοδος | Σχόλιο |
|---|---|---|---|
| `java Quadratic -3.0 2.0` | x² − 3x + 2 | `2.0` `1.0` | κανονική περίπτωση |
| `java Quadratic -1.0 -1.0` | x² − x − 1 | `1.618033988749895` `-0.6180339887498949` | χρυσή τομή |
| `java Quadratic 1.0 1.0` | x² + x + 1 | `NaN` `NaN` | αρνητική διακρίνουσα → `sqrt` αρνητικού |
| `java Quadratic 1.0 hello` | | `NumberFormatException: hello` | μη αριθμητική είσοδος |
| `java Quadratic 1.0` | | `ArrayIndexOutOfBoundsException` | λείπει όρισμα |

> [!tip] Τι θα βελτίωνες;
> Έλεγχος `if (discriminant < 0)` πριν το `sqrt` (→ Ενότητα III), και έλεγχος `args.length`. Επίσης το πρόγραμμα λύνει μόνο εξισώσεις με a = 1.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - `double x = 1 / 2;` → `0.0`, όχι `0.5` (η διαίρεση γίνεται σε `int` πρώτα).
> - Σύγκριση πραγματικών με `==` → βλ. [[09 - Ανακρίβειες Αναπαράστασης]].
> - `Math.sqrt` αρνητικού δεν «σκάει» – επιστρέφει σιωπηλά `NaN`, που «μολύνει» κάθε επόμενο υπολογισμό.
> - Γωνίες σε μοίρες στο `Math.sin(90)` → θέλει `Math.sin(Math.toRadians(90))`.
