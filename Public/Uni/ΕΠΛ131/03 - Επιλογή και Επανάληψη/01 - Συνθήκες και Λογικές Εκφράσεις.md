# 01 - Συνθήκες και Λογικές Εκφράσεις

Τι είναι συνθήκη, πώς αποτιμάται μια λογική έκφραση (short-circuit), με ποια σειρά γράφουμε τις συνθήκες, και πώς τις αρνούμαστε σωστά (διαφάνειες III-3 … III-13).

## 1. Συνθήκη

> [!note] Συνθήκη – Condition (III-3)
> Μία έκφραση η οποία είναι **είτε αληθής (`true`) είτε ψευδής (`false`)** – δηλαδή μία **λογική έκφραση** (τύπου `boolean`).

> [!warning] Προσοχή: Δοκιμή για ισότητα ανάμεσα σε πραγματικούς αριθμούς
> ```java
> 1.29999 == 1.2999                       // ⇒ false
> Math.abs(1.29999 - 1.2999) < 0.0001     // ⇒ true
> ```
> Εξαιτίας των λαθών αναπαράστασης, οι πραγματικοί συγκρίνονται **με ανοχή**: `Math.abs(a - b) < EPSILON`. Βλ. [[09 - Ανακρίβειες Αναπαράστασης|II – 09 Ανακρίβειες]].

## 2. Αποτίμηση λογικών εκφράσεων – short-circuit (III-4)

> [!important] Κανόνας αποτίμησης (short-circuit evaluation)
> Η αποτίμηση αρχίζει **από τα αριστερά** και προχωρεί **μόνο μέχρι το σημείο που χρειάζεται**:
> - `false && E` ⇒ `false` — η αποτίμηση της `E` **δεν χρειάζεται**
> - `true || E` ⇒ `true` — η αποτίμηση της `E` **δεν χρειάζεται**

### Σειρά συνθηκών σε μία λογική έκφραση (III-5, III-6)

Ο κανόνας είναι κυρίως για λόγους **αποδοτικότητας**, αλλά έχει και μεγάλη χρησιμότητα για τη **σειρά** των συνθηκών:

```java
(y % x) > 2 && x != 0     // ✗ αν x == 0 → ArithmeticException (διαίρεση με 0)
x != 0 && (y % x) > 2     // ✓ αν x == 0, το (y % x) > 2 ΔΕΝ αποτιμάται
```

> [!important] Ο γενικός κανόνας
> - Σε μία **σύζευξη** `E1 && E2`: η `E1` μπαίνει **αριστερά** αν, όταν είναι `false`, η αποτίμηση της `E2` θα οδηγούσε σε πρόβλημα.
> - Σε μία **διάζευξη** `E1 || E2`: η `E1` μπαίνει **αριστερά** αν, όταν είναι `true`, η αποτίμηση της `E2` θα οδηγούσε σε πρόβλημα.
>
> Με αυτή τη σειρά **αποτρέπεται** η αποτίμηση της `E2`. Η συνθήκη-«φρουρός» (guard) πάει πάντα **πρώτη**.

> [!example]- Φρουροί που θα δεις ξανά
> | Φρουρός πρώτα | Προστατεύει από |
> |---|---|
> | `x != 0 && y % x > 2` | διαίρεση με 0 |
> | `pos < x.length && x[pos] != item` | `ArrayIndexOutOfBoundsException` (γραμμική αναζήτηση, IV-53) |
> | `args.length > 0 && args[0].equals("-v")` | ανύπαρκτο όρισμα |
> | `x == 0 \|\| y / x > 1` | διαίρεση με 0 (στη διάζευξη ο φρουρός είναι «αληθές ⇒ σταμάτα») |
> | `s != null && s.length() > 0` | `NullPointerException` ➕ |

### Εκμετάλλευση για αποδοτικότητα (III-7)

Ακόμη και όταν η σειρά θα μπορούσε να είναι οποιαδήποτε, ενδείκνυται να γίνεται εκμετάλλευση του κανόνα για **μείωση του υπολογιστικού κόστους**.

> [!example]- Το παράδειγμα της διαφάνειας
> Έστω `E1 && E2` όπου η `E1` είναι πολύ ακριβή και η `E2` πολύ φθηνή, με `E1 = true` και `E2 = false`.
> - `E1 && E2`: αποτιμάται **και** η ακριβή `E1` (true) **και** η `E2`.
> - `E2 && E1`: η φθηνή `E2` είναι `false` → η ακριβή `E1` **δεν** αποτιμάται.
>
> **Ορθή πρακτική:** αριστερά μπαίνει η συνθήκη της οποίας η αποτίμηση κοστίζει **λιγότερο** (εφόσον δεν παραβιάζεται κάποιος φρουρός).

> [!warning] Short-circuit και παρενέργειες ➕
> ```java
> int i = 0;
> if (false && ++i > 0) { }    // το ++i ΔΕΝ εκτελείται → i == 0
> if (true  || ++i > 0) { }    // ούτε εδώ → i == 0
> if (false &  ++i > 0) { }    // με & εκτελείται → i == 1
> ```
> Μην βάζεις `++`, αναθέσεις ή κλήσεις με παρενέργειες στη **δεξιά** πλευρά `&&`/`||` – μπορεί να μην εκτελεστούν.

## 3. Προτεραιότητες (III-8)

> [!important] Από την υψηλότερη στη χαμηλότερη
>
> | Προτεραιότητα | Τελεστές |
> |---|---|
> | 1 (υψηλότερη) | κλήσεις μεθόδων |
> | 2 | `!` `+` `-` (μοναδιαίοι τελεστές) ➕ και `++` `--`, cast |
> | 3 | `*` `/` `%` |
> | 4 | `+` `-` |
> | 5 | `<` `<=` `>=` `>` |
> | 6 | `==` `!=` |
> | 7 | `&&` |
> | 8 | `\|\|` |
> | 9 (χαμηλότερη) | `=` ➕ και `+=`, `-=`, … |

Συνέπειες:
- `x + 1 > y * 2` = `(x + 1) > (y * 2)` – η αριθμητική πριν τη σύγκριση.
- `a < b == c < d` = `(a < b) == (c < d)`.
- **`a || b && c`** = `a || (b && c)` – το `&&` δένει πιο σφιχτά (όπως ∧ πριν ∨ στο ΕΠΛ111).
- `n % 2 == 0` = `(n % 2) == 0` (οι παρενθέσεις είναι περιττές αλλά βοηθούν).

> [!warning] Παγίδες προτεραιότητας ➕
> - **`!x > 5`** με `int x` ✗ compile: το `!` εφαρμόζεται πρώτο στο `x` (int). Σωστά: `!(x > 5)` ή `x <= 5`.
> - **`x > 0 && < 10`** ✗ – κάθε σύγκριση θέλει δύο τελεστέους: `x > 0 && x < 10`.
> - **`x == 1 || 2`** ✗ – σωστά `x == 1 || x == 2`.

## 4. Σύγκριση χαρακτήρων (III-9)

Οι σχεσιακοί τελεστές εφαρμόζονται σε χαρακτήρες – συγκρίνονται οι **κωδικοί** τους:

| Έκφραση | Τιμή | Γιατί |
|---|---|---|
| `'9' >= '0'` | `true` | 57 ≥ 48 |
| `'a' < 'e'` | `true` | 97 < 101 |
| `'B' <= 'A'` | `false` | 66 > 65 |
| `'Z' == 'z'` | `false` | 90 ≠ 122 – κεφαλαία ≠ μικρά |
| `'a' <= 'A'` | `false` | τα κεφαλαία **προηγούνται** |

## 5. Ανάθεση λογικών τιμών (III-10)

```java
boolean even, odd;
even = (n % 2 == 0);        // ή  even = n % 2 == 0;
odd = !even;

boolean is_lower, is_upper, is_letter, white_space;
char ch = '!';
is_lower    = 'a' <= ch && ch <= 'z';
is_upper    = 'A' <= ch && ch <= 'Z';
is_letter   = is_lower || is_upper;
white_space = ch == '\n' || ch == ' ' || ch == '\t';
```

> [!tip] Αντί για `if (…) b = true; else b = false;` γράψε απευθείας `b = …;`. Είναι το ίδιο και πιο καθαρό.

## 6. Συμπλήρωμα συνθηκών – Complementing Conditions (III-11)

> [!note] Ορισμός
> Το **συμπλήρωμα** μίας συνθήκης είναι η **άρνησή** της.

| Συνθήκη | Συμπλήρωμα |
|---|---|
| `true` | `false` |
| `false` | `true` |
| `item == SENT` | `!(item == SENT)` ή `item != SENT` |
| `item > SENT` | `item <= SENT` |
| `(n % 2) == 0` | `(n % 2) != 0` |

> [!warning] Το συμπλήρωμα του `>` είναι `<=`, όχι `<`
> Ο «ξεχασμένος» ίσος είναι το πιο συχνό λάθος: `!(x > 5)` ≡ `x <= 5`.
>
> | Συνθήκη | Συμπλήρωμα |
> |---|---|
> | `<` | `>=` |
> | `<=` | `>` |
> | `>` | `<=` |
> | `>=` | `<` |
> | `==` | `!=` |

## 7. Κανόνες De Morgan (III-12)

> [!important] De Morgan
> - **`!(E1 && E2)` ≡ `!E1 || !E2`**
> - **`!(E1 || E2)` ≡ `!E1 && !E2`**
>
> Η άρνηση «μπαίνει μέσα» **και αλλάζει τον τελεστή** (`&&` ↔ `||`).

> [!example]- Απόδειξη με πίνακες αληθείας
>
> | E1 | E2 | E1 && E2 | !(E1 && E2) | !E1 | !E2 | !E1 \|\| !E2 |
> |---|---|---|---|---|---|---|
> | T | T | T | **F** | F | F | **F** |
> | T | F | F | **T** | F | T | **T** |
> | F | T | F | **T** | T | F | **T** |
> | F | F | F | **T** | T | T | **T** |
>
> | E1 | E2 | E1 \|\| E2 | !(E1 \|\| E2) | !E1 | !E2 | !E1 && !E2 |
> |---|---|---|---|---|---|---|
> | T | T | T | **F** | F | F | **F** |
> | T | F | T | **F** | F | T | **F** |
> | F | T | T | **F** | T | F | **F** |
> | F | F | F | **T** | T | T | **T** |
>
> Οι στήλες σε έντονα συμφωνούν ⇒ ισοδύναμες. (Ίδια απόδειξη με το [[Uni/ΕΠΛ111/ΕΠΛ111 Προτασιακή-Κατηγορική Λογική/03 - Ισοδυναμίες|ΕΠΛ111 – Ισοδυναμίες]].)

### Παραδείγματα (III-13)

**Παράδειγμα 1**

| Βήμα | Κανόνας |
|---|---|
| `!(age > 25 && (status == 'S' \|\| status == 'D'))` | αρχική |
| ≡ `!(age > 25) \|\| !(status == 'S' \|\| status == 'D')` | De Morgan (`&&`) |
| ≡ `age <= 25 \|\| (!(status == 'S') && !(status == 'D'))` | συμπλήρωμα, De Morgan (`\|\|`) |
| ≡ `age <= 25 \|\| (status != 'S' && status != 'D')` | συμπλήρωμα |

**Παράδειγμα 2 – «δεν είναι δίσεκτο»**

| Βήμα | Κανόνας |
|---|---|
| `!(year % 4 == 0 && (year % 100 != 0 \|\| year % 400 == 0))` | αρχική |
| ≡ `!(year % 4 == 0) \|\| !(year % 100 != 0 \|\| year % 400 == 0)` | De Morgan (`&&`) |
| ≡ `year % 4 != 0 \|\| !(year % 100 != 0) && !(year % 400 == 0)` | συμπλήρωμα, De Morgan (`\|\|`) |
| ≡ `year % 4 != 0 \|\| year % 100 == 0 && year % 400 != 0` | συμπλήρωμα |

> [!tip] Στο τελευταίο βήμα δεν χρειάζονται παρενθέσεις γύρω από το `year % 100 == 0 && year % 400 != 0`, επειδή το `&&` προηγείται του `||`. Βάλ' τες όμως για αναγνωσιμότητα.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - `==` σε `double`.
> - Φρουρός στη **λάθος** πλευρά: `x[pos] != item && pos < x.length`.
> - De Morgan χωρίς αλλαγή τελεστή: `!(a && b)` → ✗ `!a && !b`.
> - Συμπλήρωμα του `<` ως `>` (ξεχνάς το ίσο).
> - `!x > 5` αντί για `!(x > 5)`.
