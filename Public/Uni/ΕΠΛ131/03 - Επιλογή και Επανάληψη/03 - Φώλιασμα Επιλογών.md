# 03 - Φώλιασμα Επιλογών

Εντολές `if` μέσα σε άλλες `if` (nesting): πώς διαβάζονται, πώς «ισιώνουν» σε αλυσίδα `else if`, και οι παγίδες τους (διαφάνειες III-20 … III-35).

## 1. Τι σημαίνει ένα φώλιασμα; (III-21, III-22)

```java
if (x > y)
    if (x > z) res = x;
    else       res = z;
else
    if (y > z) res = y;
    else       res = z;
```

> [!example]- Διάγραμμα ροής και ερμηνεία
> ```
>                  x > y ?
>            όχι /         \ ναι
>          y > z ?         x > z ?
>        όχι/   \ναι     όχι/   \ναι
>     res=z   res=y    res=z   res=x
> ```
> Ο κώδικας βρίσκει το **μέγιστο** των `x`, `y`, `z`. Κάθε φύλλο του δέντρου αντιστοιχεί σε **ένα** μονοπάτι συνθηκών.

## 2. Γενικό φώλιασμα (III-23, III-24)

```java
if (C1)
    if (C2)
        if (C4) S1 else S2
    else
        if (C5) S3 else S4
else
    if (C3)
        if (C6) S5 else S6
    else
        if (C7) S7 else S8
```
Περίπλοκη λογική που κάνει τον κώδικα **δυσανάγνωστο**. Ισοδύναμη «επίπεδη» μορφή:

```java
if      ( C1 &&  C2 &&  C4) S1
else if ( C1 &&  C2 && !C4) S2
else if ( C1 && !C2 &&  C5) S3
else if ( C1 && !C2 && !C5) S4
else if (!C1 &&  C3 &&  C6) S5
else if (!C1 &&  C3 && !C6) S6
else if (!C1 && !C3 &&  C7) S7
else if (!C1 && !C3 && !C7) S8
```

> [!important] Το αντάλλαγμα
> - ✓ **Πιο διαφανής** λογική: κάθε κλάδος γράφει ρητά πότε εκτελείται.
> - ✗ Κάθε συνθήκη **αποτιμάται πολλαπλάσιο αριθμό φορών** (π.χ. η `C1` μέχρι και 8 φορές).
> - ✗ Αν μια συνθήκη έχει **παρενέργεια** ή αλλάζει τιμή στο μεταξύ, οι δύο μορφές **δεν** είναι ισοδύναμες.

## 3. Επαναφορά στο δίσεκτο έτος (III-25 … III-29)

**Φωλιασμένη μορφή:**
```java
if (year % 4 == 0)
    if (year % 100 == 0)
        if (year % 400 == 0) isLeapYear = true;
        else                 isLeapYear = false;
    else isLeapYear = true;
else isLeapYear = false;
```

```
            year % 4 == 0 ?
         όχι /           \ ναι
   isLeap=false     year % 100 == 0 ?
                  όχι /           \ ναι
            isLeap=true      year % 400 == 0 ?
                           όχι /           \ ναι
                     isLeap=false      isLeap=true
```

**Επίπεδη μορφή (III-29):**
```java
if      (year % 4 == 0 && year % 100 == 0 && year % 400 == 0) isLeapYear = true;
else if (year % 4 == 0 && year % 100 == 0 && year % 400 != 0) isLeapYear = false;
else if (year % 4 == 0 && year % 100 != 0)                    isLeapYear = true;
else if (year % 4 != 0)                                        isLeapYear = false;
```

> [!warning] Παρατήρηση ➕
> Στην επίπεδη μορφή οι 4 κλάδοι καλύπτουν όλες τις περιπτώσεις, αλλά ο compiler **δεν** το ξέρει: αν ακολουθούσε `System.out.println(isLeapYear);` με τοπική `isLeapYear` χωρίς αρχική τιμή, θα έβγαζε «might not have been initialized». Ο τελευταίος κλάδος συνήθως γράφεται σκέτο `else`.

## 4. Διακλάδωση μόνο στην κατεύθυνση του «όχι» – αλυσίδα `else if` (III-29, III-30)

> [!note] Αλυσίδα επιλογών
> Ο **πιο συνηθισμένος** τρόπος φωλιάσματος – απλά επειδή είναι ο πιο φυσικός – είναι όταν η διακλάδωση γίνεται **μόνο στην κατεύθυνση του όχι**. Έτσι υπάρχει μία **αλυσίδα** επιλογών:
> ```
> if (C1) S1
> else if (C2) S2
> else if (C3) S3
> . . .
> else if (Cn-1) Sn-1
> else Sn
> ```
> Εκτελείται η **πρώτη** `Si` της οποίας η `Ci` είναι αληθής· αν καμία, η `Sn`.

> [!important] Κλειδί: στο `else if` ξέρεις ήδη ότι όλες οι **προηγούμενες** συνθήκες ήταν ψευδείς
> Άρα **δεν** χρειάζεται να τις ξαναγράψεις.

### Παραδείγματα (III-31)

```java
// Μέγιστο τριών
if      (x > z && x > y) res = x;
else if (y > x && y > z) res = y;
else                     res = z;

// Δίσεκτο
if (year % 4 == 0 && year % 100 != 0) isLeapYear = true;
else if (year % 4 == 0 && year % 100 == 0 && year % 400 == 0) isLeapYear = true;
else isLeapYear = false;

// Βαθμολογία
if (weighted_aver >= 8.5) System.out.println("Excellent");
else if (weighted_aver < 8.5 && weighted_aver >= 6.5) System.out.println("Very Good");
else if (weighted_aver < 6.5 && weighted_aver > 5.0)  System.out.println("Good");
else System.out.println("Failure");
```

> [!warning] ⚠️ Σημείωση: το «μέγιστο τριών» έχει σφάλμα στις ισοπαλίες
> Με `x = 5, y = 5, z = 1`: η `x > y` είναι ψευδής **και** η `y > x` είναι ψευδής → `res = z = 1` ✗ (το μέγιστο είναι 5).
> Διόρθωση: `>=` αντί για `>` – `if (x >= y && x >= z) res = x; else if (y >= z) res = y; else res = z;`
> Η φωλιασμένη εκδοχή της §1 **δεν** έχει αυτό το πρόβλημα (δίνει 5). Καλό παράδειγμα γιατί πρέπει να δοκιμάζεις **οριακές** περιπτώσεις.

> [!tip] Βαθμολογία – τι θα βελτίωνες
> - Τα `weighted_aver < 8.5` και `weighted_aver < 6.5` είναι **περιττά**: αφού φτάσαμε στο `else if`, η προηγούμενη συνθήκη ήταν ψευδής. Αρκεί `else if (weighted_aver >= 6.5)` και `else if (weighted_aver > 5.0)`.
> - Προσοχή στο όριο: με `> 5.0` ο μέσος όρος **ακριβώς 5.0** βγαίνει `Failure`. Είναι αυτό που θέλουμε;
> - ⚠️ Στη διαφάνεια γράφεται `printnl` – typo, δεν κάνει compile· σωστά `println`.

## 5. Παράδειγμα: Φορολογικός συντελεστής (III-32)

| Εισόδημα | Φορολογικός συντελεστής |
|---|---|
| 0 – 47.449 | 22% |
| 47.450 – 114.649 | 25% |
| 114.650 – 174.699 | 28% |
| 174.700 – 311.949 | 33% |
| 311.950 – | 35% |

**5 αμοιβαία αποκλειόμενες επιλογές:**
```java
double rate;
if      (income <  47450) rate = 0.22;
else if (income < 114650) rate = 0.25;
else if (income < 174700) rate = 0.28;
else if (income < 311950) rate = 0.33;
else                      rate = 0.35;
```

### Είναι ορθή ή λάθος; (III-33)

```java
double rate = 0.35;
if (income <  47450) rate = 0.22;
if (income < 114650) rate = 0.25;
if (income < 174700) rate = 0.28;
if (income < 311950) rate = 0.33;
```

> [!success]- Απάντηση
> **Λάθος.** Τα `if` είναι **ανεξάρτητα** (όχι αλυσίδα), οπότε εκτελούνται **όλα**, και κερδίζει η **τελευταία** αληθής ανάθεση.
> Για `income = 10000`: όλες οι συνθήκες αληθείς → `rate = 0.33` ✗ (έπρεπε 0.22). Σωστό αποτέλεσμα δίνει μόνο για εισοδήματα ≥ 174.700.

### Είναι ορθή ή λάθος; (III-34)

```java
double rate = 0.35;
if (income < 311950) rate = 0.33;
if (income < 174700) rate = 0.28;
if (income < 114650) rate = 0.25;
if (income <  47450) rate = 0.22;
```

> [!success]- Απάντηση
> **Ορθή.** Οι συνθήκες είναι σε **φθίνουσα** σειρά ορίων, οπότε η τελευταία αληθής ανάθεση είναι πάντα η πιο «στενή» (σωστή) κατηγορία. Για `income = 10000` → `0.22` ✓.
> Είναι όμως **λιγότερο αποδοτική** (αποτιμώνται πάντα και οι 4 συνθήκες, και γίνονται περιττές αναθέσεις) και **λιγότερο σαφής** από την αλυσίδα `else if` – ο αναγνώστης πρέπει να σκεφτεί γιατί δουλεύει (*Don't make me think*, Ενότητα V).

## 6. Το κρεμάμενο `else` (dangling else) ➕

> [!important] Κανόνας
> Ένα `else` ανήκει **πάντα στο πλησιέστερο προηγούμενο `if` που δεν έχει ήδη `else`** – ανεξάρτητα από την εσοχή.

```java
if (q > 5)
    if (q > 20) System.out.println("A");
else                                   // ← παρά την εσοχή, ανήκει στο if (q > 20)!
    System.out.println("B");
```

| `q` | Έξοδος | Γιατί |
|---|---|---|
| 10 | `B` | `q > 5` ✓, `q > 20` ✗ → `else` του εσωτερικού |
| 3 | *(τίποτα)* | `q > 5` ✗ → το εξωτερικό `if` δεν έχει `else` |
| 25 | `A` | |

Αν ήθελες το `else` για το **εξωτερικό** `if`, χρειάζονται `{ }`:
```java
if (q > 5) {
    if (q > 20) System.out.println("A");
} else
    System.out.println("B");
```

## 7. Σύνοψη: Αλγοριθμική Δομή Επιλογής (III-35)

> [!important] Σύνοψη
> - Η δομή της επιλογής επιτρέπει την **ανταπόκριση σε διαφορετικές καταστάσεις** με ευέλικτο τρόπο.
> - Κανονικά μία εντολή επιλογής πρέπει να περιλαμβάνει δράσεις για **κάθε πιθανό ενδεχόμενο**, έστω και αν κάποια από αυτές είναι η «απραξία» (“do nothing”), όπως συχνά συμβαίνει.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Ανεξάρτητα `if` αντί για αλυσίδα `else if` όταν οι περιπτώσεις είναι αμοιβαία αποκλειόμενες.
> - Λάθος σειρά ορίων σε αλυσίδα: `if (x > 0) … else if (x > 10) …` → ο δεύτερος κλάδος **δεν εκτελείται ποτέ**.
> - `>` αντί για `>=` → ισοπαλίες/όρια πέφτουν σε λάθος κλάδο.
> - Κρεμάμενο `else` με παραπλανητική εσοχή.
> - Περιττή επανάληψη συνθηκών που ήδη ξέρεις ότι είναι ψευδείς.
