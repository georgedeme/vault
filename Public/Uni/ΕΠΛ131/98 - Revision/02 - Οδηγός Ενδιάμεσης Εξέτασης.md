# 02 - Οδηγός Ενδιάμεσης Εξέτασης

Πώς λύνεται κάθε είδος άσκησης των ενδιάμεσων του ΕΠΛ 131, με βάση τις δύο λυμένες ενδιάμεσες του φακέλου `99 - Material`: **Ενδιάμεση 1, 17/2/2023** (15 ερωτήσεις) και **Ενδιάμεση 2, 18/3/2022** (13 ερωτήσεις). Όλες οι απαντήσεις ελέγχθηκαν με `javac`/`java` 17. Όπου η επίσημη λύση έχει λάθος, σημειώνεται με **⚠️ Σημείωση**.

## 1. Η μορφή της εξέτασης

> [!note] Κανόνες (από το εξώφυλλο και των δύο)
> - **75 λεπτά**, **100 μονάδες**, απαντάς σε **όλες** τις ερωτήσεις.
> 1. Είναι απαραίτητο όπου χρειάζεται να **δείχνετε τρόπο σκέψης** στα ερωτήματα.
> 2. **Πολύπλοκες ορθές απαντήσεις θα βαθμολογούνται με 0.**
> 3. Δεν χρειάζεται να δείχνετε τρόπο σκέψης στα ερωτήματα **πολλαπλής επιλογής**.
> 4. Στα ερωτήματα πολλαπλής επιλογής **αφαιρούνται μονάδες για λάθος απαντήσεις**.

> [!important] Τι σημαίνουν στην πράξη
> - **≈ 5 λεπτά ανά ερώτηση.** Οι ερωτήσεις «τιμή έκφρασης» θέλουν 30 δευτερόλεπτα· κράτα τον χρόνο για τα προγράμματα.
> - **«Πολύπλοκες = 0»**: γράψε τη **μικρότερη** λύση που κάνει τη δουλειά – ένας βρόχος αντί για δύο, χωρίς πίνακα αν δεν χρειάζεται. Αν η εκφώνηση λέει «ένα for και ένα if», αυτό είναι το σχήμα της λύσης.
> - **Αρνητική βαθμολογία**: στην πολλαπλή επιλογή, αν δεν μπορείς να αποκλείσεις τουλάχιστον τις μισές επιλογές, σκέψου να την αφήσεις κενή.
> - Η ενδιάμεση της **27/10/2025** (VII-1) έρχεται μετά την Ενότητα VII: ύλη II–VII. Η 2023 κάλυπτε κυρίως II–III (+ `args`, `String`), η 2022 κυρίως πίνακες, μεθόδους, `StdIn` και αρχεία (`In`).

## Α. Τιμή έκφρασης

**Μέθοδος**
1. Γράψε πάνω από κάθε τελεστέο τον **τύπο** του (`int`, `double`, `String`, `char`).
2. Εφάρμοσε **προτεραιότητα**: cast και μοναδιαίοι › `* / %` › `+ -`. Ίδια προτεραιότητα → από **αριστερά**.
3. Σε κάθε πράξη: `int ∘ int` → `int` (η διαίρεση κόβει) · ένας `double` → `double` · ένας `String` στο `+` → **συνένωση**.
4. Γράψε το αποτέλεσμα **με τη μορφή του τύπου του**: `0.5` (double), `0` (int), `"x2"` (String), `0.0` αν είναι double μηδέν.

> [!example] 2023 Ε.2 και Ε.3 – `int x = 2; double y = 1.0;`
>
> | Έκφραση | Τύποι | Τιμή |
> |---|---|---|
> | `1/x` | `int / int` | **`0`** |
> | `1.0/x` | `double / int` | `0.5` |
> | `y/x` | `double / int` | `0.5` |
> | `((int) y)/x` | `int / int` | **`0`** – το cast γίνεται πρώτα |
> | `"x" + 2` | `String + int` | `"x2"` |

> [!tip] Παραλλαγές που μπορεί να πέσουν (ελέγχθηκαν)
> `(int) y / x` = `0` (το cast δένει πιο σφιχτά) · `(double) 1 / x` = `0.5` · `(double)(1 / x)` = `0.0` · `"x" + 2 + 3` = `"x23"` · `2 + 3 + "x"` = `"5x"` · `'x' + 2` = `122` · `"" + 'x' + 2` = `"x2"` · `x / 2 * 2.0` = `2.0` · `7 % 3 * 2` = `2`.

## Β. Ίχνος κώδικα – τι τυπώνει / ποια τιμή

**Μέθοδος**
1. **Μέτρα τις επαναλήψεις πριν ξεκινήσεις**: αρχική τιμή, συνθήκη, βήμα. `i = 1; i <= 10; i += 2` → 1, 3, 5, 7, 9 = 5.
2. Φτιάξε **πίνακα ίχνους**: μία στήλη ανά μεταβλητή, μία γραμμή ανά αλλαγή.
3. Ψάξε αν η αλλαγή ανά επανάληψη είναι **σταθερή** – τότε πολλαπλασίασε (2022 Ε.1: +9 ανά εξωτερική).
4. Κοίτα **τι εκτελείται μία φορά**: `;` αμέσως μετά το `for (…)`/`while (…)`, εντολή χωρίς `{}` μετά τον βρόχο.
5. Στην πολλαπλή επιλογή, αν η απάντησή σου δεν είναι στις επιλογές → ξανακοίτα όρια και `;`. Υπάρχει σχεδόν πάντα «Καμία από τις πιο πάνω».

![[Ενδιάμεση - Πίνακας Ίχνους.png|800]]

> [!example] 2023 Ε.6 – φωλιασμένα `if`
> ```java
> int x = 5;
> int y = 11;
> if (x>y || y<0)
>      y = 0;
> else if (y> 2*x)
>      y = y/2;
>    else
>      y = x;
> ```
> `5 > 11` ψευδές, `11 < 0` ψευδές → `else if`: `11 > 10` αληθές → `y = 11/2 = 5` (ακέραια). Το τελευταίο `else` δεν εκτελείται. **`x = 5`, `y = 5`** – η ίδια τιμή για άλλο λόγο από αυτόν που «φαίνεται» (`y = x`).

> [!example] 2023 Ε.7, Ε.8 – πίνακας ίχνους
> ```java
> int x = 0;
> for (int i=0; i<N; i++)
>      x += N;
> ```
>
> | `x` | `i` | `N` |
> |---|---|---|
> | 0 | 0 | 5 |
> | 5 | 1 | |
> | 10 | 2 | |
> | 15 | 3 | |
> | 20 | 4 | |
> | 25 | 5 (έλεγχος ψευδής) | |
>
> Ε.8: με `N = 100` → `N` επαναλήψεις × `N` = **`10000`**. Ο πίνακας της εκφώνησης έχει 8 γραμμές· γέμισε όσες χρειάζονται και άφησε τις υπόλοιπες κενές – μη «συμπληρώσεις» από ανησυχία.

> [!example] 2023 Ε.9 – αντίστροφο ίχνος: «ποια αρχική τιμή δίνει n = 4;»
> ```java
> int n = 0;
> int k = 1;
> while(k<x){
>     k+=k;
>     ++n;
> }
> ```
> Κάνε ίχνος **χωρίς** το `x`: `k` = 1, 2, 4, 8, 16 με `n` = 0, 1, 2, 3, 4. Για να τελειώσει με `n = 4` πρέπει: ο έλεγχος να **περάσει** για `k = 8` (`8 < x`) και να **αποτύχει** για `k = 16` (`16 >= x`). Άρα **`9 ≤ x ≤ 16`** – οποιαδήποτε τιμή εκεί (π.χ. 10). Το `k += k` διπλασιάζει: `n = ⌈log₂ x⌉`.

> [!example] 2023 Ε.4 – συμπλήρωσε την εντολή ώστε να βγαίνει το μοτίβο
> ```java
> int i;
> String s = "";
> for(i=0;i<N;++i)
>     ______________
> ```
> Ζητείται `N=1 → "11"`, `N=2 → "2112"`, `N=3 → "321123"`.
> **Μέθοδος:** σύγκρινε διαδοχικές γραμμές. Από `"11"` σε `"2112"`: το παλιό `s` μένει **στη μέση** και προστίθεται το `2` και από τις δύο πλευρές. Στην επανάληψη `i` προστίθεται το `i+1`.
> **Απάντηση:** `s = (i+1) + s + (i+1);`
> Γιατί δουλεύει παρότι αρχίζει με `int`: `(i+1) + s` – ο δεύτερος τελεστέος είναι `String`, άρα συνένωση. Αν το `s` ήταν στο τέλος (`(i+1) + (i+1) + s`), θα έκανε πρώτα **πρόσθεση**: `"2"` αντί για `"11"`.

> [!example] 2023 Ε.10 – πολλαπλή επιλογή (απάντηση: **Ζ. Καμία από τις πιο πάνω**)
> ```java
> int prod= 1;
> int N = 4;
> for(int i=N; i>0;--N);
>      prod*=N;
> ```
> Δύο παγίδες μαζί: (1) το **`;`** μετά το `for` κάνει το σώμα **κενό**, (2) το βήμα μειώνει το **`N`**, όχι το `i`. Το `i` μένει `4 > 0` για πάντα → **άπειρος βρόχος**, η `prod*=N` δεν εκτελείται ποτέ. Το 24 (`4!`) είναι η «δόλωμα» απάντηση για όποιον δεν βλέπει το `;`.

> [!example] 2023 Ε.11 – τριγωνικός βρόχος (απάντηση: **Δ. 15**)
> ```java
> for (i = 0; i <N ; i++)
>     for (j=i;j<N;++j)
>         ++count;
> ```
> Με `N = 5`: το `j` ξεκινά από το `i` → 5 + 4 + 3 + 2 + 1 = **15** = N(N+1)/2. Η επίσημη λύση το δείχνει γράφοντας τις τιμές του `j` ανά γραμμή – αυτός είναι ο «τρόπος σκέψης» που ζητείται.

> [!example] 2022 Ε.1 – φωλιασμένοι βρόχοι (απάντηση: **Β. k = 49**)
> Βλ. το σχέδιο πιο πάνω: 5 εξωτερικές × (+1 +4·2) = 45, συν το αρχικό 4. Το `println("k="+k)` τυπώνει `k=49`.

## Γ. «Τι περιγράφει καλύτερα τον κώδικα;»

**Μέθοδος**
1. Διάλεξε **μικρή** είσοδο που ξεχωρίζει τις επιλογές (π.χ. `"foyi"` – όλα τα γράμματα διαφορετικά).
2. Τρέξε τον κώδικα **με το χέρι**, γράφοντας τον πίνακα μετά από κάθε επανάληψη.
3. Διάβασε **κάθε δείκτη** ξεχωριστά: `x[i]` ή `x[n-1-i]`; Οι παγίδες είναι σε ένα σύμβολο.
4. Για μεθόδους: τι αλλάζει ο καλών; (`int` παράμετρος → τίποτα· πίνακας → τα στοιχεία)

> [!example] 2022 Ε.2 – «αντιστροφή» που δεν αντιστρέφει (απάντηση: **Ε. το περιεχόμενο μένει ίδιο**)
> ```java
> /* x είναι ενάς πίνακας χαρακτήρων */
> for (i = 0; i < (x.length / 2); i++) {
>    temp = x[i];
>    x[i] = x[x.len - i - 1];
>    x[i] = temp;
> }
> ```
> Μοιάζει με αντιστροφή (Δ), αλλά η τρίτη εντολή γράφει πάλι στο **`x[i]`**, όχι στο `x[x.length-i-1]`: η τιμή του `x[i]` επαναφέρεται και το `x[n-1-i]` δεν αλλάζει ποτέ. Ίχνος με `"foyi"` → `"foyi"`. (Το `x.len` είναι τυπογραφικό της εκφώνησης – `x.length`.)

> [!example] 2022 Ε.3 (απάντηση: **Β. θέση του τελευταίου μη-κενού**)
> ```java
> k = table.length - 1;
> while (k >= 0 && looking==1) {
>    if (table[k] == blank) --k;
>    else looking = 0;
> }
> if (looking==1) looking = -1; else looking = k;
> ```
> Ξεκινά από το **τέλος** (`length - 1`) και προχωρά προς τα πίσω όσο βλέπει κενά· σταματά στον πρώτο μη-κενό **από δεξιά** = τελευταίος μη-κενός. Όλα κενά → `-1`. Με `"ab c  "` → `3`. Το `k >= 0` είναι ο **φρουρός** και είναι πρώτος στο `&&`.

> [!example] 2022 Ε.4 – πέρασμα με τιμή (απάντηση: **Α. 0,1,2,3,**)
> ```java
> public static void myFunc (int i) { i = i + 1; }
> …
> i = 0;
> for(j=0;j<4;++j){
>    System.out.print(x[j+i]+ ",");
>    myFunc(i);
> }
> ```
> Η `myFunc` αλλάζει το **αντίγραφό** της· το `i` της `main` μένει `0`. Άρα τυπώνει `x[0]…x[3]` = `0,1,2,3,`. Η «δόλωμα» επιλογή Ε (`0,2,4,6,`) υποθέτει ότι το `i` αυξάνεται.

> [!example] 2022 Ε.8 – περιέγραψε και δώσε παράδειγμα
> ```java
> int i = args.length;
> while(i-- !=0)
>    System.out.println(args[i]);
> ```
> **Τυπώνει τα ορίσματα σε αντίστροφη σειρά**, ένα ανά γραμμή: `java ExamQuestion 1 2 3` → `3`, `2`, `1`. Το `i--` συγκρίνει την **παλιά** τιμή και μετά μειώνει: για `i = 3` ελέγχει `3 != 0` και μέσα στο σώμα `i = 2` – γι' αυτό δεν βγαίνει εκτός ορίων. Χωρίς ορίσματα δεν τυπώνει τίποτα. (Η επίσημη λύση γράφει `3 2 1` σε μία γραμμή – με `println` βγαίνουν σε τρεις.)

## Δ. Αλγόριθμος σε ψευδοκώδικα

**Μέθοδος**
1. Χρησιμοποίησε **μόνο** τις συναρτήσεις που δίνονται, με τα ονόματα που δίνονται – και **μην** τις υλοποιήσεις αν η εκφώνηση το απαγορεύει.
2. Σχήμα «μέτρησης»: `μετρητής ← 0` · βρόχος σε όλα τα στοιχεία · `αν συνθήκη: μετρητής ← μετρητής + 1`.
3. Αν ζητείται κάτι «συμπληρωματικό» με ήδη γνωστή συνάρτηση, **ξαναχρησιμοποίησέ** την – μην γράψεις νέο βρόχο.

> [!example] 2023 Ε.1(α) – `even(X)`: πόσα ψηφία του X είναι άρτια
> (`125206` → 4, `1355193` → 0· το 0 μετράει ως άρτιο.) Δίνονται `get_digit(X, i)` και `get_num_digits(X)`.
> ```
> i = 0
> even = 0
> ενόσω i < get_num_digits(X)
>     d = get_digit(X, i)
>     εάν d διαιρείται από το 2
>         ++even
>     i++
> ```
> Επέστρεψε `even`. Ο έλεγχος «διαιρείται από το 2» στη Java: `d % 2 == 0`.

> [!example] 2023 Ε.1(β) – `odd(X)`: πόσα ψηφία είναι περιττά
> ```
> get_num_digits(X) − even(X)
> ```
> Μία γραμμή. Ένας νέος βρόχος με `d % 2 != 0` είναι **σωστός αλλά «πολύπλοκος»** – και η εκφώνηση προειδοποιεί ότι πολύπλοκες απαντήσεις παίρνουν 0. Αυτό είναι το νόημα του «χρησιμοποιήστε τις `even` και `get_num_digits`».

> [!tip] Χωρίς τις βοηθητικές: τα ψηφία με `%` και `/`
> ```java
> int even = 0;
> do { if ((X % 10) % 2 == 0) even++; X = X / 10; } while (X != 0);
> ```
> `do-while` ώστε το `X = 0` να δώσει 1 άρτιο ψηφίο (ένα `while (X != 0)` θα έδινε 0 ψηφία).

## Ε. Γράψε κώδικα ή πρόγραμμα

**Μέθοδος**
1. **Από πού** έρχεται η είσοδος; Γραμμή εντολής → `args[i]` + `parseInt`/`parseDouble` · πληκτρολόγιο/άγνωστο πλήθος → `while (!StdIn.isEmpty())` · αρχείο → `In f = new In(args[0])`.
2. **Σκελετός**: διάβασε → υπολόγισε → τύπωσε. Τα περισσότερα θέματα είναι 5–10 γραμμές.
3. Διάβασε τους **περιορισμούς**: «μόνο μία εντολή επανάληψης», «χωρίς πίνακα», «χωρίς if-else», «χωρίς μεθόδους βιβλιοθήκης». Είναι υπόδειξη για τη λύση, όχι εμπόδιο.
4. Κάνε **ίχνος** με το παράδειγμα της εκφώνησης (π.χ. «για x=2, n=3 τυπώνει 1.3333»).
5. Έλεγξε τα **όρια**: «από 10001 έως 20000» = `<=`· κενή είσοδος· ένα στοιχείο.

> [!example]- 2023 Ε.5 – μέση τιμή τριών ακεραίων (x=3, y=2, z=50 → 3 · 2, 2, 2 → 2)
> ```java
> if ((x >= y && y >= z) || (x <= y && y <= z)) f = y;
> else if ((x >= z && z >= y) || (x <= z && z <= y)) f = z;
> else f = x;
> ```
> Ιδέα: το `y` είναι η μέση αν βρίσκεται **ανάμεσα** στα άλλα δύο (σε οποιαδήποτε σειρά). Αλλιώς ελέγχεις το `z`, αλλιώς είναι το `x`. Τα `>=` κάνουν σωστές τις ισοπαλίες (`5, 5, 1` → 5).
>
> ⚠️ **Σημείωση:** η επίσημη λύση γράφει `if (x>=y && y>=z) || (x<=y && y<=z) f =y;` – **χωρίς** εξωτερική παρένθεση, που **δεν κάνει compile** (`illegal start of expression`). Η συνθήκη του `if` πρέπει να είναι ολόκληρη μέσα σε μία παρένθεση.

> [!example]- 2023 Ε.13 – `xⁿ / n!` με έναν βρόχο, χωρίς πίνακες ή `Math`
> ```java
> public class ExamQ {
>    public static void main(String[] args){
>       double x = Double.parseDouble(args[0]);
>       int n = Integer.parseInt(args[1]);
>       double num = 1.0;
>       double den = 1.0;
>       for (int i = 0; i < n; ++i) {
>          num = num * x;          // x^n
>          den = den * (i + 1);    // n!
>       }
>       System.out.println(num / den);
>    }
> }
> ```
> `x=2, n=3` → `8/6` = `1.3333333333333333` · `x=3, n=3` → `27/6` = `4.5` · `n = 0` → `1.0` (σωστό: x⁰/0! = 1).
> - Ο **ένας** βρόχος υπολογίζει **και** τα δύο (αριθμητή και παρονομαστή) – αυτός είναι ο λόγος του περιορισμού.
> - `den` ως `double`: ένα `int` παραγοντικό υπερχειλίζει στο 13!.
> - Ακόμη πιο απλό: `term = term * x / (i + 1);` με `term = 1.0` – ένας όρος αντί για δύο μεταβλητές.

> [!example]- 2023 Ε.14 – `switch` αντί για `if` (A/a → Excellent, B/b → Very Good, C/c → Good, F/f → Fail, αλλιώς Λάθος)
> ```java
> public class ExamQ {
>    public static void main(String[] args){
>       char c = args[0].charAt(0);   // πρώτος χαρακτήρας του ορίσματος
>       switch (c) {
>          case 'A': case 'a': System.out.println("Excellent"); break;
>          case 'B': case 'b': System.out.println("Very Good"); break;
>          case 'C': case 'c': System.out.println("Good"); break;
>          case 'F': case 'f': System.out.println("Fail"); break;
>          default: System.out.println("Λάθος");
>       }
>    }
> }
> ```
> - Δύο `case` στη σειρά χωρίς εντολή ανάμεσα = **«ή»** (σκόπιμο fall-through).
> - Το `break` σε **κάθε** ομάδα· χωρίς αυτό, `b` θα τύπωνε `Very Good`, `Good`, `Fail`, `Λάθος` (ελέγχθηκε).
> - Οι ετικέτες είναι `char` με **μονά** εισαγωγικά (`'A'`), όχι `"A"`.
> - `D`, `E` → `Λάθος` (δεν υπάρχουν στον πίνακα). `"Ab"` → `Excellent` (μετράει μόνο ο πρώτος χαρακτήρας).
>
> ⚠️ **Σημείωση:** η επίσημη λύση γράφει `switch(c):` με άνω-κάτω τελεία και **χωρίς** `{ }` γύρω από τα `case` – δεν κάνει compile. Επίσης έχει τυπογραφικά εισαγωγικά (`‘A’`, `“Excellent”`).

> [!example]- 2023 Ε.15 – Νόμος του Amdahl: S = t / (t − f + f/p)
> ```java
> public class ExamQ {
>    public static void main(String[] args){
>       double t = Double.parseDouble(args[0]);
>       double f = Double.parseDouble(args[1]);
>       double p = Double.parseDouble(args[2]);
>       double S = t / (t - f + f / p);
>       System.out.println(S);
>    }
> }
> ```
> `t=100, f=40, p=4` → `100 / (60 + 10)` = `1.4285714285714286`.
> - Η παρένθεση στον παρονομαστή είναι **όλη** η ερώτηση: `t / t - f + f / p` = `1 − 40 + 10` = `−29`.
> - `f / p` χωρίς παρένθεση είναι σωστό: η διαίρεση γίνεται πριν την πρόσθεση.
> - Όλα `double` – με `int` το `f / p` θα έκοβε (`40/3 = 13`).

> [!example]- 2022 Ε.5 – ακέραιοι 10001 έως 20000, N ανά γραμμή, με ένα `for` και ένα `if`
> ```java
> public class ExamQuestion {
>    public static void main(String[] args) {
>       int N = Integer.parseInt(args[0]);
>       for (int i = 10001; i <= 20000; ++i) {
>          System.out.print(i + " ");
>          if ((i - 10000) % N == 0) System.out.println();
>       }
>    }
> }
> ```
> Με `N = 3`: `10001 10002 10003` / `10004 10005 10006` / … Το `i - 10000` μετράει **πόσοι** έχουν τυπωθεί (1, 2, 3, …): αλλαγή γραμμής όταν είναι πολλαπλάσιο του `N`.
>
> ⚠️ **Σημείωση:** η επίσημη λύση έχει τρία λάθη: (1) `for(i=10001;…)` χωρίς `int` → `cannot find symbol`· (2) `i<20000` – χάνεται το **20000**· (3) **`i-10000 % N`** = `i - (10000 % N)` γιατί το `%` έχει μεγαλύτερη προτεραιότητα από το `-` – για `N = 3` είναι `i - 1 == 0`, δηλαδή **ποτέ** δεν αλλάζει γραμμή. Χρειάζεται `(i-10000) % N`.

> [!example]- 2022 Ε.6 – είναι η είσοδος (άγνωστου μεγέθους) σε αύξουσα σειρά; Χωρίς πίνακα
> ```java
> public class ExamQuestion {
>    public static void main(String[] args) {
>       int pvalue = 0, value;
>       if (!StdIn.isEmpty()) pvalue = StdIn.readInt();
>       while (!StdIn.isEmpty()) {
>          value = StdIn.readInt();
>          if (value < pvalue) {
>             System.out.print("Τα Δεδομένα εισόδου ΔΕΝ εισάγονται με αύξουσα σειρά");
>             return;
>          }
>          pvalue = value;
>       }
>       System.out.print("Τα δεδομένα εισόδου εισάγονται με αύξουσα σειρά");
>    }
> }
> ```
> **Ιδέα:** δεν χρειάζεται πίνακας – αρκεί να θυμάσαι τον **προηγούμενο** (`pvalue`) και να συγκρίνεις με τον τρέχοντα. Μόλις βρεις μία «πτώση» → `return`.
> - `3 45 46 567 10234` → αύξουσα · `123 845 460 …` → όχι (`460 < 845`).
> - Ίσες διαδοχικές τιμές (`5 5 5`) περνούν ως «αύξουσα»· για **γνησίως** αύξουσα: `value <= pvalue`.
> - Κενή είσοδος ή ένας αριθμός → «αύξουσα» (τίποτα δεν την παραβιάζει).
>
> ⚠️ **Σημείωση:** η επίσημη λύση δηλώνει `int pvalue, value;` **χωρίς** αρχική τιμή και αναθέτει το `pvalue` μόνο μέσα στο `if`. Ο μεταγλωττιστής δεν μπορεί να εγγυηθεί ότι έχει τιμή στο `value < pvalue` → **`variable pvalue might not have been initialized`**. Λύση: `int pvalue = 0`.

> [!example]- 2022 Ε.7 – `sum_digit`: άθροισμα ψηφίων (23416 → 16)
> ```java
> public static int sum_digit(int x) {
>    int sum = 0;
>    while (x != 0) {
>       sum += x % 10;     // τελευταίο ψηφίο
>       x = x / 10;        // αφαίρεσέ το
>    }
>    return sum;
> }
> ```
> Ίχνος: `23416` → +6, `2341` → +1, `234` → +4, `23` → +3, `2` → +2, `0` → τέλος = 16. `sum_digit(0)` = 0.
>
> ⚠️ **Σημείωση:** η εκφώνηση και η λύση γράφουν `unsigned int x` (και `unsinged`) – η Java **δεν** έχει `unsigned` (είναι από τη C). Γράψε `int x`. Για αρνητικό όρισμα (`-23`) ο κώδικας δίνει `-5` (το `%` κρατά το πρόσημο)· με `x = Math.abs(x);` στην αρχή δίνει 5.

> [!example]- 2022 Ε.9 – άθροισμα n όρων της σειράς (1/1·1/2) + (1/2·1/3) + … + (1/n·1/(n+1))

> public class ExamQuestion {
>    public static void main(String[] args) {
>       int n = Integer.parseInt(args[0]);
>       double sum = 0;

> ⚠️ **Σημείωση:** η επίσημη λύση δεν δηλώνει το `i` (`for(i=1;…)`) και **δεν τυπώνει** το `sum`.

> [!example]- 2022 Ε.10 – αραιός πίνακας → πυκνός
> **Ορισμός:** ο `A` είναι αραιός αν **τουλάχιστον τα μισά** στοιχεία του είναι 0. Ο πυκνός `B` έχει διπλάσιες θέσεις από τα μη μηδενικά: στο πρώτο μισό οι **τιμές**, στο δεύτερο μισό οι **θέσεις** τους στον `A`.
> `A = {0, 0, 50, 0, -7, 50, 0, 0}` → `B = {50, -7, 50, 2, 4, 5}`.
> ```java
> // (α) πλήθος μη μηδενικών αν ο A είναι αραιός, αλλιώς -1
> private static int dense_num(int[] A) {
>    int count = 0;                              // μηδενικά
>    for (int i = 0; i < A.length; ++i)
>       if (A[i] == 0) count++;
>    if (2 * count >= A.length) return A.length - count;
>    else return -1;
> }
>
> // (β) ο πυκνός B αν ο A είναι αραιός, αλλιώς ο ίδιος ο A
> private static int[] dense(int[] A) {
>    int c = dense_num(A);
>    if (c == -1) return A;
>    int[] B = new int[2 * c];
>    int p = 0;
>    for (int i = 0; i < A.length; ++i)
>       if (A[i] != 0) {
>          B[p] = A[i];          // τιμή στο πρώτο μισό
>          B[c + p] = i;         // θέση στο δεύτερο μισό
>          p++;
>       }
>    return B;
> }
> ```
> - `2 * count >= A.length` ≡ «τουλάχιστον μισά» χωρίς πραγματική διαίρεση· ισοδύναμο με το `count >= (A.length+1)/2` της επίσημης λύσης.
> - Το (β) **ξαναχρησιμοποιεί** το (α) – και για τον έλεγχο και για το μέγεθος.
>
> ⚠️ **Σημείωση:** η εκφώνηση και η επίσημη λύση γράφουν **`A.length()`** – σε πίνακα είναι **`A.length`** (πεδίο, χωρίς παρενθέσεις)· με `()` → `cannot find symbol`. Επίσης `count++` χωρίς `;` και `If` με κεφαλαίο. Το σοβαρότερο: η επίσημη (β) φτιάχνει `new int[c]` και αντιγράφει **μόνο τις τιμές** – λείπουν οι **θέσεις** που ζητά η εκφώνηση (το `B` του παραδείγματος έχει 6 στοιχεία, όχι 3).

> [!example]- 2022 Ε.13 – συμπλήρωσε τα κενά: ταξινόμηση με εισαγωγή σε αύξουσα σειρά

> private static void insertSort(double[] t){
>   for (int i = 1; i < t.length; i++){
>     boolean stop = false;
>     for (int j = i; j > 0 && !stop; --j)

## ΣΤ. Βρες τα λάθη

**Μέθοδος**
1. **Συντακτικά** (σάρωσε γραμμή-γραμμή): `=` αντί `==` σε συνθήκη · `;` που λείπουν/περισσεύουν · άνισες `( )` `{ }` · `length` vs `length()` · αδήλωτες μεταβλητές · `switch (c):` · `“ ”` αντί `" "` · τύποι (`int x = 2.5`).
2. **Λογικά** (κάνε ίχνος με παράδειγμα της εκφώνησης **και** ένα οριακό – κενό, ένα στοιχείο, όλα ίδια):
   - όρια δεικτών: `charAt(i+1)` θέλει `i + 1 < length()`
   - σειρά στο `&&`: ο φρουρός ορίων **πρώτος**
   - `||` αντί για `&&` σε συνθήκη συνέχισης βρόχου
   - η συνθήκη μετά τον βρόχο ταιριάζει με το **πού σταματά** ο βρόχος;
3. Για κάθε διόρθωση, ξανακάνε ίχνος **όλο** το πρόγραμμα – μια διόρθωση μπορεί να αλλάξει τι χρειάζεται αλλού.

> [!example] 2023 Ε.12 – `StringSameChar`: είναι όλοι οι χαρακτήρες του `args[0]` ίδιοι;
> (`#####`, `5555555`, `^^` → ίδιοι · `11111%`, `0234`, `ggg1ggg` → όχι)
> ```java
>  1 public class StringSameChar
>  2 {
>  3    public static void main(String[] args)
>  4    {
>  5      int i=0;
>  6      while (args[0].charAt(i) == args[0].charAt(i+1) || i+1 < args[0].length()){
>  7        i++;
>  8      }
>  9      if (i = args[0].length())
> 10          System.out.println("Idioi");
> 11      else
> 12          System.out.println("Diaforetikoi");
> 13    }
> 14 }
> ```
> **Συντακτικό, γραμμή 9:** `if (i = args[0].length())` – ανάθεση αντί για σύγκριση· το αποτέλεσμα είναι `int`, όχι `boolean` → compile error. Διόρθωση: `==`.
> **Λογικό, γραμμή 6:** για `"#####"` οι χαρακτήρες είναι όλοι ίσοι, άρα το αριστερό μέρος του `||` είναι πάντα αληθές και το `i` φτάνει στο τελευταίο: `charAt(i+1)` → `StringIndexOutOfBoundsException`. Δύο προβλήματα: (α) `||` αντί `&&` (β) ο έλεγχος ορίων πρέπει να είναι **πρώτος**.
>
> **Επίσημη διόρθωση:** `while (i+1 < args[0].length() && args[0].charAt(i) == args[0].charAt(i+1))` και `if (i == args[0].length())`.
>
> ⚠️ **Σημείωση:** οι δύο επίσημες διορθώσεις **μαζί** δεν δουλεύουν: ο διορθωμένος βρόχος σταματά στο `i = length − 1` (όταν `i + 1 == length`), άρα το `i == args[0].length()` δεν ισχύει **ποτέ** για μη κενό string και τυπώνεται **πάντα** `Diaforetikoi` (ελέγχθηκε και για τα 6 παραδείγματα). Δύο σωστές επιλογές:
> - κράτα τον επίσημο βρόχο και γράψε `if (i == args[0].length() - 1)`, ή
> - (μένουν μόνο οι δύο γραμμές με λάθη) σύγκρινε κάθε χαρακτήρα με τον **πρώτο**:
> ```java
> while (i < args[0].length() && args[0].charAt(i) == args[0].charAt(0))
>    i++;
> if (i == args[0].length()) …        // πέρασε όλους → ίδιοι
> ```
> Αυτή σταματά στο `length` όταν όλοι είναι ίδιοι, οπότε η γραμμή 9 με `==` είναι σωστή όπως είναι. (Για κενό όρισμα `""` δίνει «Idioi» χωρίς εξαίρεση: το `i < 0` είναι ψευδές πριν αποτιμηθεί το `charAt(0)`.)

## 3. Λάθη στις επίσημες λύσεις – συγκεντρωτικά

| Ερώτηση | Τι γράφει η λύση | Πρόβλημα | Σωστό |
|---|---|---|---|
| 2023 Ε.5 | `if (x>=y && y>=z) \|\| (…) f=y;` | δεν κάνει compile | `if ((…) \|\| (…))` |
| 2023 Ε.12 | βρόχος έως `i+1 < length` και `i == length()` | τυπώνει πάντα «Diaforetikoi» | `i == length() - 1` ή σύγκριση με `charAt(0)` |
| 2023 Ε.14 | `switch(c):` | δεν κάνει compile | `switch (c) { … }` |
| 2022 Ε.5 | `for(i=…; i<20000;…)`, `i-10000 % N` | αδήλωτο `i`, χάνει το 20000, προτεραιότητα `%` | `int i`, `<=`, `(i-10000) % N` |
| 2022 Ε.6 | `int pvalue, value;` | might not have been initialized | `int pvalue = 0` |
| 2022 Ε.7 | `unsigned int x` | δεν υπάρχει στη Java | `int x` |
| 2022 Ε.9 | `for(i=1;…)`, χωρίς εκτύπωση | αδήλωτο `i` | `int i`, `println(sum)` |
| 2022 Ε.10 | `A.length()`, `new int[c]` | compile error · λείπουν οι θέσεις | `A.length`, `new int[2*c]` |
| 2022 Ε.11 | `if ((… \|\| …)` | άνισες παρενθέσεις · αγνοεί τελικά κενά | `readAll().equals(…)` |
| 2022 Ε.13 | `t.length()`, `FALSE` | compile error | `t.length`, `false` |

> [!tip] Τι μαθαίνουμε από αυτό
> Οι λύσεις γράφτηκαν στο χέρι, όχι σε μεταγλωττιστή. Στη δική σου απάντηση **αυτά ακριβώς** είναι που κόβουν μονάδες: `length` vs `length()`, δήλωση του `i`, παρενθέσεις στο `if`, προτεραιότητα του `%`, αρχικοποίηση μεταβλητών, `<` vs `<=`. Πριν παραδώσεις, κάνε ένα πέρασμα **μόνο** για αυτά.

## 4. Λίστα ελέγχου πριν παραδώσεις

> [!important] Για κάθε κώδικα που έγραψες
> - [ ] Κάθε μεταβλητή **δηλωμένη** (`int i`) και **αρχικοποιημένη** πριν χρησιμοποιηθεί
> - [ ] `parseInt`/`parseDouble` για κάθε `args[i]` που είναι αριθμός
> - [ ] `a.length` για πίνακα, `s.length()` για String
> - [ ] `==` σε συνθήκες (όχι `=`), `equals` για String
> - [ ] Όρια βρόχου: «έως Ν» → `<=`· δείκτες `0 … length−1`
> - [ ] Πραγματική διαίρεση: `1.0 / i`, όχι `1 / i`
> - [ ] Παρενθέσεις: ολόκληρη η συνθήκη του `if`/`while` σε μία· `(i - k) % N`
> - [ ] `break` σε κάθε `case` · `{ }` γύρω από σώματα με πολλές εντολές
> - [ ] Τυπώνεις το αποτέλεσμα; (`println`, όχι μόνο υπολογισμός)
> - [ ] Ίχνος με το παράδειγμα της εκφώνησης + μία οριακή περίπτωση

## 5. Εξάσκηση στο ύφος των εξετάσεων

### Άσκηση 1 (τύπου Α)

### Άσκηση 2 (τύπου Β, πολλαπλή επιλογή)

```java
int s = 0;
for (int i = 1; i <= 5; i++)
   for (int j = i; j <= 5; j += 2)
      s++;
```
Η τιμή του `s` είναι: Α. 9 · Β. 15 · Γ. 25 · Δ. 5 · Ε. Καμία

> [!success]- Λύση

### Άσκηση 3 (τύπου Β, αντίστροφο ίχνος)

```java
int n = 0, k = 100;
while (k > x) { k = k / 2; n++; }
```
Μετά την εκτέλεση `n == 3`. Ποιες ακέραιες τιμές του `x` είναι δυνατές;

> [!success]- Λύση
> `k`: 100 → 50 → 25 → 12 (μετά από 3 επαναλήψεις). Χρειάζεται `25 > x` (να γίνει η 3η) και `12 <= x` (να **μη** γίνει η 4η): **`12 ≤ x ≤ 24`**.

### Άσκηση 4 (τύπου Γ)

```java
for (int i = 0; i < a.length - 1; i++)
   if (a[i] > a[i+1]) { int t = a[i]; a[i] = a[i+1]; a[i+1] = t; }
```
Τι περιγράφει καλύτερα τον κώδικα; Α. ταξινομεί τον πίνακα · Β. φέρνει το μέγιστο στην τελευταία θέση · Γ. φέρνει το ελάχιστο στην πρώτη θέση · Δ. αντιστρέφει τον πίνακα

> [!success]- Λύση
> **Β.** Ένα πέρασμα της ταξινόμησης φυσαλίδας: το μέγιστο «σπρώχνεται» δεξιά σε κάθε σύγκριση. Ίχνος με `{3, 1, 2}` → `{1, 2, 3}` φαίνεται ταξινομημένο, αλλά με `{3, 2, 1}` → `{2, 1, 3}`: **όχι** ταξινόμηση (Α ✗), το ελάχιστο δεν είναι πρώτο (Γ ✗). Διάλεξε είσοδο που **ξεχωρίζει** τις επιλογές.

### Άσκηση 5 (τύπου Ε)

Γράψε πρόγραμμα που διαβάζει από την standard είσοδο ακεραίους άγνωστου πλήθους και τυπώνει πόσοι είναι μεγαλύτεροι από τον **πρώτο**. Χωρίς πίνακα.

> [!success]- Λύση
> ```java
> public class GreaterThanFirst {
>    public static void main(String[] args) {
>       if (StdIn.isEmpty()) { System.out.println(0); return; }
>       int first = StdIn.readInt();
>       int count = 0;
>       while (!StdIn.isEmpty())
>          if (StdIn.readInt() > first) count++;
>       System.out.println(count);
>    }
> }
> ```
> Ίδιο σχήμα με τη 2022 Ε.6: διάβασε τον πρώτο **έξω** από τον βρόχο, μετά σύγκρινε. Ο έλεγχος κενής εισόδου αποφεύγει `NoSuchElementException`.

### Άσκηση 6 (τύπου ΣΤ)

Το πρόγραμμα πρέπει να τυπώνει πόσες φορές εμφανίζεται ο χαρακτήρας `args[1].charAt(0)` στο `args[0]`. Βρες ένα συντακτικό και ένα λογικό λάθος.
```java
1 int count = 0;
2 char c = args[1].charAt(0);
3 for (int i = 0; i <= args[0].length(); i++)
4    if (args[0].charAt(i) = c) count++;
5 System.out.println(count);
```

> [!success]- Λύση
> **Συντακτικό, γραμμή 4:** `=` → `==` (αλλιώς `unexpected type` – ανάθεση σε αποτέλεσμα μεθόδου). **Λογικό, γραμμή 3:** `<=` → `<` – με `<=` το `charAt(length())` πετάει `StringIndexOutOfBoundsException`. Το `==` εδώ είναι σωστό: συγκρίνει `char`, όχι `String`.
