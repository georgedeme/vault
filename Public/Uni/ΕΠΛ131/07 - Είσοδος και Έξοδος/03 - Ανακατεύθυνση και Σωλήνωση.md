# 03 - Ανακατεύθυνση και Σωλήνωση

Το λειτουργικό σύστημα μπορεί να συνδέσει την standard είσοδο/έξοδο ενός προγράμματος με **αρχείο** (ανακατεύθυνση, `<` `>`) ή με **άλλο πρόγραμμα** (σωλήνωση, `|`), χωρίς καμία αλλαγή στον κώδικα (διαφάνειες VII-34 … VII-51).

## 1. Είσοδος–Έξοδος με ανακατεύθυνση (VII-34)

> [!note] Χαρακτηριστικά
> - Το standard κανάλι εισόδου/εξόδου **ανακατευθύνεται σε αρχείο κειμένου**. Συντελείται σε **επίπεδο λειτουργικού συστήματος**.
> - Οι εντολές είναι **οι ίδιες** όπως για τη διαδραστική εισαγωγή στοιχείων. Όμως **αφαιρούνται τα user prompts**.
>   - Δεν εφαρμόζεται σε κάθε περίπτωση διαδραστικού προγράμματος (π.χ. «Είκοσι Ερωτήσεις», όπου η επόμενη ερώτηση εξαρτάται από την απάντηση).
> - **Μόνο ένα αρχείο** για την ανακατεύθυνση εισόδου (και ένα για την έξοδο).
> - **Απεριόριστος** αριθμός στοιχείων εισόδου.
> - **Αποθήκευση αποτελέσματος** για μακροπρόθεσμη αξιοποίηση.

| Σύμβολο | Σημαίνει | Παράδειγμα |
|---|---|---|
| `< αρχείο` | η `StdIn` διαβάζει από το αρχείο αντί για το πληκτρολόγιο | `java Average < Data.txt` |
| `> αρχείο` | η `System.out` γράφει στο αρχείο αντί για την οθόνη (το **σβήνει** πρώτα) | `java RandomSeq 50 20 40 > Data.txt` |
| `>> αρχείο` | ➕ όπως το `>` αλλά **προσθέτει** στο τέλος | `java RandomSeq 10 1 6 >> Data.txt` |
| `A \| B` | η έξοδος του `A` γίνεται είσοδος του `B` | `java RandomSeq 50 20 40 \| java Average` |

> [!important] Το πρόγραμμα δεν το καταλαβαίνει
> Τα `<`, `>`, `|` **δεν** φτάνουν στη Java: δεν εμφανίζονται στο `args` και ο κώδικας δεν αλλάζει. Το πρόγραμμα απλώς διαβάζει από `StdIn` και γράφει σε `System.out` – το λειτουργικό σύστημα αποφασίζει πού είναι συνδεδεμένα. (Σχέδιο: [[03 - Standard Είσοδος και Επεξεργασία Αρχείων#2. Ανακατεύθυνση εισόδου/εξόδου|VI – 03 §2]].)

## 2. Μέσος όρος – Version 3: ανακατεύθυνση εισόδου (VII-35, VII-36)

Η VII-35 παίρνει τη Version 2 και **διαγράφει** τα δύο `System.out.print("Enter value: ");`:

```java
// Computing the average of a list of numbers
// Version 3: File redirection for input

public class Average {

 public static void main(String[] args) {
  double sum = 0.0;
  int cnt = 0;
  while (!StdIn.isEmpty()){
     sum += StdIn.readDouble();
     cnt++;
  }
  double average = sum/cnt;
  System.out.println("\nAverage is " + average);
 }

}
```

| `Data.txt` | Εντολή | Έξοδος |
|---|---|---|
| `45 67`<br>`2`<br>`109 200` | `java Average < Data.txt` | `Average is 84.6` |

> [!tip] Η μορφή του αρχείου δεν έχει σημασία
> Τιμές σε μία γραμμή, μία ανά γραμμή, ή ανακατεμένες με κενές γραμμές: η `readDouble()` διαβάζει **λέξεις**, άρα όλα δίνουν το ίδιο αποτέλεσμα. Αυτό εννοούν οι διαφάνειες με «η δομή του αρχείου είναι ιδεατή» ([[04 - Αρχεία με In και Out|04]]).

> [!warning] Τα prompts με ανακατεύθυνση
> Αν τρέξεις τη **Version 2** (με τα prompts) με `< Data.txt`, δουλεύει κανονικά αλλά τυπώνει `Enter value: Enter value: …` όλα στη σειρά, γιατί κανείς δεν πληκτρολογεί. Με `> out.txt` τα prompts καταλήγουν **μέσα στο αρχείο** εξόδου. Γι' αυτό σε προγράμματα-«φίλτρα» δεν βάζουμε prompts.

> [!note] ⚠️ Σημείωση: πού είναι η Version 4;
> Οι διαφάνειες αριθμούν τις εκδόσεις του `Average` 1, 2, 3 και 5 (VII-59). Η Version 4 λείπει (όπως και η διαφάνεια VII-58)· πιθανότατα είναι η χρήση της Version 3 μέσω σωλήνωσης (§4), που δεν χρειάζεται αλλαγή στον κώδικα.

## 3. Γεννήτρια τυχαίων αριθμών (VII-37, VII-38)

```java
// Generates a random sequence of N numbers from
// base to limit inclusive.
// N, base and limit entered from command line

public class RandomSeq {

 public static void main(String[] args) {
  int N = Integer.parseInt(args[0]);
  int base = Integer.parseInt(args[1]);
  int limit = Integer.parseInt(args[2]);
  for (int i = 1; i <= N; i++){
    System.out.print(base +
       (int)(Math.random()*(limit-base+1)) + "  ");
    if (i % 10 == 0) System.out.println();
  }
 }

}
```

```
$ java RandomSeq 20 1 10
6  6  5  2  2  9  9  7  8  10
6  5  4  7  3  8  1  6  8  7
```

> [!important] Τρία μοτίβα σε ένα πρόγραμμα
> - **Τυχαίος ακέραιος στο `[base, limit]`**: `base + (int)(Math.random() * (limit - base + 1))` ([[08 - Μετατροπή Τύπων|II – 08]]). Το `+1` κάνει το `limit` εφικτό.
> - **Αλλαγή γραμμής κάθε 10**: `if (i % 10 == 0) System.out.println();` – γι' αυτό ο μετρητής ξεκινά από **1**.
> - Το `base + (int)(…) + "  "` αποτιμάται **από αριστερά**: πρώτα πρόσθεση ακεραίων, μετά συνένωση.

> [!warning] Παγίδα: η σειρά στη συνένωση
> `System.out.print("  " + base + (int)(Math.random()*…))` με `base = 20` και τυχαίο `5` τυπώνει `  205`, όχι `  25`: ο πρώτος τελεστέος είναι `String`, άρα και τα δύο `+` γίνονται συνένωση ([[05 - String και char|II – 05]]).

**Ανακατεύθυνση εξόδου και μετά εισόδου (VII-38):**

```
$ java RandomSeq 50 20 40 > Data.txt        ← input από γραμμή εντολής, ανακατεύθυνση output
$ cat Data.txt
35  36  39  23  32  25  38  30  25  39
28  35  30  39  32  35  24  23  25  28
…
$ java Average < Data.txt                   ← input μέσω ανακατεύθυνσης

Average is 31.08
```

> [!note] Σημ. της διαφάνειας (VII-38)
> Η `RandomSeq` παράγει τους τυχαίους αριθμούς ως **ακεραίους** και η `Average` τους επεξεργάζεται ως **πραγματικούς** – κανένα πρόβλημα (το `"35"` διαβάζεται και ως `double`). Το **αντίθετο** όμως θα ήταν πρόβλημα: ένα πρόγραμμα με `readInt()` πάνω σε `"31.08"` σκάει με `InputMismatchException`.

## 4. Σωλήνωση διεργασιών (process pipe, VII-39 … VII-42)

```
$ process1 | process2 | process3
```

> [!note] Τι είναι
> - Όπως και η ανακατεύθυνση, η «σωλήνωση» διεργασιών συντελείται σε **επίπεδο λειτουργικού συστήματος**.
> - Το **output** μίας διεργασίας (δηλαδή του υπό εκτέλεση προγράμματος) **διοχετεύεται ως input** μιας άλλης διεργασίας.
> - Έτσι συντίθεται μια ακολουθία διεργασιών – ένας **«σωλήνας» διεργασιών**.
>   - Μπορεί να προκύπτει και **παράλληλη επεξεργασία**: δεν χρειάζεται να ολοκληρωθεί μια διεργασία για να αρχίσει η επόμενη.
> - Επομένως το λογισμικό μας μπορεί να διασπαστεί σε επιμέρους προγράμματα (ξεχωριστές κλάσεις) που χρησιμοποιούνται και **ανεξάρτητα**: **άρθρωση σε υψηλό επίπεδο**, **πολλαπλές συνθέσεις** διεργασιών, και κατ' επέκταση **επαναχρησιμοποίηση**.

```
$ java RandomSeq 50 20 40 > Data.txt
$ java Average < Data.txt
Average is 31.08

$ java RandomSeq 50 20 40 | java Average
Average is 31.08

$ java RandomSeq 1000000 1 100 | java Average
Average is 50.99188678931984
```

> [!tip] Τι κερδίζουμε (VII-41)
> - **Δεν υπάρχει το διαλογικό στοιχείο**: κανείς δεν πληκτρολογεί.
> - Δεν χρειάζεται ενδιάμεσο αρχείο: ένα εκατομμύριο αριθμοί περνούν κατευθείαν από το ένα πρόγραμμα στο άλλο.
> - ⚠️ Το `Average is 31.08` εμφανίζεται ίδιο και στις δύο εκτελέσεις της διαφάνειας, αλλά με τυχαίους αριθμούς **δεν** θα έβγαινε ίδιο – είναι διαφορετική εκτέλεση της `RandomSeq`. Το `≈ 50.99` για 1…100 είναι λογικό: ο μέσος όρος ομοιόμορφων ακεραίων 1…100 είναι 50.5, και με 10⁶ δείγματα πέφτει κοντά.

> [!note] Τεχνική της σωλήνωσης (VII-42)
> Ιδιαίτερα κατάλληλη για προβλήματα που συνεπάγονται τον **μετασχηματισμό του αρχικού input** σε διάφορες **ενδιάμεσες μορφές** μέχρι τον τελικό μετασχηματισμό που συνιστά το τελικό output. Ο σχεδιασμός αποτελείται από το **αρχικό**, τα **ενδιάμεσα** και το **τελικό** στάδιο.

## 5. Παράδειγμα: Caps | Centralize | DoubleSpace (VII-43 … VII-48)

Στόχος: από το `input.txt` (κείμενο του Τμήματος Πληροφορικής) να φτιαχτεί το `output.txt` με **κεφαλαία**, **κεντραρισμένες** γραμμές σε πλάτος 60, και **διπλό διάστιχο**.

```
$ java Caps < input.txt | java Centralize 60 | java DoubleSpace > output.txt
```

![[Σωλήνωση - Caps Centralize DoubleSpace.png|800]]

### Caps – κεφαλαία

```java
// Process Caps

public class Caps {

  private static char capL (char c) {
    if ('a' <= c && c <= 'z')
      return (char)(c - 'a' + 'A');
    else return c;
  }

  private static String convert(String s) {
    String rs = new String(); // = "";
    for (int i = 0; i < s.length(); i++)
      rs += capL(s.charAt(i));
    return rs;
  }

  public static void main (String [] args) {
    System.out.print(convert(StdIn.readAll()));
  }
}
```

> [!important] Τι κάνει κάθε κομμάτι
> - `c - 'a' + 'A'`: η απόσταση του γράμματος από το `'a'`, προστιθέμενη στο `'A'`. Το αποτέλεσμα είναι **`int`**, άρα χρειάζεται `(char)` ([[05 - String και char|II – 05]]). Για `'c'`: `99 − 97 + 65 = 67` = `'C'`.
> - Αλλάζουν **μόνο** τα `a`–`z`: ψηφία, σημεία στίξης, κεφαλαία και **ελληνικά** μένουν ίδια (το `'α'` δεν είναι ανάμεσα σε `'a'` και `'z'`).
> - `readAll()` διαβάζει **όλο** το κείμενο μαζί με τις αλλαγές γραμμής, οπότε η έξοδος έχει ακριβώς τις ίδιες γραμμές. Γι' αυτό `print` και όχι `println`.
> - `new String()` = `""` (το λέει και το σχόλιο). `rs += …` δημιουργεί κάθε φορά **νέο** string ([[02 - Συμβολοσειρές ως Δείκτες και Σύγκριση|VI – 02]]).
> - `private`: οι `capL`/`convert` είναι βοηθητικές, δεν χρησιμοποιούνται εκτός κλάσης.

### Centralize – κεντράρισμα

```java
// Process Centralize

public class Centralize {

  private static String blanks (int n) {
    String s = "";
    for (int i = 1; i <= n; i++) s += ' ';
    return s;
  }

  public static void main(String[] args) {
    int N = Integer.parseInt(args[0]);
    while (!StdIn.isEmpty()){
      String s = StdIn.readLine();
      int len = s.length();
      int left = (N - len)/2;
      int right = N - (len + left);
      System.out.print(blanks(left) + s +
         blanks(right) + "\n");
    }
  }
}
```

![[Σωλήνωση - Κεντράρισμα Γραμμής.png|800]]

| `N` | Γραμμή | `len` | `left` | `right` | Αποτέλεσμα |
|---|---|---|---|---|---|
| 10 | `"abc"` | 3 | 3 | 4 | `"   abc    "` – το «μισό» κενό δεξιά |
| 10 | `"abcd"` | 4 | 3 | 3 | `"   abcd   "` |
| 10 | `""` | 0 | 5 | 5 | 10 κενά |
| 10 | 15 χαρακτήρες | 15 | −2 | −3 | η γραμμή όπως είναι (`blanks` με αρνητικό → `""`) |

> [!warning] Παγίδες του `Centralize`
> - `(N - len)/2` είναι **ακέραια** διαίρεση: με περιττή διαφορά, το `right` παίρνει ένα κενό παραπάνω. Το `right = N - (len + left)` εξασφαλίζει ότι κάθε γραμμή έχει **ακριβώς** `N` χαρακτήρες (όταν χωράει).
> - Η ακέραια διαίρεση κόβει **προς το 0**: `-5/2 = -2`, όχι `-3`.
> - Το `60` είναι **όρισμα γραμμής εντολής** (`args[0]`), ενώ το κείμενο έρχεται από `StdIn`. Σε σωλήνωση κάθε πρόγραμμα έχει τα δικά του ορίσματα.
> - Τα κενά **δεξιά** δεν φαίνονται στην οθόνη αλλά υπάρχουν στο αρχείο.

### DoubleSpace – διπλό διάστιχο

```java
// Process DoubleSpace

public class DoubleSpace {

 public static void main(String[] args) {
   while(!StdIn.isEmpty()){
     String s = StdIn.readLine();
     System.out.print(s + "\n\n");
   }
 }

}
```

Κάθε γραμμή τυπώνεται με **δύο** αλλαγές γραμμής: η μία τελειώνει τη γραμμή, η άλλη αφήνει μια κενή.

## 6. Αλλάζει το αποτέλεσμα αν αλλάξει η σειρά; (VII-49)

Η διαφάνεια ρωτά «Ποια θα είναι τα αποτελέσματα των ακόλουθων σωληνώσεων;» χωρίς να απαντά. Οι απαντήσεις (ελέγχθηκαν τρέχοντας τα προγράμματα στο `input.txt`):

| # | Σωλήνωση | Αποτέλεσμα |
|---|---|---|
| 0 | `Caps < input.txt \| Centralize 60 \| DoubleSpace > output.txt` | το `output.txt` της VII-44 (28 γραμμές) |
| 1 | `Centralize 60 < input.txt \| DoubleSpace \| Caps > output.txt` | **ακριβώς ίδιο** με το 0 – κανένα βήμα δεν επηρεάζει τα άλλα |
| 2 | `DoubleSpace < input.txt \| Caps \| Centralize 60 > output.txt` | **σχεδόν** ίδιο: οι κενές γραμμές γίνονται **60 κενά** (το `Centralize` κεντράρει και την κενή γραμμή), και η **τελευταία** κενή γραμμή χάνεται (27 γραμμές) |
| 3 | `Centralize 60 < input.txt \| Centralize 60 > output.txt` | ίδιο με **ένα** `Centralize 60`: κάθε γραμμή έχει ήδη 60 χαρακτήρες → `left = right = 0` |
| 4 | `Caps < input.txt \| Caps > output.txt` | ίδιο με **ένα** `Caps`: τα κεφαλαία μένουν κεφαλαία |
| 5 | `DoubleSpace < input.txt \| DoubleSpace > output.txt` | **όχι** ίδιο: μετά από κάθε γραμμή **3** κενές, εκτός από την τελευταία που έχει **1** (54 γραμμές) |

> [!example]- Γιατί η 5 δίνει 3 κενές γραμμές – και η τελευταία μόνο 1
> Μετά το πρώτο `DoubleSpace`: `L1`, `""`, `L2`, `""`, …, `L14`, `""`.
> Το δεύτερο `DoubleSpace` διαβάζει **και τις κενές γραμμές** (η `isEmpty()` είναι `false` όσο ακολουθεί κείμενο): `L1` → `L1` + 1 κενή, `""` → 2 κενές, άρα 3 κενές μετά το `L1`.
> Μετά το `L14` όμως απομένει μόνο `"\n"` – κενός χαρακτήρας – άρα `isEmpty()` = `true` και η τελευταία κενή γραμμή **δεν** διαβάζεται: το `L14` ακολουθείται από 1 κενή.
>
> Το ίδιο φαινόμενο εξηγεί τη χαμένη κενή γραμμή στο 2: το `Centralize` σταματά πριν την τελευταία κενή γραμμή του `DoubleSpace`.

> [!important] Ο κανόνας
> Δύο βήματα αντιμετατίθενται όταν το ένα δεν αλλάζει αυτό που κοιτάζει το άλλο. Τα `Caps` και `Centralize` αλλάζουν **χαρακτήρες**, όχι μήκη ή γραμμές – αντιμετατίθενται ελεύθερα. Το `DoubleSpace` **προσθέτει γραμμές**, που μετά τις επεξεργάζεται το `Centralize`. Ένα βήμα είναι **ταυτοδύναμο** (`f(f(x)) = f(x)`) αν δεύτερη εφαρμογή δεν αλλάζει τίποτα: `Caps` και `Centralize` ναι, `DoubleSpace` όχι.

## 7. Επαναχρησιμοποίηση και βιβλιοθήκες (VII-50)

> [!note] Επισήμανση αναφορικά με την επαναχρησιμοποίηση
> - Η επαναχρησιμοποίηση μέσω σωλήνωσης γίνεται σε **επίπεδο κλάσεων**, δηλαδή σε σχέση με την **ολότητα** της διεργασίας του κάθε προγράμματος. Επί της ουσίας, η σωλήνωση αφορά τις **συναρτήσεις `main`** των εμπλεκόμενων κλάσεων.
> - Τμήματα μίας κλάσης θα μπορούσαν να επαναχρησιμοποιηθούν σε άλλο πρόγραμμα, **νοουμένου ότι** δηλώνονται ως **`public`** και όχι ως `private` (απόκρυψη πληροφοριών).
> - Οι κλάσεις που συνιστούν **Βιβλιοθήκες** (π.χ. `Math`, `StdIn`, `StdOut`, `System.out`) αποτελούνται από ένα σύνολο ξεχωριστών επαναχρησιμοποιήσιμων συναρτήσεων, και επομένως μια Βιβλιοθήκη **δεν** είθισται να αντιπροσωπεύει μια προγραμματιστική διεργασία.
>   - Κατ' επέκταση, κλάσεις που είναι Βιβλιοθήκες **δεν** εμπλέκονται σε σωληνώσεις διεργασιών.
>   - Εξάλλου η `main` μιας Βιβλιοθήκης είθισται να έχει ως σκοπό τη **δοκιμή** των υπολοίπων συναρτήσεων.

| | Πρόγραμμα-φίλτρο (`Caps`) | Βιβλιοθήκη (`TextProcess`) |
|---|---|---|
| Μονάδα επαναχρησιμοποίησης | όλο το πρόγραμμα (η `main`) | κάθε `public` μέθοδος χωριστά |
| Πώς συνδυάζεται | σωλήνωση στο shell | κλήσεις μεθόδων μέσα σε Java |
| Βοηθητικές μέθοδοι | `private` | οι χρήσιμες `public`, οι βοηθητικές `private` |
| Ρόλος της `main` | κάνει τη δουλειά | δοκιμάζει τις μεθόδους |

## 8. Άσκηση: η βιβλιοθήκη `TextProcess` (VII-51)

Να κατασκευαστεί η βιβλιοθήκη `TextProcess` για την επεξεργασία κειμένου, με τις μεθόδους

```java
String Caps (String s)
String Centralize (String s, int N)
String DoubleSpace(String s)
```

```java
// main in TextProcess used for testing the other functions
public static void main(String[] args){
   int N = Integer.parseInt(args[0]);
   System.out.print(DoubleSpace(Centralize(Caps(StdIn.readAll()), N)));}

// Outside TextProcess
System.out.print(TextProcess.DoubleSpace(
                    TextProcess.Centralize(
                       TextProcess.Caps(StdIn.readAll()), N)));
```

> [!example]- Λύση (ελέγχθηκε)
> Η δυσκολία: οι μέθοδοι παίρνουν **όλο** το κείμενο σε ένα `String`, όχι γραμμή-γραμμή. Οι `Centralize` και `DoubleSpace` πρέπει να το **χωρίσουν σε γραμμές** μόνες τους.
> ```java
> public class TextProcess {
>
>    public static String Caps(String s) {
>       String rs = "";
>       for (int i = 0; i < s.length(); i++) {
>          char c = s.charAt(i);
>          if ('a' <= c && c <= 'z') rs += (char)(c - 'a' + 'A');
>          else rs += c;
>       }
>       return rs;
>    }
>
>    private static String blanks(int n) {
>       String s = "";
>       for (int i = 1; i <= n; i++) s += ' ';
>       return s;
>    }
>
>    public static String Centralize(String s, int N) {
>       String rs = "";
>       String[] lines = s.split("\n");
>       for (String line : lines) {
>          int len = line.length();
>          int left = (N - len) / 2;
>          int right = N - (len + left);
>          rs += blanks(left) + line + blanks(right) + "\n";
>       }
>       return rs;
>    }
>
>    public static String DoubleSpace(String s) {
>       String rs = "";
>       String[] lines = s.split("\n");
>       for (String line : lines) rs += line + "\n\n";
>       return rs;
>    }
>
>    public static void main(String[] args) {
>       int N = Integer.parseInt(args[0]);
>       System.out.print(DoubleSpace(Centralize(Caps(StdIn.readAll()), N)));
>    }
> }
> ```
> - Η κλήση `DoubleSpace(Centralize(Caps(…), N))` εκτελείται **από μέσα προς τα έξω**: πρώτα `Caps`, μετά `Centralize`, τελευταία `DoubleSpace` – ίδια σειρά με τη σωλήνωση.
> - Η `split("\n")` πετά τις κενές γραμμές στο **τέλος** του κειμένου (όπως και η `isEmpty()` στις διεργασίες), οπότε η έξοδος είναι ίδια με της σωλήνωσης.
> - Η `blanks` μένει `private`: είναι λεπτομέρεια υλοποίησης. Οι τρεις μέθοδοι είναι `public` για να καλούνται ως `TextProcess.Caps(…)`.
> - Χωρίς `split`: σάρωσε το κείμενο με `indexOf('\n', από)` και `substring` ([[01 - Το String ως Αφηρημένος Τύπος Δεδομένων|VI – 01]]).
> - Τα ονόματα με κεφαλαίο (`Caps`) είναι της διαφάνειας· η σύμβαση της Java θέλει μεθόδους με μικρό (`caps`).

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Prompts σε πρόγραμμα που διαβάζει από αρχείο ή σωλήνα → «σκουπίδια» στην έξοδο.
> - Νομίζεις ότι τα `< file`, `| java B` είναι ορίσματα στο `args`.
> - `java Average | java RandomSeq` → η `RandomSeq` δεν διαβάζει `StdIn`, θέλει **ορίσματα** (`args[0]` → `ArrayIndexOutOfBoundsException`). Σε σωλήνα, η είσοδος του επόμενου είναι **`StdIn`**, όχι `args`.
> - `> Data.txt` σβήνει ό,τι υπήρχε στο `Data.txt` – για προσθήκη `>>`.
> - `(char)` λείπει στο `c - 'a' + 'A'` → compile error (`int` σε `char`).
> - Στο `Centralize` νομίζεις ότι τα κενά μοιράζονται πάντα ίσα – με περιττή διαφορά πάει ένα παραπάνω **δεξιά**.
> - Νομίζεις ότι η σειρά σε μια σωλήνωση δεν μετράει ποτέ (ή πάντα) – εξαρτάται αν τα βήματα επηρεάζουν το ένα το άλλο (§6).
