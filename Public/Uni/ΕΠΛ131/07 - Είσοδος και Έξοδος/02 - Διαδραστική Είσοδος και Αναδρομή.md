# 02 - Διαδραστική Είσοδος και Αναδρομή

Είσοδος από το πληκτρολόγιο την ώρα που τρέχει το πρόγραμμα (`StdIn`, `Scanner`), και δύο τρόποι να «θυμηθούμε» άγνωστο πλήθος αριθμών για να τους τυπώσουμε ανάποδα: η **στοίβα του συστήματος** (αναδρομή) και ένας **πίνακας-στοίβα** (διαφάνειες VII-13 … VII-33).

## 1. Διαδραστική εισαγωγή δεδομένων (VII-13)

> [!note] Χαρακτηριστικά
> - **Standard Input channel**: το πληκτρολόγιο, **την ώρα που τρέχει** το πρόγραμμα (αντίθετα με τα ορίσματα, που δίνονται πριν ξεκινήσει).
> - Μέσω **διαλόγου** με τον χρήστη, με κατάλληλα μηνύματα για είσοδο: **user prompts** (`"Enter value: "`).
> - Δεν αφορά μόνο τη `main` αλλά **οποιαδήποτε** συνάρτηση.
> - **Δεν υπάρχει περιορισμός** στο πλήθος των στοιχείων (μόνο πρακτικοί περιορισμοί).
> - Βιβλιοθήκη **`StdIn`**, ή η **`Scanner`** της Java.

| | Ορίσματα γραμμής εντολής | Διαδραστική είσοδος |
|---|---|---|
| Πότε δίνονται | πριν ξεκινήσει το πρόγραμμα | ενώ τρέχει |
| Πλήθος | μικρό, γνωστό από `args.length` | απεριόριστο, άγνωστο εκ των προτέρων |
| Τύπος | πάντα `String` → `parseXxx` | `readInt()`, `readDouble()`, … επιστρέφουν έτοιμο τύπο |
| Ποιος τα διαβάζει | μόνο η `main` (μέσω `args`) | οποιαδήποτε μέθοδος |
| Τέλος | – | `Ctrl-D` (Linux/macOS) ή `Ctrl-Z, Enter` (Windows) |

## 2. Οι βιβλιοθήκες `StdIn` και `StdOut` (VII-14)

| `public class StdIn` | |
|---|---|
| `boolean isEmpty()` | `true` αν δεν υπάρχουν άλλες τιμές, αλλιώς `false` |
| `int readInt()` · `double readDouble()` · `long readLong()` · `boolean readBoolean()` · `char readChar()` | διαβάζει τιμή του τύπου |
| `String readString()` | διαβάζει την επόμενη «λέξη» |
| `String readLine()` | διαβάζει το υπόλοιπο της γραμμής |
| `String readAll()` | διαβάζει το υπόλοιπο του κειμένου |

| `public class StdOut` (ταυτόσημη με τη `System.out`) | |
|---|---|
| `void print(String s)` · `void println(String s)` · `void println()` · `void printf(String f, ...)` | όπως στη `System.out` |

> [!important] Στατικές μέθοδοι – `public static`
> Καλούνται με το **όνομα της κλάσης**: `StdIn.readInt()`. Δεν δημιουργούμε αντικείμενο `StdIn`. (Αντίθετα, οι `In`/`Out` της [[04 - Αρχεία με In και Out|04]] έχουν μεθόδους **αναφοράς**.) Τα πλήρη όρια κάθε μεθόδου (`readLine` μετά από `readInt`, τι θεωρείται «κενό») είναι στο [[03 - Standard Είσοδος και Επεξεργασία Αρχείων|VI – 03]].

> [!warning] ➕ Τι κάνει η `isEmpty()` στην πράξη
> Επιστρέφει `true` όταν **δεν απομένει καμία λέξη** – δηλαδή όταν απομένουν μόνο κενοί χαρακτήρες (κενά, tab, αλλαγές γραμμής) ή τίποτα. Στο πληκτρολόγιο **περιμένει** μέχρι ο χρήστης να γράψει κάτι ή να δώσει τέλος εισόδου (`Ctrl-D`). Αυτό έχει συνέπειες στις [[04 - Αρχεία με In και Out#3. Μέτρηση χαρακτήρων και η παγίδα της isEmpty (VII-56)|μετρήσεις χαρακτήρων]].

## 3. Η εναλλακτική: Scanner (VII-15)

```java
import java.util.Scanner;
Scanner inp = new Scanner(System.in);
```

| `Scanner` | Αντίστοιχο `StdIn` |
|---|---|
| `boolean hasNext()` | `!isEmpty()` |
| `int nextInt()` · `double nextDouble()` · `long nextLong()` · `boolean nextBoolean()` | `readInt()` · … |
| `String next()` | `readString()` |
| `String nextLine()` | `readLine()` |

> [!warning] ⚠️ Σημείωση για τη VII-15
> - Η διαφάνεια γράφει `Scanner inp = Scanner(System.in);` – λείπει το **`new`** (δεν κάνει compile). Σωστό: `new Scanner(System.in)`.
> - Δεν υπάρχει `nextString()`: η επόμενη λέξη διαβάζεται με **`next()`**.
> - Η `nextBoolean()` επιστρέφει `boolean`, όχι `Boolean`.
> - Η `Scanner` είναι μέθοδοι **αναφοράς** (καλούνται πάνω στο αντικείμενο `inp`), ενώ η `StdIn` στατικές.

> [!example]- Η Version 2 του μέσου όρου με `Scanner`
> ```java
> import java.util.Scanner;
>
> public class AverageScanner {
>    public static void main(String[] args) {
>       Scanner inp = new Scanner(System.in);
>       double sum = 0.0;
>       int cnt = 0;
>       System.out.print("Enter value: ");
>       while (inp.hasNext()) {
>          sum += inp.nextDouble();
>          cnt++;
>          System.out.print("Enter value: ");
>       }
>       System.out.println("\nAverage is " + sum/cnt);
>    }
> }
> ```
> Πλεονέκτημα: είναι μέρος της Java (δεν θέλει `StdIn.java`). Η `hasNextDouble()` θα σταματούσε (αντί να σκάσει) στην πρώτη μη αριθμητική λέξη.

## 4. Μέσος όρος – Version 2: διαδραστικά (VII-16 … VII-18)

```java
// Computing the average of a list of numbers
// Version 2: Input entered interactively

public class Average {

 public static void main(String[] args) {
  double sum = 0.0;
  int cnt = 0;
  System.out.print("Enter value: ");
  while (!StdIn.isEmpty()) {
     double value = StdIn.readDouble();
     sum += value;
     cnt++;
     System.out.print("Enter value: ");
  }
  double average = sum/cnt;
  System.out.println("\nAverage is " + average);
 }

}
```

Η VII-17 δείχνει την ίδια, πιο σύντομα: `sum += StdIn.readDouble();` (χωρίς τη βοηθητική μεταβλητή `value`).

```
$ java Average
Enter value: 45
Enter value: 67
Enter value: 2
Enter value: 109
Enter value: 200
Enter value: <Ctrl-d> or <Ctrl-Z, Enter>
Average is 84.6

$ java Average
Enter value: <Ctrl-d> or <Ctrl-Z, Enter>
Average is NaN
```

> [!tip] Γιατί το prompt τυπώνεται **δύο** φορές στον κώδικα
> Μία πριν τον βρόχο (για την πρώτη τιμή) και μία στο τέλος κάθε επανάληψης (για την επόμενη). Η `isEmpty()` **περιμένει** την πληκτρολόγηση, άρα το μήνυμα πρέπει να έχει τυπωθεί **πριν** την κλήση της. Γι' αυτό το τελευταίο `Enter value:` εμφανίζεται πάντα, ακόμη κι όταν ο χρήστης τελειώνει.

> [!warning] Παγίδες της διαδραστικής εισόδου (ελέγχθηκαν)
> - Είσοδος `1 abc 2` → `InputMismatchException` στο `abc`: η `isEmpty()` λέει «υπάρχει λέξη», αλλά η `readDouble()` δεν μπορεί να τη μετατρέψει.
> - Πολλές τιμές στην **ίδια γραμμή** (`45 67 2`) δουλεύουν κανονικά: η `readDouble()` διαβάζει λέξεις, όχι γραμμές. Απλώς τα prompts βγαίνουν «μαζεμένα».
> - Μόνο τέλος εισόδου → `cnt = 0` → `NaN` (όπως στη Version 1).
> - `\nAverage` – το `\n` στην αρχή υπάρχει για να μην κολλήσει το αποτέλεσμα στο τελευταίο `Enter value: `.

## 5. Αντίστροφη σειρά με αναδρομή (VII-19 … VII-30)

Πρόβλημα: διάβασε αριθμούς μέχρι το `0` και τύπωσέ τους **ανάποδα** – χωρίς να ξέρεις από πριν πόσοι είναι, και **χωρίς πίνακα**.

**Ψευδοκώδικας**
```
rev(i):
    ζήτα και διάβασε τον αριθμό n (τον i-οστό)
    αν n = 0:
        τύπωσε "The numbers in reverse order are:"
        επίστρεψε
    rev(i + 1)                      // πρώτα όλοι οι επόμενοι …
    τύπωσε "Number i is n"          // … μετά ο δικός μου
```

```java
// Reversing a list of numbers entered interactively

public class Reverse {

 public static void rev(int i) {
   System.out.print("Enter number " + i + ": ");
   int n = StdIn.readInt();
   if (n==0) {
    System.out.println(
        "The numbers in reverse order are:");
    return; }
   rev(i+1);
   System.out.println("Number " + i + " is " + n);
 }

 public static void main(String[] args){
   System.out.println("Enter the sequence of numbers to be reversed, terminating with 0");
   rev(1);
 }
}
```

```
$ java Reverse
Enter the sequence of numbers to be reversed,
terminating with 0
Enter number 1: 34
Enter number 2: 89
Enter number 3: 56
Enter number 4: 12
Enter number 5: 0
The numbers in reverse order are:
Number 4 is 12
Number 3 is 56
Number 2 is 89
Number 1 is 34
```

> [!note] ➕ Αναδρομή
> Μια μέθοδος είναι **αναδρομική** όταν καλεί τον εαυτό της (`rev` καλεί `rev`). Χρειάζεται:
> 1. **Βασική περίπτωση** που σταματά χωρίς νέα κλήση – εδώ `n == 0` → `return`.
> 2. **Πρόοδο** προς τη βασική περίπτωση – εδώ κάθε κλήση **καταναλώνει** έναν αριθμό από την είσοδο.
>
> Η κανονική θεωρία της αναδρομής είναι στο §2.3 του βιβλίου· εδώ τη χρησιμοποιούμε για να δούμε τη **στοίβα του συστήματος**.

### Η στοίβα του συστήματος (System Stack, VII-21 … VII-30)

Κάθε κλήση μεθόδου παίρνει ένα **πλαίσιο** (frame) στη στοίβα με τις **δικές της** τοπικές μεταβλητές (`i`, `n`). Οι διαφάνειες δείχνουν δύο φάσεις:

![[Διαδραστική - Στοίβα Αναδρομής.png|800]]

| Φάση | Τι γίνεται | Στοίβα (κορυφή δεξιά) |
|---|---|---|
| **Pushing in function calls** | κάθε `rev` διαβάζει ένα `n` και καλεί την επόμενη | `rev(1)` → `rev(1) rev(2)` → … → `rev(1) … rev(5)` |
| βασική περίπτωση | `rev(5)` διαβάζει `0`, τυπώνει τον τίτλο, `return` | `rev(1) rev(2) rev(3) rev(4)` |
| **Popping the stack** | επιστρέφει η `rev(5)`, η `rev(4)` συνεχίζει μετά το `rev(i+1)` και τυπώνει `Number 4 is 12`, επιστρέφει, … | `rev(1) rev(2) rev(3)` → … → **Empty** |

> [!important] Γιατί βγαίνουν ανάποδα
> Η `println` βρίσκεται **μετά** την αναδρομική κλήση. Άρα κάθε κλήση τυπώνει μόνο **αφού τελειώσουν όλες οι επόμενες**. Η τελευταία που μπήκε στη στοίβα βγαίνει πρώτη: **LIFO** (Last In, First Out). Ο πίνακας «υπάρχει», απλώς τον κρατά η στοίβα: κάθε πλαίσιο έχει τη δική του τιμή `n`.

> [!example]- «Μοιάζει ίδιο αλλά δεν είναι»: println **πριν** την αναδρομή (ελέγχθηκε)
> ```java
> if (n==0) { System.out.println("The numbers in reverse order are:"); return; }
> System.out.println("Number " + i + " is " + n);   // πρώτα τυπώνω …
> rev(i+1);                                          // … μετά καλώ
> ```
> Με είσοδο `5 7 0`:
> ```
> Enter number 1: Number 1 is 5
> Enter number 2: Number 2 is 7
> Enter number 3: The numbers in reverse order are:
> ```
> Οι αριθμοί βγαίνουν στην **αρχική** σειρά, και ο τίτλος στο **τέλος**. Η θέση της εντολής σε σχέση με την αναδρομική κλήση καθορίζει τη σειρά.

> [!warning] Παγίδες του `Reverse` (ελέγχθηκαν)
> - Είσοδος `5 7 0 9`: το `9` **δεν διαβάζεται ποτέ** – η είσοδος σταματά στο `0`. Έξοδος: `Number 2 is 7`, `Number 1 is 5`.
> - Πρώτος αριθμός `0` → τυπώνεται μόνο ο τίτλος, χωρίς αριθμούς (VII-20).
> - Τέλος εισόδου (`Ctrl-D`) **χωρίς** `0` → `NoSuchElementException` στην `readInt()`: λείπει η βασική περίπτωση.
> - Πολλές χιλιάδες αριθμοί → `StackOverflowError`: κάθε αριθμός κρατά ένα πλαίσιο στη στοίβα μέχρι το τέλος.
> - Το `0` είναι **φρουρός** (sentinel): δεν είναι δεδομένο, άρα δεν μπορείς να αντιστρέψεις μια ακολουθία που περιέχει το 0.

## 6. Αντίστροφη σειρά με πίνακα ως στοίβα (VII-31 … VII-33)

Η ίδια δουλειά χωρίς αναδρομή: κάθε νέος αριθμός μπαίνει στη **θέση 0** ενός πίνακα που μεγαλώνει κατά ένα.

```java
// Enter a list of numbers interactively and store it
// incrementally and in reverse order in a table

public class Reverse {

  // Treating xs as a stack
  public static int[] add(int[] xs, int x) {
   if (xs==null){
      xs = new int[1];
      xs[0] = x;
   }
   else {
      int[] temp = xs;
      xs = new int[temp.length + 1];
      xs[0] = x;
      for (int i = 0; i < temp.length; i++)
           xs[i+1] = temp[i];
   }
   return xs;
  }

  public static void main(String[] args) {
    int []xs = null;
    int num;
    do {
      System.out.print("Enter number: ");
      num = StdIn.readInt();
      if (num != 0) xs = add(xs,num);
    } while (num != 0);

    if (xs != null){
     System.out.println("The numbers in reverse order are:");
     for (int x : xs) System.out.println(x);
    }
  }
}
```

```
$ java Reverse
Enter number: 34
Enter number: 89
Enter number: 56
Enter number: 12
Enter number: 0
The numbers in reverse order are:
12
56
89
34
```

![[Διαδραστική - Πίνακας ως Στοίβα.png|800]]

> [!important] Τι πρέπει να προσέξεις στην `add`
> - Ο πίνακας **δεν μεγαλώνει**: φτιάχνεται **νέος** με `length + 1` και αντιγράφονται τα παλιά (το μέγεθος ενός πίνακα μένει σταθερό, [[01 - Πίνακες στη Java|IV – 01]]). Γι' αυτό η `add` **επιστρέφει** τον νέο πίνακα και η κλήση είναι `xs = add(xs, num);`.
> - Η ανάθεση `xs = new int[…]` **μέσα** στη μέθοδο αλλάζει μόνο την τοπική παράμετρο, όχι το `xs` της `main` ([[03 - Πίνακες ως Αναφορές και Μέθοδοι|IV – 03]]). Χωρίς το `xs =` στη `main`, το `xs` μένει `null` και δεν τυπώνεται τίποτα.
> - Το `null` σημαίνει «δεν υπάρχει πίνακας ακόμη» – διαφορετικό από κενό πίνακα (`new int[0]`).
> - Ίδια ιδέα με την `add` του `TabLib` για `String[]` ([[06 - Πίνακες με Στοιχεία Συμβολοσειρές|VI – 06]]).

> [!tip] Η διαφορά των δύο λύσεων
>
> | | Αναδρομή (VII-19) | Πίνακας (VII-31) |
> |---|---|---|
> | Πού αποθηκεύονται οι αριθμοί | στα πλαίσια της στοίβας | σε πίνακα στον σωρό (heap) |
> | Σειρά εισόδου/εξόδου | διαβάζει όλους, τυπώνει στην επιστροφή | διαβάζει όλους, μετά τυπώνει |
> | Βρόχος | κανένας – η αναδρομή κάνει την επανάληψη | `do-while` (ο αριθμός διαβάζεται **πριν** ελεγχθεί) |
> | Τα δεδομένα μετά | χάνονται | μένουν στο `xs` για άλλη χρήση |
> | Κόστος | N κλήσεις | ≈ N²/2 αντιγραφές (κάθε `add` αντιγράφει όλο τον πίνακα) |

> [!example]- Κανονική (όχι αντίστροφη) σειρά: προσθήκη στο τέλος (ελέγχθηκε)
> ```java
> public static int[] append(int[] xs, int x) {
>    int len = (xs == null) ? 0 : xs.length;
>    int[] nxs = new int[len + 1];
>    for (int i = 0; i < len; i++) nxs[i] = xs[i];
>    nxs[len] = x;                  // στο ΤΕΛΟΣ, όχι στη θέση 0
>    return nxs;
> }
> ```
> Με `34 89 56 0` τυπώνει `34 89 56`. Η μόνη αλλαγή από την `add`: πού μπαίνει το νέο στοιχείο. Πίνακας με προσθήκη και αφαίρεση στην **ίδια** άκρη = **στοίβα** (stack)· προσθήκη στη μία και αφαίρεση στην άλλη = **ουρά** (queue).

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - `Scanner inp = Scanner(System.in);` χωρίς `new` (όπως στη VII-15) · `inp.nextString()` δεν υπάρχει.
> - Prompt **μετά** την `isEmpty()` → ο χρήστης βλέπει το μήνυμα αφού έχει ήδη γράψει.
> - `add(xs, num);` χωρίς `xs =` → καμία αλλαγή.
> - `for (int x : xs)` όταν `xs == null` → `NullPointerException` (γι' αυτό το `if (xs != null)`).
> - `while` αντί `do-while` στο `Reverse` με πίνακα: το `num` δεν έχει τιμή πριν τον πρώτο έλεγχο (compile error για τοπική μεταβλητή).
> - Αναδρομή χωρίς βασική περίπτωση (ή χωρίς `0` στην είσοδο) → εξαίρεση.
> - Σύγχυση της σειράς: η εντολή **μετά** την αναδρομική κλήση εκτελείται στην **επιστροφή**, σε αντίστροφη σειρά.
