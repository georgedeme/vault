# 01 - Δομή Κλάσης, Κατασκευαστές και Μέθοδοι

Πώς ορίζουμε δικούς μας τύπους δεδομένων (κλάσεις) στη Java: <span class="hl-blue">πεδία (fields)</span>, <span class="hl-blue">κατασκευαστές (constructors)</span>, ο τελεστής `new`, οι μέθοδοι, το Java style και η <span class="hl-blue">υπερφόρτωση (overloading)</span> (διαφάνειες XII-1, XII-2, XII-18 … XII-28).

> «Δημιουργώντας Αντικείμενα — Ορίζοντας τα πεδία και τις μεθόδους αναφοράς τους» (XII-1)

## 1. Ανατομία μιας κλάσης (XII-2, XII-46)

Μια κλάση στη Java ορίζει έναν νέο τύπο δεδομένων, δηλαδή το **σύνολο των τιμών** (δεδομένα / κατάσταση) και τις **λειτουργίες** (συμπεριφορά) που επιτρέπονται πάνω σε αυτές:

```java
public class ClassName {
    // 1. Πεδία δεδομένων (fields / instance variables) — είθισται private
    // 2. Κατασκευαστές (constructors) — αρχικοποιούν το νέο αντικείμενο
    // 3. Μέθοδοι (methods) — λειτουργίες πάνω στο αντικείμενο
}
```

> [!note] Βασική αρχή (XII-2)
> **Τα πεδία είθισται να είναι ιδιωτικά (`private`)**, ώστε να μην τροποποιούνται ανεξέλεγκτα έξω από την κλάση (βλ. [[02 - Static, Ενθυλάκωση και this#4. Ενθυλάκωση (Encapsulation) και public vs private (XII-36 … XII-39)|Ενθυλάκωση]]).

> [!warning] ⚠️ Σημείωση (XII-2)
> Η διαφάνεια XII-2 γράφει `public class Object { ... }` ως σχηματικό όνομα. Στη Java η `java.lang.Object` είναι η προϋπάρχουσα υπερκλάση όλων των κλάσεων, οπότε στην πράξη **δεν** ονομάζουμε δική μας κλάση `Object`.

## 2. Κατασκευαστές — Constructors (XII-18, XII-24 … XII-26)

> [!note] Ορισμός & κανόνες (XII-18)
> Ο <span class="hl-blue">κατασκευαστής (constructor)</span> είναι μια ειδική μέθοδος που εκτελείται αυτόματα όταν δημιουργείται ένα αντικείμενο με `new`:
> 1. Το όνομά του είναι **ακριβώς ίδιο** με το όνομα της κλάσης (`ClassName`).
> 2. **Ποτέ δεν επιστρέφει τίποτα** — **ούτε `void`**!
> 3. Συνήθως αρχικοποιεί τα πεδία δεδομένων του αντικειμένου (**instance variables**).
> 4. Όλες οι κλάσεις χρειάζονται **τουλάχιστον έναν** κατασκευαστή.

### Ο προεπιλεγμένος (default) κατασκευαστής (XII-18, XII-24)

- Εάν ο προγραμματιστής **ΔΕΝ ορίσει ΚΑΝΕΝΑΝ** κατασκευαστή, η Java προσθέτει αυτόματα έναν **default no-args constructor**:
  ```java
  ClassName() { }
  ```
  ο οποίος δεσμεύει μνήμη και θέτει τα πεδία στις εξ ορισμού (default) τιμές τους (`0` για αριθμούς, `false` για `boolean`, `'\u0000'` για `char`, `null` για αναφορές).

> [!warning] ➕ Παγίδα εξετάσεων: πότε «εξαφανίζεται» ο default constructor!
> Μόλις ορίσεις **έστω και έναν** κατασκευαστή με ορίσματα (π.χ. `public Fraction(int p, int q)`), η Java **παύει** να παρέχει τον κενό default κατασκευαστή! Αν τότε γράψεις `new Fraction()` χωρίς να έχεις ορίσει ρητά `public Fraction()`, προκύπτει **σφάλμα μεταγλώττισης**.
>
> Επίσης, αν κατά λάθος βάλεις `void` (`public void Fraction()`), η Java το θεωρεί **απλή μέθοδο** με το όνομα της κλάσης, **όχι** κατασκευαστή!

### Υπερφόρτωση κατασκευαστών & Copy Constructor — Παράδειγμα `Fraction` (XII-24, XII-25)

Μια κλάση μπορεί να έχει πολλούς κατασκευαστές (**overloaded constructors**), αρκεί να διαφέρουν στον **αριθμό** ή/και στους **τύπους** των ορισμάτων:

```java
public class Fraction {
    private int num, denom;

    public Fraction() {                 // "No-args" constructor
        num = 0;
        denom = 1;
    }

    public Fraction(int n) {            // 1 όρισμα: ακέραιος n/1
        num = n;
        denom = 1;
    }

    public Fraction(int p, int q) {     // 2 ορίσματα: p/q απλοποιημένο
        num = p;
        denom = q;
        reduce();
    }

    public Fraction(Fraction other) {   // Copy constructor (αντιγραφέας-κατασκευαστής)
        num = other.num;
        denom = other.denom;
    }
}
```

> [!tip] Copy Constructor (αντιγραφέας-κατασκευαστής)
> Δέχεται ένα άλλο αντικείμενο της **ίδιας κλάσης** και δημιουργεί ένα **νέο, ανεξάρτητο** αντίγραφο με τα ίδια δεδομένα. Παρατήρησε ότι μέσα στον κατασκευαστή της `Fraction` έχουμε άμεση πρόσβαση στα `other.num` και `other.denom` παρόλο που είναι `private` (βλ. [[02 - Static, Ενθυλάκωση και this#5. Πρόσβαση σε private πεδία άλλου αντικειμένου (XII-39)|02 §5]]).

### Αλυσίδωση κατασκευαστών με `this(...)` (XII-26)

Διαφορετικοί κατασκευαστές της ίδιας κλάσης μπορούν να καλούν ο ένας τον άλλον με `this(...)` για να αποφεύγουμε **διπλότυπο κώδικα**:

```java
public class Fraction {
    ...
    public Fraction(int n) {
        this(n, 1);           // καλεί τον Fraction(int p, int q)
    }

    public Fraction(int p, int q) {
        num = p;
        denom = q;
        reduce();
    }
}
```

> [!important] ➕ Κανόνες της `this(...)`
> - Η κλήση `this(...)` **πρέπει να είναι η πρώτη εντολή** στο σώμα του κατασκευαστή (αλλιώς compile error: `call to this must be first statement in constructor`).
> - Δεν επιτρέπεται κύκλος κλήσεων (π.χ. `A()` καλεί `A(int)` που καλεί `A()`) → σφάλμα μεταγλώττισης (`recursive constructor invocation`).
> - Δες επίσης τη χρήση `this(3);` στον κατασκευαστή της `TicTacToe` (XII-12, [[04 - Πλήρη Παραδείγματα - DeckObj, GLife και TicTacToe#3. Αντικείμενο TicTacToe (XII-11 … XII-17)|04 §3]]).

## 3. Ο τελεστής `new` και η συλλογή απορριμμάτων (XII-27, XII-28)

Οι κατασκευαστές καλούνται **πάντα** με τον τελεστή `new`:

```java
Fraction f1 = new Fraction();       // 0 / 1
Fraction f2 = new Fraction(5);      // 5 / 1
Fraction f3 = new Fraction(4, 6);   // 2 / 3 (λόγω reduce())
Fraction f4 = new Fraction(f3);     // 2 / 3 (νέο αντικείμενο, αντίγραφο του f3)
```

Πρέπει να δημιουργήσουμε ένα αντικείμενο πριν το χρησιμοποιήσουμε (XII-28):

```java
Fraction f;                    // δήλωση μεταβλητής αναφοράς
f = new Fraction(2, 3);        // το f δείχνει τώρα σε έγκυρο αντικείμενο (2/3)
f = new Fraction(3, 4);        // το f δείχνει σε ΝΕΟ αντικείμενο (3/4)
                               // το παλιό (2/3) δεν έχει αναφορές → "garbage-collected"
```

> [!warning] ⚠️ Σημείωση (XII-28)
> Η διαφάνεια XII-28 σχολιάζει δίπλα στο `Fraction f;` ότι **`f is set to null`**.
> - Αυτό ισχύει **μόνο αν το `f` είναι πεδίο κλάσης** (instance ή static variable), όπου η Java το αρχικοποιεί αυτόματα σε `null`.
> - Αν το `f` είναι **τοπική μεταβλητή** μέσα σε μέθοδο (π.χ. στη `main`), **δεν** αρχικοποιείται αυτόματα — αν επιχειρήσεις να το χρησιμοποιήσεις πριν του αναθέσεις τιμή, παίρνεις **σφάλμα μεταγλώττισης** (`variable f might not have been initialized`). Αν του αναθέσεις ρητά `f = null;` και καλέσεις μέθοδο `f.toString()`, τότε παίρνεις **`NullPointerException`** στο χρόνο εκτέλεσης.

## 4. Ανασκόπηση μεθόδων & Java Style (XII-19 … XII-21)

Κάθε μέθοδος ορίζεται **πάντα μέσα σε μια κλάση** και αποτελείται από **επικεφαλίδα (Header)** και **σώμα (Body)**:

```java
public [ή private ή protected] returnType methodName(type1 name1, ..., typeN nameN) {
    // Body
}
```

| Στοιχείο | Κανόνας (XII-19, XII-20) |
|---|---|
| Προσδιοριστής πρόσβασης | `public`, `private` ή `protected` (συνήθως `public` για τη διεπαφή) |
| Τύπος επιστροφής (`returnType`) | Οποιοσδήποτε βασικός τύπος ή τύπος κλάσης (αντικείμενο), ή `void` (δεν επιστρέφει τίποτα) |
| Παράμετροι (`formal parameters`) | Οποιοσδήποτε τύπος δεδομένων ή αντικείμενο. Άδειες παρενθέσεις `()` = δεν παίρνει ορίσματα |

### Java Style για ονόματα μεθόδων (XII-21)

- Ξεκινούν με **μικρό** γράμμα και κάθε επόμενη λέξη με **κεφαλαίο** (`camelCase`).
- Συχνά ακούγονται σαν **ρήματα** (`move`, `shuffle`, `evolve`).
- Μέθοδος που **επιστρέφει** την τιμή ενός πεδίου (accessor / getter) αρχίζει με **`get`**: `getWidth()`, `getX()`.
- Μέθοδος που **θέτει** τιμή σε ένα πεδίο (mutator / setter) αρχίζει με **`set`**: `setLocation(...)`, `setText(...)`.

## 5. Υπερφόρτωση Μεθόδων — Overloaded Methods (XII-22, XII-23)

> [!note] Ορισμός (XII-22)
> Μέθοδοι της **ΙΔΙΑΣ** κλάσης που έχουν το **ίδιο όνομα** αλλά **διαφορετικό αριθμό ή/και τύπους ορισμάτων** ονομάζονται <span class="hl-blue">overloaded methods</span>.

Χρησιμοποιούνται για εναλλακτικές εκδοχές της ίδιας ενέργειας:

```java
public void move(int x, int y)       { ... }
public void move(double x, double y) { ... }
public void move(Point p)            { ... }

public Fraction add(int n)           { ... }
public Fraction add(Fraction other)  { ... }
```

Ο μεταγλωττιστής τις αντιμετωπίζει σαν **εντελώς διαφορετικές μεθόδους** και αποφασίζει κατά τη **μεταγλώττιση** ποια θα καλέσει με βάση τον αριθμό και τον τύπο των ορισμάτων (XII-23):

```java
Circle circle = new Circle(5);
circle.move(50, 100);                  // καλεί move(int, int)
Point center = new Point(50, 100);
circle.move(center);                   // καλεί move(Point)
```

> [!warning] ➕ Τι ΔΕΝ αποτελεί overloading (κλασική παγίδα!)
> Η υπογραφή (signature) για το overloading αποτελείται **μόνο** από το όνομα και τη λίστα τύπων των παραμέτρων. **Δεν** αρκεί:
> - διαφορετικός **τύπος επιστροφής** (`int f(int x)` και `double f(int x)` → compile error: `method f(int) is already defined`),
> - διαφορετικά **ονόματα παραμέτρων** (`void move(int x, int y)` και `void move(int a, int b)` → compile error),
> - διαφορετικό **`public`/`private`** (`public void f()` και `private void f()` → compile error).

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Προσθήκη `void` στον κατασκευαστή (`public void Fraction()`): μετατρέπεται σε κανονική μέθοδο, όχι σε κατασκευαστή.
> - Κλήση `new ClassName()` όταν έχεις ορίσει κατασκευαστή με ορίσματα αλλά **όχι** no-args κατασκευαστή → compile error.
> - Τοποθέτηση της `this(...)` ως δεύτερη εντολή στον κατασκευαστή → compile error.
> - Χρήση μεταβλητής αντικειμένου πριν το `new` (`Fraction f; f.toString();`) → compile error (τοπική) ή `NullPointerException` (πεδίο `null`).
> - Προσπάθεια overloading μόνο με αλλαγή του `returnType` (π.χ. `int f()` και `double f()`).
