# 03 - Αναφορές, Ψευδώνυμα και Πέρασμα δια Τιμής

Πώς αποθηκεύονται τα αντικείμενα στη μνήμη, τι σημαίνει <span class="hl-blue">αναφορά (reference)</span> και <span class="hl-blue">ψευδώνυμο (aliasing)</span>, πώς δεσμεύουμε **συστοιχίες από αντικείμενα** (`BouncingBalls`, `Charge[]`), και πώς λειτουργεί το **πέρασμα δια τιμής (`PassByValue`)** (διαφάνειες XII-48, XII-56 … XII-69, XII-73).

## 1. Παράδειγμα: Μπάλα Αναπήδησης `Ball` (XII-56)

Μια μπάλα που κινείται και αναπηδά μέσα στο μοναδιαίο τετράγωνο $[0, 1] \times [0, 1]$:

```java
public class Ball {
    private double rx, ry;          // θέση (instance variables)
    private double vx, vy;          // ταχύτητα
    private double radius;          // ακτίνα

    public Ball() {
        rx = ry = 0.5;
        vx     = 0.015 - Math.random() * 0.03;   // [-0.015, +0.015)
        vy     = 0.015 - Math.random() * 0.03;
        radius = 0.01  + Math.random() * 0.01;   // [0.01, 0.02)
    }

    public void move() {
        if ((rx + vx > 1.0) || (rx + vx < 0.0)) vx = -vx;   // αναπήδηση (bounce)
        if ((ry + vy > 1.0) || (ry + vy < 0.0)) vy = -vy;
        rx = rx + vx;
        ry = ry + vy;
    }

    public void draw() {
        StdDraw.filledCircle(rx, ry, radius);
    }
}
```

## 2. Αναφορές Αντικειμένου — Ίχνος Μνήμης & Aliasing (XII-57 … XII-64)

Τα ονόματα των μεταβλητών αντικειμένων **δεν** περιέχουν τα ίδια τα δεδομένα, αλλά τη **διεύθυνση μνήμης (αναφορά)** όπου βρίσκονται τα πεδία του αντικειμένου.

Ας παρακολουθήσουμε τον κώδικα των διαφανειών XII-57 … XII-64 σε κύρια μνήμη 64-bit (διευθύνσεις `C0` … `CC`, όπου κάθε `double` καταλαμβάνει μία θέση):

```java
Ball b1 = new Ball();   // 1. δεσμεύει C0..C4, b1 = C0
b1.move();              // 2. ενημερώνει rx, ry στα C0, C1
b1.move();              // 3. ενημερώνει rx, ry στα C0, C1

Ball b2 = new Ball();   // 4. δεσμεύει C7..CB, b2 = C7
b2.move();              // 5. ενημερώνει rx, ry στα C7, C8

b2 = b1;                // 6. ALIASING! b2 παίρνει τη διεύθυνση C0 (C7..CB → garbage!)
b2.move();              // 7. μετακινεί το αντικείμενο στη C0 → αλλάζει ΚΑΙ το b1!
```

| Βήμα | Εντολή | `b1` | `b2` | Αντικείμενο `C0..C4` `(rx, ry)` | Αντικείμενο `C7..CB` `(rx, ry)` |
|---|---|---|---|---|---|
| 1 | `Ball b1 = new Ball();` | `C0` | — | `(0.50, 0.50)` με `vx=0.05, vy=0.01` | — |
| 2 | `b1.move();` | `C0` | — | `(0.55, 0.51)` | — |
| 3 | `b1.move();` | `C0` | — | `(0.60, 0.52)` | — |
| 4 | `Ball b2 = new Ball();` | `C0` | `C7` | `(0.60, 0.52)` | `(0.50, 0.50)` με `vx=0.07, vy=0.04` |
| 5 | `b2.move();` | `C0` | `C7` | `(0.60, 0.52)` | `(0.57, 0.54)` |
| 6 | **`b2 = b1;`** | `C0` | **`C0`** | `(0.60, 0.52)` | *ορφανό → Garbage Collector!* |
| 7 | **`b2.move();`** | `C0` | `C0` | **`(0.65, 0.53)`** (άλλαξε και για το `b1`!) | *(απρόσιτο)* |

![[Αντικείμενα - Αναφορές Μνήμης και Aliasing.png|800]]

> [!important] Ψευδώνυμα (Aliasing) & Garbage Collector (XII-63, XII-64)
> - Μετά το `b2 = b1;`, οι μεταβλητές `b1` και `b2` είναι <span class="hl-red">ψευδώνυμα (aliases)</span>: δείχνουν στο **ίδιο** αντικείμενο στη μνήμη (`C0`). Κάθε αλλαγή μέσω του `b2` φαίνεται αμέσως και μέσω του `b1`.
> - Τα δεδομένα στις διευθύνσεις `C7..CB` δεν έχουν πλέον καμία αναφορά που να δείχνει σε αυτά — παραδίδονται στον αυτόματο **συλλέκτη απορριμμάτων (garbage collector / abstract bit recycler)** για ανακύκλωση μνήμης.
> - **Σύγκριση με `==`**: ο τελεστής `b1 == b2` συγκρίνει **διευθύνσεις**, όχι περιεχόμενα! Πριν το `b2 = b1;` είναι `false` (ακόμα κι αν δύο μπάλες είχαν ακριβώς ίδια πεδία), ενώ μετά γίνεται `true`.

## 3. Συστοιχίες από Αντικείμενα — Δέσμευση σε 2 Βήματα (XII-48, XII-65)

Όταν φτιάχνουμε έναν πίνακα αντικειμένων (π.χ. `Ball[]` ή `Charge[]`), απαιτούνται **δύο ξεχωριστά βήματα δέσμευσης μνήμης**:

1. **Δέσμευση του πίνακα αναφορών**: `Ball[] balls = new Ball[N];` — δημιουργεί `N` θέσεις, **όλες αρχικά `null`** (δεν έχει κληθεί ακόμα κανένας κατασκευαστής `Ball()`!).
2. **Δέσμευση κάθε ξεχωριστού αντικειμένου** σε βρόχο: `balls[i] = new Ball();`.

```java
// Παράδειγμα BouncingBalls (XII-65)
public class BouncingBalls {
    public static void main(String[] args) {
        int N = Integer.parseInt(args[0]);
        Ball balls[] = new Ball[N];                 // Βήμα 1: πίνακας από N null αναφορές
        for (int i = 0; i < N; i++)
            balls[i] = new Ball();                  // Βήμα 2: δημιουργία κάθε αντικειμένου

        while (true) {                              // Επαναληπτικός βρόχος για το κινούμενο σχέδιο
            StdDraw.clear();
            for (int i = 0; i < N; i++) {
                balls[i].move();
                balls[i].draw();
            }
            StdDraw.show(20);
        }
    }
}
```

> [!warning] ➕ Κλασική παγίδα εξετάσεων: `NullPointerException` σε πίνακα αντικειμένων
> Αν παραλείψεις το Βήμα 2 (`for ... balls[i] = new Ball();`) και καλέσεις αμέσως `balls[0].move();`, το πρόγραμμα **μεταγλωττίζεται κανονικά** αλλά σκάει στον χρόνο εκτέλεσης με **`NullPointerException`** γιατί `balls[0]` είναι `null`!

### Επεκταμένη `Ball`: Χρώμα (`Color`) και Συγκρούσεις (XII-67 … XII-69)

Στις διαφάνειες XII-67 … XII-69 η `Ball` επεκτείνεται με δύο σημαντικές ιδέες:
1. **Σύνθεση αντικειμένων (Composition)**: προστίθεται πεδίο τύπου αντικειμένου `private Color color;` που αρχικοποιείται με τυχαίο RGB χρώμα:
   ```java
   color = new Color((int)(Math.random()*256), (int)(Math.random()*256), (int)(Math.random()*256));
   ```
2. **Μέθοδος `collisionMove(Ball[] bs, int n)`**: δέχεται τον πίνακα όλων των μπαλών και τον δείκτη `n` της τρέχουσας μπάλας. Επειδή είμαστε μέσα στην κλάση `Ball`, η μέθοδος διαβάζει απευθείας τα `private` πεδία `bs[i].rx` και `bs[i].ry` των άλλων μπαλών:
   ```java
   public boolean collisionMove(Ball[] bs, int n) {
       boolean collision = false;
       for (int i = 0; i < bs.length; i++) {
           if (i != n)
               if (rx == bs[i].rx && ry == bs[i].ry) {
                   vx = -vx; vy = -vy; rx = rx + vx; ry = ry + vy;
                   collision = true;
               }
       }
       return collision;
   }
   ```

> [!warning] ⚠️ Σημείωση (XII-68)
> Η συνθήκη `rx == bs[i].rx && ry == bs[i].ry` έχει δύο αδυναμίες στην πράξη: (α) συγκρίνει `double` με `==` (σφάλματα κινητής υποδιαστολής) και (β) ελέγχει αν ταυτίζονται τα **κέντρα**, όχι αν ακουμπάνε οι κύκλοι! Ρεαλιστικός έλεγχος σύγκρουσης δύο κύκλων είναι η Ευκλείδεια απόσταση: `Math.hypot(rx - bs[i].rx, ry - bs[i].ry) <= radius + bs[i].radius`.

## 4. Πέρασμα δια τιμής — `PassByValue` (XII-73)

> [!important] Ο χρυσός κανόνας της Java (XII-73)
> Στη Java **ΟΛΑ** τα ορίσματα περνάνε **πάντα δια τιμής (pass by value)**:
> - **Βασικοί τύποι (`int`, `double`, `boolean`, `char`)**: περνά **αντίγραφο της τιμής** → καμία αλλαγή μέσα στη μέθοδο δεν επηρεάζει τη μεταβλητή του καλούντα.
> - **Αντικείμενα & πίνακες**: περνά **αντίγραφο της αναφοράς (διεύθυνσης)** →
>   - αν τροποποιήσεις το **περιεχόμενο** του αντικειμένου/πίνακα (`b[3] = 7;`), η αλλαγή **φαίνεται** στον καλούντα!
>   - αν ανακατευθύνεις την **ίδια την παράμετρο** σε άλλο αντικείμενο (`c = "seven";` ή `b = new int[5];`), η μεταβλητή του καλούντα **ΔΕΝ** αλλάζει!

```java
public class PassByValue {
    static void update(int a, int[] b, String c) {
        a    = 7;           // αλλάζει ΜΟΝΟ το τοπικό αντίγραφο a
        b[3] = 7;           // τροποποιεί το περιεχόμενο του ΚΟΙΝΟΥ πίνακα b!
        c    = "seven";     // αλλάζει ΜΟΝΟ πού δείχνει η τοπική αναφορά c
        StdOut.println(a + " " + b[3] + " " + c);
    }

    public static void main(String[] args) {
        int a = 3;
        int[] b = { 0, 1, 2, 3, 4, 5 };
        String c = "three";
        StdOut.println(a + " " + b[3] + " " + c);   // 3 3 three
        update(a, b, c);                            // 7 7 seven
        StdOut.println(a + " " + b[3] + " " + c);   // 3 7 three
    }
}
```

![[Αντικείμενα - Πέρασμα δια Τιμής.png|800]]

> [!example]- ➕ Τι θα γινόταν αν γράφαμε `b = new int[]{9, 9, 9, 9};` μέσα στην `update`;
> Τότε η τοπική παράμετρος `b` θα έδειχνε στον νέο πίνακα `{9, 9, 9, 9}`, ενώ ο πίνακας της `main` θα έμενε **ανέπαφος** (`b[3]` θα παρέμενε `3`). Ακριβώς για τον ίδιο λόγο, δεν μπορείς να γράψεις στη Java μια μέθοδο `swap(Ball x, Ball y)` που να αντιμεταθέτει τις δύο αναφορές του καλούντα!

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Να νομίζεις ότι `b2 = b1;` αντιγράφει το αντικείμενο: αντιγράφει μόνο τη **διεύθυνση** (aliasing). Για ανεξάρτητο αντίγραφο χρειάζεται `new` (copy constructor).
> - Ξέχασμα του βρόχου αρχικοποίησης σε πίνακα αντικειμένων (`Ball[] a = new Ball[N];` χωρίς `a[i] = new Ball();`) → `NullPointerException`.
> - Σύγκριση αντικειμένων με `==` αντί για `.equals(...)`: το `==` ελέγχει αν είναι το **ίδιο** αντικείμενο στη μνήμη, όχι αν έχουν τα ίδια πεδία.
> - Να νομίζεις ότι η Java έχει «πέρασμα δια αναφοράς» επειδή αλλάζει το `b[3]`: περνά **αντίγραφο της αναφοράς** (pass-by-value of the reference), γι' αυτό `c = "seven"` ή `b = new int[...]` δεν επηρεάζει τον καλούντα.
