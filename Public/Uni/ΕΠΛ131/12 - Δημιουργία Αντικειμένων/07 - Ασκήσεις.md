# 07 - Ασκήσεις

20 ασκήσεις στο ύφος των διαφανειών και των εξετάσεων της **Ενότητας XII – Δημιουργία Αντικειμένων**. **Λύσε πρώτα, άνοιξε μετά.**

> [!tip] Πώς να το χρησιμοποιήσεις
> Πριν ανοίξεις τη λύση, έλεγξε πάντα: (1) μεταγλωττίζεται ή έχει compile error (`static`/default constructor/`this`/overloading); (2) αν τρέχει, τι δείχνουν οι αναφορές στη μνήμη;

---

## Μέρος Α — Κατασκευαστές, `new` και Overloading

### Άσκηση 1

Μεταγλωττίζεται ο παρακάτω κώδικας; Αν όχι, γιατί;
```java
public class Box {
    private int w;
    public Box(int w) { this.w = w; }
    public static void main(String[] args) {
        Box b = new Box();
    }
}
```

> [!success]- Λύση
> **Όχι — σφάλμα μεταγλώττισης.** Επειδή ορίσαμε κατασκευαστή με όρισμα `Box(int w)`, η Java **δεν** παρέχει πλέον τον default no-args constructor `Box()`. Για να δουλέψει η `new Box()`, πρέπει να ορίσουμε ρητά `public Box() { this(0); }`.

### Άσκηση 2

Τι τυπώνει ο παρακάτω κώδικας; Προσοχή στη δήλωση της `Thing`!
```java
public class Thing {
    private int x = 5;
    public void Thing() { x = 99; }
    public static void main(String[] args) {
        Thing t = new Thing();
        System.out.println(t.x);
    }
}
```

> [!success]- Λύση
> Τυπώνει **`5`**, όχι `99`! Επειδή η `public void Thing()` έχει τύπο επιστροφής `void`, **δεν είναι κατασκευαστής** αλλά μια συνηθισμένη μέθοδος. Έτσι η Java δημιουργεί τον default constructor `Thing() {}`, ο οποίος αφήνει το `x` στην τιμή `5`. (Θα έπρεπε να κληθεί `t.Thing();` για να γίνει `99`.)

### Άσκηση 3

Ποιες από τις παρακάτω δηλώσεις μέσα στην ίδια κλάση `Calc` είναι **έγκυρο overloading** της `public int f(int a, double b)` και ποιες δίνουν **σφάλμα μεταγλώττισης**;
- (α) `public double f(int a, double b)`
- (β) `public int f(double a, int b)`
- (γ) `private int f(int x, double y)`
- (δ) `public void f(int a)`

> [!success]- Λύση
> - (α) **Compile error** — ίδια λίστα τύπων `(int, double)`· διαφορετικός τύπος επιστροφής **δεν** αρκεί.
> - (β) **Έγκυρο** — διαφορετική σειρά τύπων `(double, int)`.
> - (γ) **Compile error** — ίδια λίστα τύπων `(int, double)`· ονόματα παραμέτρων και `private`/`public` δεν μετράνε.
> - (δ) **Έγκυρο** — διαφορετικός αριθμός παραμέτρων `(int)`.

### Άσκηση 4

Βρες το σφάλμα στον παρακάτω κατασκευαστή:
```java
public class Rect {
    private int w, h;
    public Rect(int side) {
        System.out.println("Square");
        this(side, side);
    }
    public Rect(int w, int h) { this.w = w; this.h = h; }
}
```

> [!success]- Λύση
> **Σφάλμα μεταγλώττισης**: η κλήση `this(side, side);` **πρέπει να είναι η πρώτη εντολή** μέσα στον κατασκευαστή (`call to this must be first statement in constructor`). Αν βάλουμε το `System.out.println("Square");` μετά το `this(side, side);`, μεταγλωττίζεται κανονικά.

### Άσκηση 5

Τι συμβαίνει σε καθεμία από τις παρακάτω περιπτώσεις; (Compile error, `NullPointerException`, ή εκτελείται κανονικά;)
```java
// Περίπτωση Α (μέσα στη main):
Fraction f;
System.out.println(f);

// Περίπτωση Β (μέσα στη main):
Fraction f = null;
System.out.println(f);
System.out.println(f.toString());
```

> [!success]- Λύση
> - **Περίπτωση Α**: **Compile error** (`variable f might not have been initialized`), γιατί η `f` είναι τοπική μεταβλητή.
> - **Περίπτωση Β**: Η πρώτη `println(f)` **εκτελείται κανονικά** και τυπώνει `null` (η `println` ελέγχει για `null` πριν καλέσει `toString()`). Η δεύτερη `f.toString()` ρίχνει **`NullPointerException`** στον χρόνο εκτέλεσης!

## Μέρος Β — `static`, `private` και `this`

### Άσκηση 6

Ποιες γραμμές στην `Test` δίνουν **σφάλμα μεταγλώττισης**;
```java
public class Test {
    private static int s = 1;
    private int n = 2;

    public static void sm() {
        System.out.println(s);      // (1)
        System.out.println(n);      // (2)
        im();                       // (3)
        Test t = new Test();
        System.out.println(t.n);    // (4)
        t.im();                     // (5)
    }

    public void im() {
        System.out.println(s + n);  // (6)
        sm();                       // (7)
    }
}
```

> [!success]- Λύση
> Σφάλμα δίνουν **μόνο οι (2) και (3)**, γιατί η `sm()` είναι `static` και προσπαθεί να χρησιμοποιήσει non-static πεδίο (`n`) και μέθοδο (`im()`) χωρίς αντικείμενο.
> Οι **(4)** και **(5)** είναι **απολύτως έγκυρες**: μέσα σε `static` μέθοδο μπορούμε να φτιάξουμε αντικείμενο `t` και να προσπελάσουμε `t.n` (ακόμα κι αν είναι `private`, αφού είμαστε στην ίδια κλάση!) και `t.im()`. Οι **(6)** και **(7)** είναι επίσης έγκυρες (μια instance μέθοδος βλέπει και `static` και non-static).

### Άσκηση 7

Τι τυπώνει ο παρακάτω κώδικας;
```java
public class Counter {
    private static int total = 0;
    private int id;

    public Counter() {
        total++;
        id = total;
    }

    public String toString() { return id + "/" + total; }

    public static void main(String[] args) {
        Counter a = new Counter();
        Counter b = new Counter();
        Counter c = new Counter();
        System.out.println(a + " " + b + " " + c);
    }
}
```

> [!success]- Λύση
> Τυπώνει **`1/3 2/3 3/3`**.
> Κάθε αντικείμενο έχει το δικό του `id` (`1`, `2`, `3`), αλλά το `total` είναι **`static`**, άρα μοιράζεται ανάμεσα σε όλα τα αντικείμενα — τη στιγμή της εκτύπωσης έχει φτάσει στο `3` για όλα!

### Άσκηση 8

Τι τυπώνει ο παρακάτω κώδικας και γιατί; Πώς διορθώνεται;
```java
public class Point {
    private int x, y;
    public Point(int x, int y) {
        x = x;
        y = y;
    }
    public String toString() { return "(" + x + "," + y + ")"; }
    public static void main(String[] args) {
        System.out.println(new Point(3, 4));
    }
}
```

> [!success]- Λύση
> Τυπώνει **`(0,0)`**! Λόγω **shadowing**, οι παράμετροι `x` και `y` «κρύβουν» τα πεδία `x` και `y`, οπότε `x = x;` αναθέτει την παράμετρο στον εαυτό της και τα πεδία μένουν στην default τιμή `0`.
> **Διόρθωση**: `this.x = x; this.y = y;`.

### Άσκηση 9

Μεταγλωττίζεται η παρακάτω μέθοδος μέσα στην κλάση `Point`; Εξήγησε γιατί.
```java
public class Point {
    private int x, y;
    public Point(int x, int y) { this.x = x; this.y = y; }
    public void swapWith(Point other) {
        int tx = this.x; this.x = other.x; other.x = tx;
        int ty = this.y; this.y = other.y; other.y = ty;
    }
}
```

> [!success]- Λύση
> **Ναι, μεταγλωττίζεται και δουλεύει κανονικά!** Το `private` στη Java ισχύει σε επίπεδο **κλάσης**, όχι αντικειμένου (XII-39). Άρα μέσα στην κλάση `Point`, η `swapWith` μπορεί όχι μόνο να διαβάσει αλλά και να **τροποποιήσει** τα `other.x` και `other.y`.

### Άσκηση 10

Γιατί οι κλήσεις `new Math()` και `new System()` δίνουν σφάλμα μεταγλώττισης;

> [!success]- Λύση
> Επειδή οι κλάσεις `Math` και `System` περιέχουν **μόνο `static`** μέλη (πεδία και μεθόδους) και δεν έχουν κανένα instance πεδίο, οπότε δεν έχει νόημα να δημιουργηθούν αντικείμενά τους. Οι κατασκευαστές τους έχουν δηλωθεί **`private`** (XII-31).

## Μέρος Γ — Αναφορές, Aliasing, Πίνακες Αντικειμένων και `PassByValue`

### Άσκηση 11

Τι τυπώνει ο παρακάτω κώδικας;
```java
public class Val {
    private int v;
    public Val(int v) { this.v = v; }
    public void add(int d) { v += d; }
    public String toString() { return "" + v; }

    public static void main(String[] args) {
        Val a = new Val(10);
        Val b = new Val(10);
        System.out.println((a == b) + " " + a + " " + b);
        b = a;
        b.add(5);
        System.out.println((a == b) + " " + a + " " + b);
    }
}
```

> [!success]- Λύση
> ```text
> false 10 10
> true 15 15
> ```
> Αρχικά `a` και `b` είναι δύο διαφορετικά αντικείμενα στη μνήμη (`a == b` είναι `false`). Μετά το `b = a;` γίνονται **ψευδώνυμα (aliases)** (`a == b` → `true`), οπότε το `b.add(5)` αυξάνει το `v` και για τα δύο (`15`). Το παλιό αντικείμενο του `b` παραδίδεται στον Garbage Collector.

### Άσκηση 12

Πόσα αντικείμενα `Val` έχουν δημιουργηθεί στη μνήμη και πόσα είναι **επιλέξιμα για Garbage Collection** στο σημείο `// ΕΔΩ`;
```java
Val v1 = new Val(1);
Val v2 = new Val(2);
Val v3 = new Val(3);
v1 = v2;
v2 = new Val(4);
v3 = v1;
// ΕΔΩ
```

> [!success]- Λύση
> - Δημιουργήθηκαν **4** αντικείμενα (`1`, `2`, `3`, `4` — όσα τα `new`).
> - Στο `// ΕΔΩ`: `v1` → αντικείμενο `2`, `v3` → αντικείμενο `2`, `v2` → αντικείμενο `4`.
> - Άρα **2** αντικείμενα (`1` και `3`) δεν έχουν καμία αναφορά και είναι επιλέξιμα για **Garbage Collection**.

### Άσκηση 13

Εντόπισε το σφάλμα στον παρακάτω κώδικα και διόρθωσέ το:
```java
Charge[] cs = new Charge[3];
for (int i = 0; i < cs.length; i++) {
    System.out.println(cs[i].potentialAt(0.5, 0.5));
}
```

> [!success]- Λύση
> Ρίχνει **`NullPointerException`** στο `i = 0`! Το `new Charge[3]` δεσμεύει μόνο τον πίνακα από 3 `null` αναφορές, όχι τα αντικείμενα `Charge`. Πρέπει πρώτα να αρχικοποιηθεί κάθε στοιχείο: `cs[i] = new Charge(x, y, q);` (XII-48).

### Άσκηση 14

Τι τυπώνει ο παρακάτω κώδικας;
```java
public class SwapTest {
    static void tricky(Val x, Val y) {
        x.add(10);
        Val tmp = x;
        x = y;
        y = tmp;
        x.add(100);
    }

    public static void main(String[] args) {
        Val a = new Val(1);
        Val b = new Val(2);
        tricky(a, b);
        System.out.println(a + " " + b);
    }
}
```

> [!success]- Λύση
> Τυπώνει **`11 102`**!
> 1. `x` δείχνει στο ίδιο αντικείμενο με το `a` (`1`), `y` στο ίδιο με το `b` (`2`).
> 2. `x.add(10)` αλλάζει το αντικείμενο του `a` σε **`11`**.
> 3. Το swap (`tmp = x; x = y; y = tmp;`) αλλάζει μόνο τις **τοπικές** αναφορές `x`, `y` — τώρα η `x` δείχνει στο αντικείμενο του `b` (`2`).
> 4. `x.add(100)` αλλάζει το αντικείμενο του `b` σε **`102`**.
> 5. Στη `main`, οι `a` και `b` δείχνουν ακόμα στα αρχικά τους αντικείμενα: `11` και `102`!

### Άσκηση 15

Δίνεται ο παρακάτω κώδικας (παραλλαγή του `PassByValue`, XII-73). Τι τυπώνει;
```java
static void f(int[] a, int[] b) {
    a[0] = 99;
    b = new int[]{ 7, 8 };
    b[0] = 55;
}
public static void main(String[] args) {
    int[] x = { 1, 2 };
    int[] y = { 3, 4 };
    f(x, y);
    System.out.println(x[0] + " " + y[0]);
}
```

> [!success]- Λύση
> Τυπώνει **`99 3`**.
> Η `a[0] = 99;` τροποποιεί τον κοινό πίνακα του `x`. Αντίθετα, η `b = new int[]{7, 8};` ανακατευθύνει την τοπική αναφορά `b` σε **νέο** πίνακα, οπότε το `b[0] = 55;` δεν αγγίζει τον πίνακα `y` της `main` (που παραμένει `{3, 4}`).

## Μέρος Δ — Σχεδίαση Κλάσεων, `equals`/`toString` και Immutability

### Άσκηση 16

Τι θα συμβεί αν στον copy constructor της `DeckObj` (XII-5) αντικαταστήσουμε το σώμα του με μία μόνο γραμμή `deck = d.deck;` και τρέξουμε:
```java
DeckObj d1 = new DeckObj();
DeckObj d2 = new DeckObj(d1);
d2.shuffle();
System.out.println(d1.equals(d2));
```

> [!success]- Λύση
> Θα τυπώσει **`true`**! Επειδή `d1.deck` και `d2.deck` θα έδειχναν στον **ίδιο** πίνακα `String[]` (ρηχή αντιγραφή / aliasing), το `d2.shuffle()` θα ανακάτευε και το `d1`! Με τον σωστό copy constructor της XII-5 (που κάνει `new String[d.deck.length]` και αντιγράφει κάθε στοιχείο), οι δύο τράπουλες είναι ανεξάρτητες και `d1.equals(d2)` είναι (σχεδόν βέβαια) `false`.

### Άσκηση 17

Γιατί η παρακάτω κλάση **ΔΕΝ** είναι πραγματικά αμετάβλητη (immutable), παρόλο που έχει `private final` πεδίο και κανέναν setter;
```java
public class Scores {
    private final int[] data;
    public Scores(int[] arr) { data = arr; }
    public int get(int i)    { return data[i]; }
}
```

> [!success]- Λύση
> Επειδή το `final` στο `int[] data` εμποδίζει μόνο την αλλαγή της **αναφοράς** `data`, όχι των **στοιχείων** του πίνακα! Ο πελάτης κρατάει την αναφορά `arr`:
> ```java
> int[] a = {10, 20};
> Scores s = new Scores(a);
> a[0] = 999;          // αλλάζει το s.get(0) σε 999!
> ```
> **Λύση**: αμυντική αντιγραφή (defensive copy) στον κατασκευαστή (`data = new int[arr.length]; ...`). (Θυμήσου τη 2η προϋπόθεση της XII-44: να μην υπάρχουν εξωτερικές αναφορές σε μεταβλητά αντικείμενα!)

### Άσκηση 18

Γράψε την πλήρη μέθοδο `public Fraction multiply(Fraction other)` και τη `public boolean equals(Fraction other)` για την κλάση `Fraction` (XII-25, XII-39), υποθέτοντας ότι κάθε `Fraction` είναι ήδη απλοποιημένο (`reduce()`).

> [!success]- Λύση
> ```java
> public Fraction multiply(Fraction other) {
>     return new Fraction(this.num * other.num, this.denom * other.denom);
>     // ο κατασκευαστής Fraction(int, int) καλεί αυτόματα reduce()!
> }
>
> public boolean equals(Fraction other) {
>     if (other == null) return false;
>     return this.num == other.num && this.denom == other.denom;
>     // (ή γενικότερα, ακόμα και χωρίς απλοποίηση: this.num * other.denom == other.num * this.denom)
> }
> ```

### Άσκηση 19

Γράψε μια **αμετάβλητη (immutable)** κλάση `Complex` για μιγαδικούς αριθμούς $a + bi$ με:
- ιδιωτικά `final` πεδία `re`, `im` (`double`),
- κατασκευαστή `Complex(double re, double im)` και no-args `Complex()` (που δίνει $0 + 0i$ μέσω `this(...)`),
- μεθόδους `Complex plus(Complex b)`, `double abs()` ($\sqrt{a^2 + b^2}$) και `String toString()` (π.χ. `"3.0 + 4.0i"`).

> [!success]- Λύση
> ```java
> public class Complex {
>     private final double re;
>     private final double im;
>
>     public Complex() {
>         this(0.0, 0.0);
>     }
>
>     public Complex(double re, double im) {
>         this.re = re;
>         this.im = im;
>     }
>
>     public Complex plus(Complex b) {
>         return new Complex(this.re + b.re, this.im + b.im);
>     }
>
>     public double abs() {
>         return Math.sqrt(re * re + im * im);
>     }
>
>     public String toString() {
>         return re + " + " + im + "i";
>     }
> }
> ```
> Πρόσεξε ότι η `plus` **δεν** αλλάζει το `this` — επιστρέφει ένα **νέο** αντικείμενο `Complex`!

### Άσκηση 20

Εντόπισε **τουλάχιστον 4** από τα σφάλματα της διαφάνειας **XII-44** στην κλάση `Charge`:
```java
public class Charge {
    private static final double k = 8.9e9;
    private final double rx, ry, q;
    public Charge(double x0, double y0, double q0) { rx = x0; ry = y0; q = q0; }
    public double pottentialAt(double x, double y) {
        double r = Euclidean(x, y);
        double v = k * q / r;
        return v;
    }
    private double Euclidean(double x, double y) {
        return Math.sqrt((x-rx)* (x-rx)+ ((y-ry)* (y-ry);
    }
    public String toString() {
        System.println(q + " at " + "(" + rx + ", " + ry + ")");
    }
}
```

> [!success]- Λύση
> 1. `k = 8.9e9` αντί για `8.99e9` (XII-42, XII-46).
> 2. `pottentialAt` (με δύο `t`) αντί για `potentialAt` (όπως στο API XII-43 και στον client XII-45).
> 3. Στη `Euclidean`: λείπουν δύο δεξιές παρενθέσεις `))` στο `Math.sqrt(...)` → compile error.
> 4. Στη `toString()`: `System.println(...)` δεν υπάρχει (είναι `System.out.println`), και κυρίως η `toString()` έχει τύπο επιστροφής `String` άρα πρέπει να κάνει **`return q + " at (" + rx + ", " + ry + ")";`** (αλλιώς `missing return statement`).
> 5. *(Μπόνους)* Το σχόλιο της διαφάνειας XII-44 για immutability γράφει `static` αντί για **`final`**.
