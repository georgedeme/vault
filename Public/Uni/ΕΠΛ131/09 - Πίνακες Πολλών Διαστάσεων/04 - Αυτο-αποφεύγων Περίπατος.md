# 04 - Αυτο-αποφεύγων Περίπατος

Προσομοίωση (Monte Carlo) ενός τυχαίου περιπάτου σε πλέγμα N × N που **δεν ξαναπερνά** από σημεία που έχει ήδη επισκεφθεί. Ένας `boolean[N][N]` θυμάται την πορεία· το ερώτημα είναι πόσο συχνά ο περίπατος **εγκλωβίζεται** (διαφάνειες IX-29 … IX-36).

## 1. Το πρόβλημα (IX-29, IX-30)

> [!note] Μοντέλο: Self-avoiding walk
> - Ένα πλέγμα N × N. Αρχίζω από το **μεσαίο** σημείο.
> - Κινούμαι **τυχαία** σε κάποια γειτονική διασταύρωση (ένα βήμα πάνω, κάτω, δεξιά ή αριστερά), **αποφεύγοντας** διασταυρώσεις από τις οποίες έχω ήδη περάσει.
> - **Δραπετεύω** όταν φτάσω σε **ακραίο** σημείο του πλέγματος (πρώτη/τελευταία σειρά, ή πρώτη/τελευταία στήλη).
> - **Εγκλωβίζομαι** (dead end) όταν δεν μπορώ να προχωρήσω από μη-ακραίο σημείο: και οι τέσσερις γείτονες είναι ήδη επισκεπτόμενοι.
>
> **Εφαρμογές:** πολυμερή, στατιστική μηχανική, κτλ.

**Ερωτήματα προς διερεύνηση (IX-30):** Ποιο είναι το ποσοστό επιτυχίας μου σε ένα πλέγμα 5 × 5; Σε ένα N × N; Σε ένα N × N × N;

> [!success]- Απαντήσεις από προσομοίωση (➕, 20 000 προσπάθειες, ελέγχθηκε)
>
> | N | Ποσοστό εγκλωβισμού | Ποσοστό επιτυχίας |
> |---|---|---|
> | 5 | **0%** | 100% |
> | 10 | ≈ 5% | ≈ 95% |
> | 20 | ≈ 32% | ≈ 68% |
> | 40 | ≈ 77–79% | ≈ 21–23% |
>
> - Στο **5 × 5** ο εγκλωβισμός είναι **αδύνατος**. Τα μη-ακραία σημεία είναι το εσωτερικό 3 × 3 (δείκτες 1…3). Ένα ακραίο σημείο δεν «επισκέπτεται» ποτέ χωρίς να τελειώσει η προσπάθεια (δραπέτευση), άρα μπορείς να εγκλωβιστείς μόνο σε σημείο που έχει **και τους τέσσερις** γείτονες εσωτερικούς. Στο 3 × 3 τέτοιο σημείο είναι μόνο το κέντρο `(2,2)` – η **αφετηρία**, όπου οι γείτονες είναι ακόμη ελεύθεροι, και στην οποία δεν μπορείς να ξαναγυρίσεις (είναι ήδη επισκεπτόμενη).
> - Όσο **μεγαλώνει** το N, τόσο **μεγαλύτερη** η πιθανότητα εγκλωβισμού: η άκρη είναι πιο μακριά και ο περίπατος έχει περισσότερο χρόνο να «κλείσει» τον εαυτό του.
> - Στις **τρεις** διαστάσεις κάθε σημείο έχει **6** γείτονες, άρα ο εγκλωβισμός είναι πολύ πιο σπάνιος για το ίδιο N. Ο κώδικας γενικεύεται με `boolean[N][N][N]` και έξι κατευθύνσεις (δείτε την [[Uni/ΕΠΛ131/09 - Πίνακες Πολλών Διαστάσεων/07 - Ασκήσεις#Άσκηση 17|Άσκηση 17]]).

## 2. Βασικά υπο-προβλήματα (IX-31)

Από την αλγοριθμική σκοπιά, ποια ερωτήματα πρέπει να απαντηθούν (με άλλα λόγια ποια είναι τα βασικά υπο-προβλήματα που χρειάζεται να επιλυθούν);

**Για δεδομένη προσπάθεια**
- Πώς **καταγράφω την πορεία** μου, για να γνωρίζω τα σημεία που έχω ήδη επισκεφτεί; → `boolean[][] a`, `a[x][y] = true`.
- Πώς **αντιλαμβάνομαι** ότι έχω κατορθώσει να δραπετεύσω, ή το αντίθετο ότι έχω εγκλωβιστεί, για να τερματίσω την προσπάθεια; → συνθήκη του `while` / έλεγχος των τεσσάρων γειτόνων.
- Σε περίπτωση που δεν έχω ακόμη εγκλωβιστεί/δραπετεύσει, πώς **επιλέγω με τυχαίο τρόπο** την επόμενή μου κίνηση; → `Math.random()` σε τέσσερα ισοπίθανα διαστήματα.

Αλγοριθμική δομή: **απροσδιόριστη επανάληψη** (συνεχίζω κανονικά την προσπάθειά μου, δηλαδή την πορεία μου, ενόσω δεν έχω ακόμη κατορθώσει να δραπετεύσω). Διακόπτω όμως ανώμαλα την πορεία μου, μόλις εγκλωβιστώ, εάν και εφόσον αυτό συμβεί – με άλλα λόγια **επιλογή** εντός της επανάληψης ως προς το ενδεχόμενο **πρόωρου τερματισμού** της επανάληψης.

**Για δεδομένο σύνολο προσπαθειών**
- Διαδοχικά εκπληρώνω το δεδομένο σύνολο προσπαθειών που έχω στη διάθεσή μου, αρχίζοντας κάθε προσπάθειά μου από το μεσαίο σημείο του πλέγματος, και παράλληλα καταγράφω τις επιτυχίες (δραπέτευσα!) και αποτυχίες μου (εγκλωβίστηκα!).
- Στο τέλος παρουσιάζω το ποσοστό αποτυχιών (ή επιτυχιών) μου.

Αλγοριθμική δομή: **απαριθμητή επανάληψη**.

## 3. Ο αλγόριθμος (IX-32, IX-33)

**Ψευδοκώδικας σε υψηλό επίπεδο (IX-32)**
```
deadEnds = 0
για κάθε προσπάθεια t = 1 … T:                      // απαριθμητή
    αρχικοποίησε το πλέγμα (κανένα σημείο επισκεπτόμενο)
    θέση ← μεσαίο σημείο
    όσο δεν έχω δραπετεύσει:                         // απροσδιόριστη
        σημείωσε τη θέση ως επισκεπτόμενη
        αν έχω εγκλωβιστεί:
            deadEnds++ ; διέκοψε την προσπάθεια       // πρόωρη διακοπή (break)
        διάλεξε τυχαία κατεύθυνση· αν ο γείτονας είναι ελεύθερος, πήγαινε εκεί
τύπωσε το ποσοστό αποτυχιών 100 · deadEnds / T
```

**Σε (ψευδο)κώδικα (IX-33):**
```java
int deadEnds = 0;  // no of unsuccessful tries
for (t = 0; t < T; t++) {  // I repeat for each try
   boolean[][] a = new boolean[N][N];  // grid representation
   int x = N/2, y = N/2;
   while (x > 0 && x < N-1 && y > 0 && y < N-1) {  // I have not escaped yet
      a[x][y] = true;  // I am at this point
      if (a[x+1][y] && a[x-1][y] && a[x][y+1] && a[x][y-1]){
         // Alas . . . I am trapped!
         deadEnds++; break;}  // I must interrupt this try!
      // I can proceed . . .
      double r = Math.random();  // . . but in a random way
      if      (r < 0.25) {if (!a[x+1][y]) x++;}
      else if (r < 0.50) {if (!a[x-1][y]) x--;}
      else if (r < 0.75) {if (!a[x][y+1]) y++;}
      else if (r < 1.0)  {if (!a[x][y-1]) y--;}
   }
}
System.out.println(100*deadEnds/T + "% of dead ends");
```

## 4. Πλήρης υλοποίηση (IX-34)

```java
public class SelfAvoidingWalk {
  public static void main(String[] args) {
    int N = Integer.parseInt(args[0]);    // grid size
    int T = Integer.parseInt(args[1]);    // number of trials
    int deadEnds = 0;                     // trials resulting in dead end

    for (int t = 0; t < T; t++) {
      boolean[][] a = new boolean[N][N];  // intersections visited
      int x = N/2, y = N/2;               // current position

      while (x > 0 && x < N-1 && y > 0 && y < N-1) {
        if (a[x-1][y] && a[x+1][y] && a[x][y-1] && a[x][y+1]) {
           deadEnds++;
           break;
        }
        a[x][y] = true;                   // mark as visited

        double r = Math.random();
        if      (r < 0.25) { if (!a[x+1][y]) x++; }
        else if (r < 0.50) { if (!a[x-1][y]) x--; }
        else if (r < 0.75) { if (!a[x][y+1]) y++; }
        else if (r < 1.00) { if (!a[x][y-1]) y--; }
      }
    }
    System.out.println(100*deadEnds/T + "% dead ends");
  }
}
```

```
$ java SelfAvoidingWalk 10 20000
5% dead ends
$ java SelfAvoidingWalk 20 20000
32% dead ends
```

> [!important] Γιατί δεν βγαίνουμε ποτέ εκτός ορίων
> Η συνθήκη του `while` εξασφαλίζει ότι **μέσα** στον βρόχο `1 ≤ x ≤ N-2` και `1 ≤ y ≤ N-2`. Άρα οι γείτονες `x±1`, `y±1` είναι στο `0 … N-1` – πάντα έγκυροι δείκτες. Μόλις μια κίνηση φέρει το `x` ή το `y` στο `0` ή στο `N-1` (ακραίο σημείο), η συνθήκη γίνεται ψευδής **πριν** διαβαστεί οποιοσδήποτε γείτονας: δραπέτευση.

![[Περίπατος - Όρια Πλέγματος.png|800]]

> [!note] Η διαφορά IX-33 και IX-34
> Η IX-33 πρώτα **σημειώνει** τη θέση και μετά ελέγχει εγκλωβισμό· η IX-34 πρώτα **ελέγχει** και μετά σημειώνει. Το αποτέλεσμα είναι ίδιο: η τρέχουσα θέση δεν είναι γείτονας του εαυτού της, άρα η σήμανσή της δεν επηρεάζει τον έλεγχο. Επίσης η IX-33 γράφει `for (t = 0; …)` χωρίς `int` (ψευδοκώδικας) και τυπώνει `"% of dead ends"` (η IX-34 `"% dead ends"`).

## 5. Σχολιάστε την εντολή επιλογής (IX-35)

```java
double r = Math.random();
if      (r < 0.25) {if (!a[x+1][y]) x++;}
else if (r < 0.50) {if (!a[x-1][y]) x--;}
else if (r < 0.75) {if (!a[x][y+1]) y++;}
else if (r < 1.0)  {if (!a[x][y-1]) y--;}
```

**Ερώτηση:** Έστω ότι, σε ένα δεδομένο σημείο της εκτέλεσης, οι είσοδοι `a[x+1][y]`, `a[x][y+1]` και `a[x][y-1]` είναι `true` και η μεταβλητή `r` διαδοχικά λαμβάνει τις τιμές `0.1, 0.045, 0.83, 0.95, 0.8` και `0.62`. Τι γίνεται;

> [!success]- Απάντηση
> Μόνο ο γείτονας `a[x-1][y]` είναι ελεύθερος, και η κίνηση προς αυτόν γίνεται **μόνο** όταν `0.25 ≤ r < 0.50`.
>
> | `r` | Κλάδος | Γείτονας | Αποτέλεσμα |
> |---|---|---|---|
> | 0.1 | `x+1` | `true` | καμία κίνηση |
> | 0.045 | `x+1` | `true` | καμία κίνηση |
> | 0.83 | `y-1` | `true` | καμία κίνηση |
> | 0.95 | `y-1` | `true` | καμία κίνηση |
> | 0.8 | `y-1` | `true` | καμία κίνηση |
> | 0.62 | `y+1` | `true` | καμία κίνηση |
>
> **Έξι επαναλήψεις χωρίς καμία κίνηση.** Δεν είναι λάθος (ο έλεγχος εγκλωβισμού είναι ψευδής, γιατί ο `x-1` είναι ελεύθερος, και κάποια στιγμή η `r` θα πέσει στο `[0.25, 0.5)`), αλλά είναι **σπατάλη**: κάθε επανάληψη ξαναελέγχει και ξανασημειώνει την ίδια θέση. Με έναν ελεύθερο γείτονα, κατά μέσο όρο χρειάζονται **4** επαναλήψεις για μία κίνηση. Η επιλογή «τυχαία ανάμεσα στις τέσσερις, και αν είναι κατειλημμένη ξαναδοκίμασε» δεν είναι το ίδιο με «τυχαία ανάμεσα στις **ελεύθερες**» ως προς το κόστος – ως προς τις πιθανότητες της πορείας όμως είναι ισοδύναμη.

![[Περίπατος - Ερώτηση IX-35.png|800]]

> [!example]- ➕ Επιλογή μόνο ανάμεσα στους ελεύθερους γείτονες
> ```java
> int[] dx = {1, -1, 0, 0}, dy = {0, 0, 1, -1};
> int[] free = new int[4]; int nf = 0;
> for (int d = 0; d < 4; d++)
>    if (!a[x+dx[d]][y+dy[d]]) free[nf++] = d;
> if (nf == 0) { deadEnds++; break; }          // εγκλωβισμός = κανένας ελεύθερος
> int d = free[(int)(Math.random() * nf)];
> x += dx[d]; y += dy[d];
> ```
> Μία κίνηση ανά επανάληψη. Οι παράλληλοι πίνακες `dx`/`dy` αντικαθιστούν την αλυσίδα `else if` – προσθήκη κατεύθυνσης (π.χ. 3Δ ή διαγώνιες) = προσθήκη στοιχείων.

## 6. Παραδείγματα (IX-36)

Η IX-36 δείχνει 48 τυχαίους περιπάτους σε πλέγμα: κάποιοι φτάνουν στην άκρη (escape), άλλοι «κουλουριάζονται» και εγκλωβίζονται (dead end).

> [!warning] ➕ Οριακές περιπτώσεις (ελέγχθηκαν)
> - `T = 0` → `ArithmeticException: / by zero` στο `100*deadEnds/T` (ακέραια διαίρεση).
> - `100*deadEnds/T` είναι **ακέραια** διαίρεση: αποκόπτει (π.χ. 5.9% → `5%`). Για δεκαδικά: `100.0*deadEnds/T`. Η σειρά μετράει: `deadEnds/T*100` θα έδινε σχεδόν πάντα `0`.
> - `N = 2` ή `N = 3`: η αρχική θέση `N/2` είναι ήδη ακραία ή απέχει ένα βήμα από την άκρη → `0% dead ends`.
> - Για **άρτιο** N, το `N/2` δεν είναι ακριβώς το κέντρο (π.χ. N = 10 → θέση 5, ενώ τα σημεία είναι 0…9) – ελαφριά ασυμμετρία, αμελητέα.
> - Ο πίνακας `a` δημιουργείται **μέσα** στον `for`: κάθε προσπάθεια ξεκινά με καθαρό πλέγμα. Αν οριζόταν μία φορά έξω, η 2η προσπάθεια θα «έβλεπε» την πορεία της 1ης.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Έλεγχος γειτόνων **πριν** εξασφαλιστεί ότι η θέση δεν είναι ακραία → `ArrayIndexOutOfBoundsException`.
> - `||` αντί για `&&` στον έλεγχο εγκλωβισμού (εγκλωβίζομαι μόνο όταν **όλοι** οι γείτονες είναι κατειλημμένοι).
> - Πίνακας `a` έξω από τον βρόχο των προσπαθειών.
> - `deadEnds/T*100` ή `T = 0`.
> - Πίστη ότι κάθε επανάληψη του `while` κάνει μία κίνηση (IX-35).
