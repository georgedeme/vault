# 05 - Το Παιχνίδι της Ζωής

Το παιχνίδι της ζωής του Conway: ένα πλέγμα `boolean[N][N]` από ζωντανά/νεκρά κελιά, που αλλάζει γενιά προς γενιά με τέσσερις απλούς κανόνες. Το πρόβλημα διασπάται σε τρία υπο-προβλήματα: **γείτονες**, **αρχική γενιά**, **επόμενη γενιά** (διαφάνειες IX-37 … IX-44).

## 1. Οι κανόνες (IX-37)

> [!note] Το παιχνίδι της ζωής (Conway)
> - Ένα κελί αναπαρίσταται από ένα μπλοκ σε ένα πλέγμα.
> - Κάθε κελί έχει **(μέχρι) 8 γείτονες** (οριζόντια, κάθετα, διαγώνια· στις άκρες λιγότερους).
> - Απλοί κανόνες για ένα κελί όταν «έρχεται στη ζωή» ή όταν «πεθαίνει»:

| Κελί | Ζωντανοί γείτονες | Επόμενη γενιά | Αιτία |
|---|---|---|---|
| ζωντανό | **< 2** | πεθαίνει | μοναξιά |
| ζωντανό | **> 3** | πεθαίνει | υπερπληθυσμός |
| ζωντανό | **2 ή 3** | παραμένει ζωντανό | |
| νεκρό | **ακριβώς 3** | έρχεται στη ζωή | |
| νεκρό | οτιδήποτε άλλο | μένει νεκρό | |

Αναπαράσταση πλέγματος N × N (IX-38):
```java
boolean[][] Gen = new boolean[N][N];
```
`true` = ζωντανό. Αρχικά όλα `false` (νεκρά).

## 2. Υπο-πρόβλημα: πόσους ζωντανούς γείτονες έχει δεδομένο κελί; (IX-38, IX-39)

```java
// How many live neighbors does cell [x][y] have?

public static int live_neighbors(boolean[][] Gen,
                                 int x, int y){
  int N = Gen.length;
  int count = 0;
  if (Gen[x][y]) count--;
  for (int i = x-1; i <= x+1; i++)
   for (int j = y-1; j <= y+1; j++)
      if (i >= 0 && i < N && j >= 0 && j < N &&
          Gen[i][j]) count++;
  return count;
}
```

> [!important] Δύο «κόλπα»
> 1. **Το 3 × 3 γύρω από το κελί, μαζί με το ίδιο.** Ο διπλός βρόχος περνά από τα 9 κελιά `[x-1 … x+1][y-1 … y+1]` – άρα μετρά και το **ίδιο** το κελί. Γι' αυτό το `if (Gen[x][y]) count--;` στην αρχή: αν το κελί είναι ζωντανό, θα μετρηθεί στον βρόχο, οπότε αφαιρείται εκ των προτέρων.
> 2. **Έλεγχος ορίων πριν την πρόσβαση.** Η συνθήκη `i >= 0 && i < N && j >= 0 && j < N && Gen[i][j]` βασίζεται στο **short-circuit** του `&&`: το `Gen[i][j]` αποτιμάται **μόνο** αν οι δείκτες είναι έγκυροι. Με το `Gen[i][j]` πρώτο θα είχαμε `ArrayIndexOutOfBoundsException` στις άκρες.

![[Ζωή - Γείτονες.png|800]]

> [!example]- Παράδειγμα (IX-38) και οριακά κελιά (ελέγχθηκαν)
> Στο σχήμα της IX-38 το κόκκινο κελί στη γωνία έχει μόνο 3 θέσεις-γείτονες (κίτρινες), το πράσινο στην κάτω άκρη 5, ενώ ένα εσωτερικό κελί (όπως το μαύρο) έχει 8.
>
> Με πλέγμα 3 × 3 όπου ζωντανά είναι τα `[0][0]`, `[0][1]`, `[1][0]`:
> - `live_neighbors(k, 0, 0)` → **2** (το ίδιο δεν μετράει)
> - `live_neighbors(k, 1, 1)` → **3**
> - `live_neighbors(k, 2, 2)` → **0**

## 3. Υπο-πρόβλημα: αρχικοποίηση πλέγματος – 1η γενιά κελιών (IX-40)

```java
// Initialize first generation randomly -
// p is the probability that a cell is alive

public static void initGen(boolean[][] Gen, double p){
   int N = Gen.length;
   for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
      if (Math.random() < p) Gen[i][j] = true;
}
```

`void` με **παράμετρο εξόδου** ([[04 - Πίνακες ως Παράμετροι Συναρτήσεων|VIII – 04]]): γεμίζει τον πίνακα του καλούντα. Κάθε κελί, ανεξάρτητα, είναι ζωντανό με πιθανότητα `p`· με `p = 0.3` περίπου το 30% των κελιών ξεκινά ζωντανό. Υποθέτει ότι ο πίνακας ξεκινά «όλο νεκρό» (δεν θέτει ποτέ `false`).

## 4. Υπο-πρόβλημα: δημιουργία νέας γενιάς από την τρέχουσα (IX-41)

```java
// Compute and return new generation from current
// generation

public static boolean[][] nextGen(boolean[][] Gen){
   int N = Gen.length;
   boolean[][] NGen = new boolean[N][N];
   for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++){
     int n = live_neighbors(Gen, i, j);
     if (Gen[i][j] && (n < 2 || n > 3))
        NGen[i][j]=false;
     else if (!Gen[i][j] && n==3) NGen[i][j]=true;
     else NGen[i][j] = Gen[i][j];
    }
   return NGen;
}
```

> [!important] Γιατί **νέος** πίνακας
> Όλα τα κελιά της νέας γενιάς πρέπει να υπολογιστούν από την **ίδια**, παλιά γενιά. Αν γράφαμε τις αλλαγές **μέσα** στο `Gen` καθώς προχωράμε, τα κελιά που ελέγχονται αργότερα θα έβλεπαν γείτονες που **έχουν ήδη αλλάξει** – μισή παλιά, μισή νέα γενιά.
>
> Η `nextGen` επιστρέφει **νέο** πίνακα (έξοδος = διεύθυνση), άρα ο καλών γράφει `Generation = nextGen(Generation);`.

> [!example]- ➕ Το «blinker» και το λάθος της επιτόπιας ενημέρωσης (ελέγχθηκαν)
> Τρία ζωντανά κελιά σε σειρά σε πλέγμα 5 × 5 («blinker») εναλλάσσονται οριζόντια ↔ κάθετα:
> ```
> .....      .....      .....
> .....      ..#..      .....
> .###.  →   ..#..  →   .###.
> .....      ..#..      .....
> .....      .....      .....
> ```
> Αν η ενημέρωση γινόταν **επί τόπου** (στο ίδιο `Gen`), η πρώτη γενιά θα έβγαινε
> ```
> .....
> ..##.
> .#.#.
> .....
> .....
> ```
> – λάθος: π.χ. το `[1][2]` γεννιέται σωστά, αλλά μετά το `[1][3]` μετρά και αυτό το «νέο» κελί ως γείτονα.
>
> Με τρία κελιά σε «γωνία» (`[0][0]`, `[0][1]`, `[1][0]`) σε πλέγμα 3 × 3, το `[1][1]` έχει 3 γείτονες και γεννιέται: η επόμενη γενιά είναι το τετράγωνο 2 × 2 («block»), που μένει πια σταθερό.

![[Ζωή - Blinker και Επιτόπια Ενημέρωση.png|800]]

> [!tip] Απλοποίηση της συνθήκης
> Οι τρεις κλάδοι συνοψίζονται σε μία έκφραση:
> ```java
> NGen[i][j] = (n == 3) || (Gen[i][j] && n == 2);
> ```
> Ζωντανό την επόμενη γενιά αν έχει 3 γείτονες (είτε ήταν ζωντανό είτε γεννιέται) ή αν ήταν ζωντανό με 2. Ο πρώτος κλάδος του slide (`NGen[i][j]=false`) είναι περιττός – ο `NGen` ξεκινά ήδη `false` – αλλά κάνει τους κανόνες ορατούς.

## 5. Συνθέτοντας τη main (IX-42, IX-43)

```java
public static void main(String[] args){
  // N - grid size
  int N = Integer.parseInt(args[0]);
  // p - probability of a cell being initially alive
  double p = Double.parseDouble(args[1]);
  // T - number of next generations to be computed
  int T = Integer.parseInt(args[2]);

  boolean[][]Generation = new boolean[N][N];
  initGen(Generation, p);
  for (int t = 1; t <= T; t++){
      Generation = nextGen(Generation);
  }
}
```

Και πάλι διάσπαση και σύνθεση (IX-43): η `main` καλεί την `initGen` και την `nextGen`, και η `nextGen` καλεί την `live_neighbors`.

**Ερώτηση (IX-42):** Τι απουσιάζει από το πρόγραμμα;

> [!success]- Απάντηση
> Η **έξοδος**! Το πρόγραμμα υπολογίζει `T` γενιές αλλά **δεν τυπώνει ούτε σχεδιάζει τίποτα** – δεν υπάρχει κανένα ορατό αποτέλεσμα. Χρειάζεται ένα ακόμη υπο-πρόβλημα, π.χ. `display(Generation)` μετά από κάθε γενιά:
> ```java
> public static void display(boolean[][] Gen){
>    for (boolean[] row : Gen){
>       for (boolean cell : row) System.out.print(cell ? '#' : '.');
>       System.out.println();
>    }
>    System.out.println();
> }
> ```
> ή με `StdDraw.filledSquare` για κάθε ζωντανό κελί ([[05 - Γραφικά με StdDraw|VII – 05]]). Δευτερευόντως λείπει και ο έλεγχος των ορισμάτων (`args.length < 3` → `ArrayIndexOutOfBoundsException`).

## 6. Σύνοψη της Ενότητας IX (IX-44, IX-49)

> [!note] Σύνοψη
> - Παραδείγματα χρήσης δισδιάστατων πινάκων: **απευθείας πρόσβαση σε σειρές, αλλά όχι σε στήλες**.
> - Οι πίνακες αποτελούν έναν οργανωμένο τρόπο αποθήκευσης τεράστιων ποσοτήτων δεδομένων, σχεδόν το ίδιο εύκολοι στη χρήση τους, όπως και οι βασικοί τύποι δεδομένων.
> - Ανάλυση πινάκων πολλαπλών διαστάσεων: σε σχέση με την **κάθε** διάσταση και όχι μόνο σε σχέση με τα στοιχεία που αφορούν την τελευταία διάσταση · συνεπώς **διάσπαση σε πολλά επίπεδα** σύμφωνα με τις διαστάσεις ενός πίνακα.
>
> Στο βιβλίο: Ενότητα **1.4** (IX-49).

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Ενημέρωση της γενιάς **επί τόπου** αντί για νέο πίνακα.
> - Ξεχασμένο `count--` για το ίδιο το κελί (κάθε ζωντανό κελί μετρά +1 γείτονα).
> - Έλεγχος `Gen[i][j]` **πριν** τους ελέγχους ορίων στη συνθήκη.
> - `nextGen(Generation);` χωρίς `Generation =` → η γενιά δεν αλλάζει ποτέ.
> - Σύγχυση των κανόνων: ζωντανό με 3 γείτονες **μένει**· νεκρό με 2 **μένει νεκρό**.
