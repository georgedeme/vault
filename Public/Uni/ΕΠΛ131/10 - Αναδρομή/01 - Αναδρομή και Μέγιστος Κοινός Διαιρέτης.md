# 01 - Αναδρομή και Μέγιστος Κοινός Διαιρέτης

Τι είναι η **αναδρομή**, πώς γράφεται (βασική περίπτωση + αναδρομικό βήμα), και το πρώτο παράδειγμα: ο **Ευκλείδειος αλγόριθμος** για τον μέγιστο κοινό διαιρέτη (διαφάνειες X-1 … X-7).

> «Αναδρομή: η δίδυμη αδελφή της επανάληψης» (X-1)

## 1. Τι είναι η αναδρομή (X-2)

> [!note] Ορισμός
> **Αναδρομή** είναι όταν μία συνάρτηση **καλεί τον εαυτό της**, άμεσα ή έμμεσα.
> - **Άμεσα**: η `f` καλεί την `f`.
> - **Έμμεσα**: η `f` καλεί τη `g`, που καλεί (ξανά) την `f`.

| Γιατί να μάθουμε αναδρομή | |
|---|---|
| Νέος τρόπος σκέψης | λύνω το πρόβλημα **υποθέτοντας** ότι ξέρω να λύσω ένα μικρότερο του ίδιου είδους |
| Ισχυρό παράδειγμα προγραμματισμού | πολλοί αλγόριθμοι γράφονται φυσικά μόνο έτσι |
| Πολλοί υπολογισμοί είναι από τη φύση τους **αυτο-αναφορικοί** | mergesort, FFT (Fast Fourier Transform), gcd · συνδεδεμένες δομές δεδομένων · ένας φάκελος που περιέχει αρχεία και άλλους φακέλους |
| Στενά συνδεδεμένη με τη **μαθηματική επαγωγή** | ο αναδρομικός ορισμός είναι επαγωγικός ορισμός, και η ορθότητά του αποδεικνύεται με επαγωγή |

> [!tip] Αναδρομή ↔ επαγωγή
> | Επαγωγή (ΕΠΛ111) | Αναδρομή (ΕΠΛ131) |
> |---|---|
> | βάση: `P(0)` | βασική περίπτωση: `if (n == 0) return …;` |
> | επαγωγικό βήμα: `P(n-1) ⇒ P(n)` | αναδρομικό βήμα: χρησιμοποιώ το αποτέλεσμα για `n-1` |
> | ισχυρή επαγωγή: όλα τα `P(k)`, `k < n` | κλήσεις για **οποιοδήποτε** μικρότερο πρόβλημα (π.χ. `gcd(q, p % q)`) |
>
> Δες [[Uni/ΕΠΛ111/06 - Μαθηματική Επαγωγή/06 - Αναδρομικοί Ορισμοί Συναρτήσεων|Αναδρομικοί Ορισμοί Συναρτήσεων]], [[Uni/ΕΠΛ111/06 - Μαθηματική Επαγωγή/05 - Ισχυρή Επαγωγή|Ισχυρή Επαγωγή]] και [[Uni/ΕΠΛ111/06 - Μαθηματική Επαγωγή/08 - Επαγωγή στη Δομή|Επαγωγή στη Δομή]].

## 2. Ανάλυση περιπτώσεων (X-3)

> [!important] Οι δύο περιπτώσεις
> Όταν εφαρμόζουμε αναδρομή αναλύουμε τις σχετικές περιπτώσεις σε:
> - **βασικές** ή **τερματικές** περιπτώσεις (base case) – λύνονται **χωρίς** νέα κλήση,
> - **γενικές** ή **μη-τερματικές** (αναδρομικές) περιπτώσεις – οι αναδρομικές κλήσεις φέρνουν μια μη-τερματική περίπτωση **ένα βήμα πιο κοντά** σε κάποια από τις τερματικές.
>
> Η ανάλυση περιπτώσεων συνδέεται με **επιλογή** (`if`/`else`).
>
> Επαναλήψεις μπορεί να αναδιατυπωθούν ως αναδρομές και το αντίθετο. Ποιος είναι ο πιο φυσικός τρόπος διατύπωσης; Προκύπτουν και ζητήματα **υπολογιστικού κόστους**.

> [!tip] ➕ Τρεις ερωτήσεις πριν γράψεις αναδρομική συνάρτηση
> 1. **Ποια είναι η βασική περίπτωση** και τι επιστρέφει; (π.χ. `q == 0` → `p`)
> 2. **Πώς μικραίνει** το πρόβλημα σε κάθε κλήση, και είναι **σίγουρο** ότι θα φτάσει στη βασική περίπτωση για **κάθε** έγκυρη είσοδο;
> 3. **Πώς συνδυάζω** το αποτέλεσμα της μικρότερης κλήσης για να πάρω το δικό μου;
>
> Αν η απάντηση στο 2 είναι «όχι για κάποιες εισόδους» (π.χ. αρνητικοί), το πρόγραμμα καταλήγει σε `StackOverflowError` ([[02 - Παραγοντικό, Αναδρομή Στοίβας και Ουράς#6. Μνήμη και StackOverflowError (X-29)|02 §6]]).

> [!example]- ➕ Έμμεση (αμοιβαία) αναδρομή (ελέγχθηκε)
> ```java
> static boolean isEven(int n){ if (n == 0) return true;  return isOdd(n-1); }
> static boolean isOdd (int n){ if (n == 0) return false; return isEven(n-1); }
> ```
> `isEven(7)` → `isOdd(6)` → `isEven(5)` → … → `isOdd(0)` → `false`. Καμία δεν καλεί τον εαυτό της απευθείας, αλλά η καθεμία καλεί τον εαυτό της **μέσω** της άλλης. Για αρνητικό `n` δεν τερματίζει ποτέ.

## 3. Μέγιστος Κοινός Διαιρέτης (X-4)

> [!note] Ορισμός
> **Μέγιστος κοινός διαιρέτης** των αριθμών α και β είναι ο μεγαλύτερος κοινός διαιρέτης των α και β. Συμβολίζεται με ΜΚΔ(α,β).

Με παραγοντοποίηση:

| | |
|---|---|
| 4032 | = 2⁶ × 3² × 7¹ |
| 1272 | = 2³ × 3¹ × 53¹ |
| ΜΚΔ | = 2³ × 3¹ = **24** |

Π.χ. ΜΚΔ(4032, 1272) = 24. **Εφαρμογές:** απλοποίηση κλασμάτων (1272/4032 = 53/168), το κρυπτογραφικό σύστημα RSA.

Η παραγοντοποίηση είναι **αργή** για μεγάλους αριθμούς. Ο Ευκλείδης έχει πολύ καλύτερη ιδέα.

## 4. Ο Ευκλείδειος αλγόριθμος (X-5 … X-7)

> [!important] Ο αναδρομικός ορισμός
> ```
> gcd(p, q) = p                  αν q = 0          ← βασική περίπτωση
>           = gcd(q, p % q)      αλλιώς            ← βήμα αναδρομής, συγκλίνει στη βασική περίπτωση
> ```

| Κλήση | Γιατί |
|---|---|
| `gcd(4032, 1272)` | |
| `= gcd(1272, 216)` | `4032 = 3 × 1272 + 216` |
| `= gcd(216, 192)` | `1272 = 5 × 216 + 192` |
| `= gcd(192, 24)` | `216 = 1 × 192 + 24` |
| `= gcd(24, 0)` | `192 = 8 × 24 + 0` |
| `= 24` | βασική περίπτωση |

![[Αναδρομή - Ευκλείδης.png|800]]

> [!note] Γεωμετρικά (X-6)
> Αν `p = 8x` και `q = 3x`, τότε το `p` «χωράει» δύο φορές το `q` και περισσεύει `p % q = 2x`. Ό,τι μετράει ακριβώς **και** το `p` **και** το `q` (το `x`) μετράει ακριβώς και το υπόλοιπο `p % q`. Άρα ο ΜΚΔ δεν αλλάζει όταν το ζεύγος `(p, q)` αντικατασταθεί από το μικρότερο `(q, p % q)`: `gcd(p, q) = x`.

```java
public static int gcd(int p, int q) {
   if (q == 0) return p;          // Βασική περίπτωση
   else return gcd(q, p % q);     // Βήμα αναδρομής
}
```

> [!tip] Γιατί τερματίζει
> Για `q > 0` ισχύει `0 ≤ p % q < q`: το δεύτερο όρισμα **μικραίνει γνήσια** σε κάθε κλήση και δεν γίνεται ποτέ αρνητικό (για μη αρνητικά ορίσματα), άρα κάποια στιγμή γίνεται `0`. Είναι ακριβώς επιχείρημα **ισχυρής επαγωγής** στο `q`.

> [!note] Ιστορικό σημείωμα (X-5)
> Το πιο γνωστό έργο του Ευκλείδη (≈300 π.Χ.) είναι τα **Στοιχεία**, 13 βιβλία. Όταν ο Πτολεμαίος Α΄ ζήτησε έναν πιο εύκολο τρόπο από τα Στοιχεία για να μάθει Γεωμετρία, η απάντηση ήταν: **«Δεν υπάρχει βασιλική οδός για τη Γεωμετρία».**

> [!warning] ➕ Οριακές περιπτώσεις (ελέγχθηκαν)
>
> | Κλήση | Αποτέλεσμα | Σχόλιο |
> |---|---|---|
> | `gcd(1272, 4032)` | `24` | το **πρώτο** βήμα αντιμεταθέτει: `1272 % 4032 = 1272` → `gcd(4032, 1272)`. Η σειρά δεν πειράζει, κοστίζει μία κλήση |
> | `gcd(0, 5)` | `5` | `gcd(5, 0)` |
> | `gcd(5, 0)` | `5` | βασική περίπτωση αμέσως |
> | `gcd(0, 0)` | `0` | μαθηματικά ο ΜΚΔ(0,0) δεν ορίζεται· η συνάρτηση επιστρέφει 0 |
> | `gcd(17, 5)` | `1` | πρώτοι μεταξύ τους |
> | `gcd(-4, 6)` | `2` | |
> | `gcd(4, -6)` | **`-2`** | το `%` της Java παίρνει το πρόσημο του **διαιρετέου**: `4 % -6 = 4`, `-6 % 4 = -2`, … → αρνητικό αποτέλεσμα |
> | `gcd(-4, -6)` | **`-2`** | |
> | `gcd(144, 89)` | `1`, **11** κλήσεις | διαδοχικοί αριθμοί **Fibonacci** είναι η χειρότερη περίπτωση: κάθε πηλίκο είναι 1 |
>
> Για ασφαλή χρήση με αρνητικούς: `return Math.abs(p);` στη βασική περίπτωση.

> [!example]- ➕ Η επαναληπτική εκδοχή
> ```java
> public static int gcdIter(int p, int q) {
>    while (q != 0) {
>       int r = p % q;
>       p = q;
>       q = r;
>    }
>    return p;
> }
> ```
> Η αναδρομή του `gcd` είναι **αναδρομή ουράς**: η αναδρομική κλήση είναι το **τελευταίο** που γίνεται, και το αποτέλεσμά της επιστρέφεται αυτούσιο. Τέτοιες αναδρομές γίνονται μηχανικά βρόχος: οι παράμετροι γίνονται μεταβλητές, η κλήση γίνεται ανάθεση ([[02 - Παραγοντικό, Αναδρομή Στοίβας και Ουράς#4. Αναδρομή ουράς (X-11)|02 §4]]).

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Αναδρομή **χωρίς βασική περίπτωση** ή με βασική περίπτωση που δεν φτάνεται για κάποιες εισόδους.
> - Αναδρομική κλήση με **το ίδιο** (όχι μικρότερο) πρόβλημα, π.χ. `gcd(p, q)` αντί για `gcd(q, p % q)`.
> - `gcd(p % q, q)`: το `q` δεν αλλάζει ποτέ, άρα δεν γίνεται ποτέ `0`· από τη δεύτερη κλήση και μετά καλείται ξανά και ξανά η **ίδια** `gcd(p % q, q)` → `StackOverflowError`.
> - `return gcd(q, p % q);` χωρίς `return` (σκέτη κλήση) → `missing return statement`.
> - Υπόθεση ότι ο `gcd` χρειάζεται `p ≥ q`.
> - Πίστη ότι ο `gcd` δίνει πάντα θετικό αποτέλεσμα στη Java.
