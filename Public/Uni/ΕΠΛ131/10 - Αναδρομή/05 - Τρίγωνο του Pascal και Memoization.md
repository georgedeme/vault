# 05 - Τρίγωνο του Pascal και Memoization

Αναδρομική λύση για το τρίγωνο του Pascal: εύκολη να γραφτεί αλλά **μη αποδοτική** (ίδιο πρόβλημα με το Fibonacci). Η λύση είναι η **memoization**: θυμάμαι κάθε τιμή που υπολόγισα σε έναν πίνακα, ώστε να μην την ξαναϋπολογίσω (διαφάνειες X-30 … X-36, X-53, X-54).

## 1. Το πρόβλημα (X-30, X-31)

**Το τρίγωνο του Pascal – να εκτυπωθούν οι πρώτες N σειρές του τριγώνου.**

```
          1
         1 1
        1 2 1
       1 3 3 1
      1 4 6 4 1
    1 5 10 10 5 1
```


> Η έξοδος των διαφανειών είναι «συμπιεσμένη». Ο κώδικας τυπώνει κάθε αριθμό με **`%10d`** (πλάτος 10, στοίχιση δεξιά), άρα στην πράξη (ελέγχθηκε, `Pascal(4)`):
> ```
>

> με **κενή** πρώτη γραμμή (το `println()` είναι πριν από κάθε σειρά, όπως στη [[02 - Παράμετροι, Τιμές Επιστροφής και return#7. return χωρίς τιμή: drawSquare (VIII-17)|drawSquare]]) και χωρίς αλλαγή γραμμής μετά την τελευταία σειρά (την κάνει το `println()` της `main`).

## 2. Ο ορισμός: τ(E, R) (X-32, X-33)

**Ορισμός της τιμής του στοιχείου E της σειράς R του τριγώνου του Pascal, τ(E,R).** Ανάλυση περιπτώσεων:

| Περίπτωση | Τιμή | Είδος |
|---|---|---|
| 1. Το E είναι το **πρώτο** στοιχείο της R | τ(E,R) = 1 | τερματική |
| 2. Το E είναι το **τελευταίο** στοιχείο της R | τ(E,R) = 1 | τερματική |
| 3. Το E είναι **ενδιάμεσο** στοιχείο της R | τ(E,R) = τ(E,R−1) + τ(E−1,R−1) | μη-τερματική |

Το πλήθος στοιχείων κάθε σειράς ισούται με τον αριθμό της, π.χ. η N-οστή σειρά έχει N στοιχεία. Η αρίθμηση σειρών και στοιχείων ξεκινά από το **1**.

> [!note] Γεωμετρικά (X-33)
> Κάθε ενδιάμεσο στοιχείο είναι το **άθροισμα των δύο** που βρίσκονται «από πάνω» του: στη σειρά `row-1`, στη **θέση** του (`elem`) και στην **αριστερή** (`elem-1`). Στο σχήμα τριγώνου στοιχισμένου αριστερά, αυτά είναι το «από πάνω» και το «πάνω-αριστερά».

> [!tip] ➕ Σύνδεση με τους διωνυμικούς συντελεστές
> τ(E, R) = C(R−1, E−1) = «R−1 ανά E−1». Ο κανόνας της περίπτωσης 3 είναι η ταυτότητα του Pascal: C(n, k) = C(n−1, k) + C(n−1, k−1). Π.χ. τ(3, 5) = C(4, 2) = 6.

## 3. Η αναδρομική υλοποίηση (X-34)

```java
public class Recursive_Pascal {

  private static int compute_element (int row, int elem) {
     if (elem == 1) return 1;
     else if (elem == row) return 1;
     else return compute_element(row-1, elem) + compute_element(row-1, elem-1);
  }

  public static void Pascal (int N){
     for (int i = 1; i <= N; i++){
        System.out.println();
        for(int j=1;j<=i;++j)
           System.out.printf("%10d", compute_element(i,j));
     }
  }

  public static void main (String[] args){
     int N = Integer.parseInt(args[0]);
     Pascal(N);
     System.out.println();
  }
}
```

Η `compute_element` είναι `private` (βοηθητική)· η `Pascal` κάνει την εκτύπωση. Κάθε στοιχείο υπολογίζεται **ανεξάρτητα** από την αρχή.

## 4. Γιατί δεν είναι αποδοτική (X-35)

![[Αναδρομή - Δέντρο Pascal.png|800]]

| Κόμβος | Τιμή |
|---|---|
| `ce(5,3)` | `ce(4,3) + ce(4,2)` = 3 + 3 = **6** |
| `ce(4,3)` | `ce(3,3) + ce(3,2)` = 1 + 2 = 3 |
| `ce(4,2)` | `ce(3,2) + ce(3,1)` = 2 + 1 = 3 |
| `ce(3,2)` | `ce(2,2) + ce(2,1)` = 1 + 1 = 2 – υπολογίζεται **δύο φορές** |

**«Easy to write but NOT EFFICIENT!!!»** Η διπλή αναδρομή στοίβας ξαναϋπολογίζει τα ίδια υπο-προβλήματα, ακριβώς όπως η `F(n-1) + F(n-2)` ([[03 - Fibonacci και Εκθετική Σπατάλη|03]]).

> [!example]- ➕ Πόσες κλήσεις (ελέγχθηκε με μετρητή)
>
> | Υπολογισμός | Κλήσεις χωρίς memo | Με memo |
> |---|---|---|
> | `ce(5,3)` | 11 | |
> | `ce(20,10)` | **184 755** | |
> | όλο το τρίγωνο 20 σειρών (όπως η `Pascal(20)`) | **2 096 940** | **552** |
>
> Το δέντρο του `ce(R, E)` έχει τόσα φύλλα όσα η τιμή του (κάθε φύλλο συνεισφέρει `1`), άρα `2·τ − 1` κόμβους: `ce(20,10)` = 92 378 → 184 755 κλήσεις.

## 5. Memoization – Δυναμικός Προγραμματισμός (X-36)

> [!note] Memoization
> **MEMOIZATION** (Dynamic Programming): **αποφυγή ίδιου υπολογισμού** με **χρήση μνήμης**. Κάθε φορά που υπολογίζεται μια τιμή, αποθηκεύεται σε πίνακα· την επόμενη φορά που ζητείται, επιστρέφεται από τον πίνακα χωρίς υπολογισμό.

```java
public class Recursive_Pascal {

  private static int [][]memo; // αργότερα

  private static int compute_element (int row, int elem) {
     if (memo[row][elem]!=0) return memo[row][elem];
     if (elem == 1) return 1;
     else if (elem == row) return 1;
     else {
        int x = compute_element(row-1, elem);
        int y= compute_element(row-1, elem-1);
        return (memo[row][elem]=x+y);
     }
  }

  public static void Pascal (int N){
     memo = new int[N+1][N+1];
     for (int i = 1; i <= N; i++){
        System.out.println();
        for(int j=1;j<=i;++j)
           System.out.printf("%10d", compute_element(i,j));
     }
  }

  public static void main (String[] args){
     int N = Integer.parseInt(args[0]);
     Pascal(N);
     System.out.println();
  }
}
```

![[Αναδρομή - Memoization.png|800]]

> [!important] Πώς δουλεύει
> - **`private static int[][] memo`**: μεταβλητή της **κλάσης**, όχι τοπική – πρέπει να **επιζεί** ανάμεσα στις κλήσεις και να τη μοιράζονται όλες ([[03 - Κλήση, Ορίσματα, Binding και Εμβέλεια#6. Εμβέλεια μεταβλητών (VIII-23, VIII-24)|VIII – 03]]). Το σχόλιο «αργότερα» σημαίνει ότι ο πίνακας **δημιουργείται** αργότερα, στην `Pascal`, όταν είναι γνωστό το `N`.
> - **`new int[N+1][N+1]`**: οι δείκτες ξεκινούν από `1`, άρα χρειάζονται θέσεις μέχρι `N`· η γραμμή και η στήλη `0` μένουν αχρησιμοποίητες.
> - **Το `0` ως «δεν υπολογίστηκε ακόμη»**: ο πίνακας ξεκινά γεμάτος `0`, και κανένα στοιχείο του τριγώνου δεν είναι `0`, άρα το `0` είναι ασφαλής **φρουρός**.
> - **`return (memo[row][elem]=x+y);`**: η ανάθεση είναι **έκφραση** με τιμή την τιμή που ανατέθηκε – αποθηκεύει και επιστρέφει μαζί.
> - Οι βασικές περιπτώσεις (`1`) δεν αποθηκεύονται – είναι ήδη φτηνές.
> - Το `x`, `y` σε ξεχωριστές γραμμές δεν είναι απαραίτητο· `memo[row][elem] = compute_element(…) + compute_element(…)` θα δούλευε το ίδιο.

> [!warning] ⚠️ Σημείωση για τη X-36
> Στη διαφάνεια η επικεφαλίδα `public static void Pascal (int N)` γράφεται **χωρίς** το `{` που ανοίγει το σώμα (υπάρχει μόνο το `}` που το κλείνει). Παραπάνω προστέθηκε.

> [!warning] ➕ Παγίδες (ελέγχθηκαν)
> - Κλήση της `compute_element` **πριν** από την `Pascal` → `memo` είναι `null` → `NullPointerException`.
> - `compute_element(6, 3)` με `memo = new int[6][6]` → `ArrayIndexOutOfBoundsException: Index 6 out of bounds for length 6`: γι' αυτό το `N+1`.
> - Μη έγκυρα ορίσματα (`elem > row`, π.χ. `ce(3,4)`, ή `elem = 0`): οι βασικές περιπτώσεις `elem == 1` / `elem == row` δεν φτάνονται ποτέ. Χωρίς memo → **`StackOverflowError`**· με memo → **`ArrayIndexOutOfBoundsException`** (`Index -1`), γιατί οι δείκτες `row-1`, `elem-1` γίνονται αρνητικοί και το `memo[row][elem]` ελέγχεται πρώτο.
> - **Υπερχείλιση `int`**: μέχρι τη σειρά 34 όλα χωράνε (μεγαλύτερο `C(33,16)` = 1 166 803 110). Από τη σειρά **35** τα μεσαία στοιχεία υπερχειλίζουν (`ce(35,18)` → `-1961361076`). Με `long` το όριο πάει πολύ πιο πέρα (σειρά 67).

> [!example]- ➕ Επαναληπτική λύση «από κάτω προς τα πάνω» με ακανόνιστο πίνακα
> Αντί για αναδρομή + memo, γέμισε το τρίγωνο σειρά-σειρά: κάθε σειρά χρειάζεται μόνο την προηγούμενη.
> ```java
> int[][] t = new int[N][];
> for (int i = 0; i < N; i++){
>    t[i] = new int[i+1];                     // η σειρά i έχει i+1 στοιχεία
>    t[i][0] = t[i][i] = 1;
>    for (int j = 1; j < i; j++) t[i][j] = t[i-1][j-1] + t[i-1][j];
> }
> ```
> Αυτό είναι ο «καθαρός» δυναμικός προγραμματισμός (όπως ο πίνακας `F` της X-17): **N²/2** προσθέσεις, καμία αναδρομή. Εδώ οι δείκτες ξεκινούν από `0` ([[01 - Δισδιάστατοι και Πολυδιάστατοι Πίνακες#8. ➕ Ακανόνιστοι (ragged) πίνακες|ακανόνιστος πίνακας, IX – 01]]).

| Τεχνική | Κατεύθυνση | Πότε |
|---|---|---|
| Αναδρομή χωρίς μνήμη | από πάνω προς τα κάτω | απλή, εκθετική όταν τα υπο-προβλήματα επικαλύπτονται |
| **Memoization** | από πάνω προς τα κάτω + πίνακας | κρατά τον αναδρομικό ορισμό, κάθε υπο-πρόβλημα μία φορά |
| Πίνακας «από κάτω» (X-17) | από κάτω προς τα πάνω | καμία αναδρομή· πρέπει να ξέρεις τη σειρά υπολογισμού |

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - `memo` ως τοπική μεταβλητή της `compute_element`: φτιάχνεται κενός σε κάθε κλήση → καμία ωφέλεια.
> - `new int[N][N]` με δείκτες από 1 → εκτός ορίων στη σειρά `N`.
> - Φρουρός `0` σε πρόβλημα όπου μια **αποθηκευμένη** τιμή μπορεί να είναι `0` (π.χ. «πλήθος τρόπων», που μπορεί να βγει 0): η τιμή θα ξαναϋπολογίζεται κάθε φορά. Εκεί χρειάζεται `-1` ή πίνακας `boolean` «υπολογίστηκε;». (Στο Fibonacci ο φρουρός `0` αρκεί, αφού το `F(0) = 0` είναι βασική περίπτωση και δεν αποθηκεύεται.)
> - Ξεχασμένη αποθήκευση: `return x + y;` χωρίς `memo[row][elem] = …` → ο πίνακας μένει μηδενικός, η λύση γίνεται πάλι εκθετική.
> - Σύγχυση `compute_element(row, elem)` με `(elem, row)`: η διαφάνεια γράφει τ(E,R) αλλά ο κώδικας παίρνει πρώτα τη **σειρά**.
