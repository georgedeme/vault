# 02 - Παραγοντικό, Αναδρομή Στοίβας και Ουράς

Το παραγοντικό γραμμένο τρεις φορές: **επαναληπτικά**, με **αναδρομή στοίβας** (ο πολλαπλασιασμός γίνεται στην επιστροφή) και με **αναδρομή ουράς** (το αποτέλεσμα «κουβαλιέται» σε παράμετρο). Και τι κοστίζει κάθε αναδρομική κλήση στη μνήμη (διαφάνειες X-8 … X-12, X-29).

## 1. Ο ορισμός (X-8)

```
0! = 1
1! = 1
2! = 1 × 2
3! = 1 × 2 × 3 = 2! × 3
. . . . . . .
n! = 1 × 2 × . . . × (n – 1) × n
   = (n – 1)! × n
```

Η τελευταία γραμμή είναι **αναδρομικός ορισμός**: το `n!` ορίζεται μέσω του `(n-1)!`.

## 2. Επαναληπτικός ορισμός (X-9)

```java
/* Iterative definition */
public static int factorial (int x){
   /* assumes x ≥ 0 */
   int res = 1;
   while (x > 1) {res = res * x;  x = x - 1;}
   return res;
}
```

Το `res` συσσωρεύει το γινόμενο `x · (x-1) · … · 2`. Για `x = 0` ή `1` ο βρόχος δεν εκτελείται → `1`.

## 3. Αναδρομή στοίβας (X-9, X-10)

```java
/* (Stack) Recursive definition */
public static int factorial (int x){
   if (x == 0 || x == 1) return 1;
   else return x * factorial(x - 1); }
```

```
factorial(4)
⇒ 4 * factorial(3)
⇒ 4 * 3 * factorial(2)
⇒ 4 * 3 * 2 * factorial(1)
⇒ 4 * 3 * 2 * 1
⇒ 24
```

> [!important] Γιατί «στοίβας»
> Η κλήση `factorial(4)` **δεν μπορεί** να υπολογίσει το `4 * …` πριν επιστρέψει η `factorial(3)`. Ο πολλαπλασιασμός μένει **σε εκκρεμότητα** και θυμάται το `4` στο πλαίσιό της στη στοίβα. Τα πλαίσια συσσωρεύονται μέχρι τη βασική περίπτωση· μετά, στην επιστροφή, κάθε πλαίσιο κάνει τον δικό του πολλαπλασιασμό: `1 → 2 → 6 → 24` (**«συσσώρευση αποτελεσμάτων»**, X-10).

## 4. Αναδρομή ουράς (X-11)

```java
/* (Tail) Recursive definition */
public static int factorial (int x){
    return factorial(x,1);
}

// Function overloading
private static int factorial (int x, int res){
    if (x == 0 || x == 1) return res;
    else return factorial(x-1, res*x); }
```

```
factorial(4)
⇒ factorial(4,1)
⇒ factorial(3,4)
⇒ factorial(2,12)
⇒ factorial(1,24)
⇒ 24
```

> [!important] Γιατί «ουράς»
> Η αναδρομική κλήση είναι η **τελευταία** ενέργεια (στην «ουρά» της συνάρτησης) και το αποτέλεσμά της επιστρέφεται **αυτούσιο** – δεν μένει τίποτα να γίνει μετά. Το μερικό γινόμενο ταξιδεύει **μπροστά**, στη **συσσωρευτική παράμετρο** `res`: ο πολλαπλασιασμός γίνεται **πριν** την κλήση (`res*x` ως όρισμα), όχι μετά.
>
> - «Ισοδύναμη» με επανάληψη: `x` και `res` είναι ακριβώς οι μεταβλητές του `while` της X-9.
> - **Function overloading** ([[05 - Υπερφόρτωση Συναρτήσεων|VIII – 05]]): η `public` εκδοχή με μία παράμετρο είναι η διεπαφή· η `private` με δύο κρύβει τη συσσωρευτική παράμετρο και την αρχική της τιμή `1` από τον χρήστη.

![[Αναδρομή - Στοίβα και Ουρά.png|800]]

| | Αναδρομή στοίβας | Αναδρομή ουράς |
|---|---|---|
| Τελευταία ενέργεια | `x * (αποτέλεσμα κλήσης)` | η κλήση |
| Πού γίνεται η δουλειά | στην **επιστροφή** | στην **κάθοδο** (στα ορίσματα) |
| Τι επιστρέφει κάθε πλαίσιο | διαφορετική τιμή (`1, 2, 6, 24`) | την **ίδια** τιμή (`24` από όλα) |
| Επιπλέον παράμετρος | όχι | συσσωρευτής `res` |
| Μετατροπή σε βρόχο | χρειάζεται σκέψη | μηχανική |

## 5. Επισημάνσεις αναφορικά με την αναδρομή (X-12)

> [!note] Επισημάνσεις
> 1. Διαχωρισμός ανάμεσα σε **τερματικές** (βασικές) και **αναδρομικές** (γενικές) περιπτώσεις, με χρήση εντολής **επιλογής**.
> 2. Η αναδρομική κλήση πρέπει να είναι **ένα βήμα πιο κοντά** σε τερματική περίπτωση, από την κλήση που οδήγησε σε αυτήν.
> 3. «**Ισοδυναμία**» με επανάληψη.

## 6. Μνήμη και StackOverflowError (X-29)

> [!note] Μνήμη
> - Κάθε αναδρομική κλήση **δεσμεύει ξεχωριστό χώρο** στη μνήμη (έχει το δικό της περιβάλλον εκτέλεσης – πλαίσιο με τις δικές της παραμέτρους και τοπικές μεταβλητές).
> - **Αποδεσμεύεται** όταν επιστρέψουμε από την κλήση που δέσμευσε τον χώρο.
> - Πολύ **βαθιές** αναδρομές κοστίζουν σε χώρο και χρόνο: μπορεί να οδηγήσουν σε **Stack overflow** εξαίρεση.

> [!warning] ➕ Η Java **δεν** βελτιστοποιεί την αναδρομή ουράς (ελέγχθηκε)
> Σε κάποιες γλώσσες (Scheme, Haskell, μεταγλωττιστές C με βελτιστοποίηση) η αναδρομή ουράς εκτελείται χωρίς νέο πλαίσιο – σαν βρόχος. Η Java **όχι**: κάθε κλήση της `factorial(x, res)` παίρνει δικό της πλαίσιο. `factorial(100000)` με την εκδοχή ουράς → **`StackOverflowError`**, όπως και η εκδοχή στοίβας. Η «ισοδυναμία με επανάληψη» της X-11 αφορά τη **λογική** (τη δομή του υπολογισμού), όχι τη μνήμη.

> [!warning] ➕ Παγίδες του παραγοντικού (ελέγχθηκαν)
>
> | Είσοδος | Επαναληπτικό | Στοίβας / ουράς | Σχόλιο |
> |---|---|---|---|
> | `12` | `479001600` | `479001600` | το μεγαλύτερο σωστό με `int` |
> | `13` | `1932053504` | `1932053504` | **λάθος** (σωστό: 6 227 020 800) – υπερχείλιση, και μάλιστα **θετικό**, άρα δεν «φαίνεται» |
> | `17` | `-288522240` | ίδιο | αρνητικό |
> | `20` | – | – | με `long`: `2432902008176640000` ✓ · `21!` υπερχειλίζει και το `long` |
> | `-3` | **`1`** | – | ο βρόχος δεν εκτελείται: σιωπηλά λάθος |
> | `-1` | – | **`StackOverflowError`** | η βασική περίπτωση (`0` ή `1`) δεν φτάνεται ποτέ: `-1, -2, -3, …` |
>
> Το σχόλιο `/* assumes x ≥ 0 */` είναι **προϋπόθεση** που ο κώδικας δεν ελέγχει. Ασφαλέστερη βασική περίπτωση: `if (x <= 1) return 1;` (τερματίζει για κάθε είσοδο, αλλά επιστρέφει `1` για αρνητικούς).

## 7. ➕ Πριν ή μετά την αναδρομική κλήση

Η **θέση** μιας εντολής σε σχέση με την αναδρομική κλήση καθορίζει **πότε** εκτελείται: πριν την κλήση → στην **κάθοδο** (με τη σειρά των κλήσεων)· μετά την κλήση → στην **επιστροφή** (με την **αντίστροφη** σειρά). Το ίδιο φαινόμενο με το `Reverse` της [[02 - Διαδραστική Είσοδος και Αναδρομή#Η στοίβα του συστήματος (System Stack, VII-21 … VII-30)|Ενότητας VII]].

```java
static void down(int n){ if (n == 0) return; System.out.print(n + " "); down(n-1); }
static void up  (int n){ if (n == 0) return; up(n-1); System.out.print(n + " "); }
static void both(int n){ if (n == 0) return; System.out.print(n + " "); both(n-1); System.out.print(n + " "); }
static void two (int n){ if (n == 0) return; two(n-1); System.out.print(n + " "); two(n-1); }
```

| Κλήση | Έξοδος (ελέγχθηκε) | Γιατί |
|---|---|---|
| `down(4)` | `4 3 2 1` | τυπώνει στην κάθοδο |
| `up(4)` | `1 2 3 4` | τυπώνει στην επιστροφή |
| `both(3)` | `3 2 1 1 2 3` | και στα δύο – «καθρέφτης» |
| `two(3)` | `1 2 1 3 1 2 1` | **δύο** αναδρομικές κλήσεις: δέντρο, όχι αλυσίδα · `2³ − 1 = 7` εκτυπώσεις |

![[Αναδρομή - Σειρά Εκτύπωσης.png|800]]

> [!example]- ➕ Ακόμα μια «παγίδα» βασικής περίπτωσης (ελέγχθηκε)
> ```java
> static void count(int n){ System.out.print(n + " "); if (n != 0) count(n-2); }
> ```
> `count(4)` → `4 2 0` ✓. `count(5)` → `5 3 1 -1 -3 …` → `StackOverflowError`: το βήμα `-2` **πηδά πάνω** από τη βασική περίπτωση `0`. Με `if (n > 0)` αντί για `n != 0`: `count(5)` → `5 3 1 -1` και σταματά.

## Συχνά Λάθη

> [!warning] Συχνά Λάθη
> - Σύγχυση: «αναδρομή ουράς» = η κλήση είναι **τελευταία**. Το `return x * factorial(x-1);` **δεν** είναι ουράς, παρόλο που η κλήση είναι «στο τέλος της γραμμής»: μετά από αυτήν γίνεται ακόμη ο πολλαπλασιασμός.
> - Λάθος αρχική τιμή του συσσωρευτή (`factorial(x, 0)` → πάντα `0`).
> - Πίστη ότι η αναδρομή ουράς στη Java δεν γεμίζει τη στοίβα.
> - `int` για παραγοντικά πάνω από `12!`.
> - Βασική περίπτωση με `==` που μπορεί να «πηδηχτεί» (`n != 0` με βήμα 2, αρνητικά ορίσματα).
