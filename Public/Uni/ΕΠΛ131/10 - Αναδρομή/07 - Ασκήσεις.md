# 07 - Ασκήσεις

20 ασκήσεις στο ύφος των διαφανειών της Ενότητας X. **Λύσε πρώτα, άνοιξε μετά.** Όλες οι απαντήσεις ελέγχθηκαν με `javac`/`java` 17.

> [!tip] Πώς να το χρησιμοποιήσεις
> Για κάθε αναδρομική συνάρτηση γράψε πρώτα τη **βασική περίπτωση** και το **βήμα**. Στα ίχνη γράψε μία γραμμή ανά κλήση (όπως οι διαφάνειες, με `⇒`) ή σχεδίασε το δέντρο κλήσεων όταν υπάρχουν δύο αναδρομικές κλήσεις.

## Μέρος Α — Βασικές έννοιες και ίχνη

### Άσκηση 1

Κάνε ίχνος της `gcd(1071, 462)` (X-7). Πόσες κλήσεις γίνονται; Τι δίνει η `gcd(462, 1071)`;

> [!success]- Λύση
> `gcd(1071, 462)` ⇒ `gcd(462, 147)` (`1071 = 2·462 + 147`) ⇒ `gcd(147, 21)` (`462 = 3·147 + 21`) ⇒ `gcd(21, 0)` (`147 = 7·21`) ⇒ **`21`**. Τέσσερις κλήσεις.
> `gcd(462, 1071)` → επίσης `21`, με μία κλήση παραπάνω: το πρώτο βήμα δίνει `gcd(1071, 462)` (`462 % 1071 = 462`).

### Άσκηση 2

Τι υπολογίζει η `mystery`; Τι δίνουν `mystery(3,4)`, `mystery(0,5)`, `mystery(5,0)`; Τι γίνεται με `mystery(3,-1)`;
```java
static int mystery(int a, int b){ if (b == 0) return 0; return a + mystery(a, b-1); }
```

> [!success]- Λύση
> Το γινόμενο `a·b` (για `b ≥ 0`), ως επαναλαμβανόμενη πρόσθεση: `12`, `0`, `0`. Με `b = -1` το `b` απομακρύνεται από το `0` (`-1, -2, …`) → `StackOverflowError`.

### Άσκηση 3

Τι τυπώνουν;
```java
static void g(int n){ if (n <= 0) return; System.out.print(n + " "); g(n-2); System.out.print(n + " "); }
static void h(int n){ if (n <= 0) return; h(n-1); h(n-1); System.out.print(n + " "); }
```
(α) `g(5)` (β) `h(3)`

> [!success]- Λύση
> (α) `5 3 1 1 3 5` – εκτύπωση πριν και μετά την κλήση: «καθρέφτης». Η βασική περίπτωση `n <= 0` πιάνει και το `-1` (με `n == 0` θα έπεφτε σε `StackOverflowError`).
> (β) `1 1 2 1 1 2 3` – δύο κλήσεις **πριν** την εκτύπωση: πρώτα τα δύο υπο-δέντρα, μετά ο κόμβος (post-order). `h(n)` τυπώνει `2ⁿ − 1` αριθμούς.

### Άσκηση 4

Τι κάνει λάθος αυτή η εκδοχή; Για ποιες εισόδους δουλεύει;
```java
static int fact1(int x){ if (x == 1) return 1; return x * fact1(x-1); }
```

> [!success]- Λύση
> Δεν έχει βασική περίπτωση για το `0`: `fact1(0)` ⇒ `0 * fact1(-1)` ⇒ … → `StackOverflowError` (ελέγχθηκε). Δουλεύει για `x ≥ 1`. Η διαφάνεια X-9 έχει `x == 0 || x == 1`.

### Άσκηση 5

Πόσα πλαίσια βρίσκονται **ταυτόχρονα** στη στοίβα (μέγιστο βάθος, χωρίς τη `main`) για `factorial(5)` (α) με αναδρομή στοίβας (β) με αναδρομή ουράς της X-11;

> [!success]- Λύση
> (α) **5**: `factorial(5)` … `factorial(1)`.
> (β) **6**: η `public factorial(5)` συν πέντε κλήσεις της `private factorial(x, res)`: `(5,1)`, `(4,5)`, `(3,20)`, `(2,60)`, `(1,120)`. Η Java δεν «διπλώνει» την αναδρομή ουράς, άρα δεν κερδίζει μνήμη.

## Μέρος Β — Γράψε αναδρομικά

### Άσκηση 6

Γράψε `sumDigits(int n)` (άθροισμα ψηφίων, `n ≥ 0`) με αναδρομή **στοίβας**, και μετά με αναδρομή **ουράς** (με overloading `public`/`private`). Τι δίνουν για `4032` και για `0`;

> [!success]- Λύση
> ```java
> static int sumDigits(int n){ if (n < 10) return n; return n % 10 + sumDigits(n / 10); }
>
> public static int sumDigitsT(int n){ return sumDigitsT(n, 0); }
> private static int sumDigitsT(int n, int acc){
>    if (n == 0) return acc;
>    return sumDigitsT(n / 10, acc + n % 10);
> }
> ```
> `9` και `0` και στις δύο. Στη στοίβας η πρόσθεση `n % 10 + …` μένει σε εκκρεμότητα· στην ουράς γίνεται στο όρισμα `acc + n % 10`.

### Άσκηση 7

Γράψε `power(long b, int e)` με `bᵉ = b · bᵉ⁻¹`. Μετά γράψε `fastPow` με `bᵉ = (b^{e/2})²` (επί `b` αν το `e` είναι περιττό). Πόσες κλήσεις κάνει καθεμία για `2³⁰`;

> [!success]- Λύση
> ```java
> static long power(long b, int e){ if (e == 0) return 1; return b * power(b, e-1); }
> static long fastPow(long b, int e){
>    if (e == 0) return 1;
>    long h = fastPow(b, e/2);                 // ΜΙΑ κλήση, αποθηκευμένη
>    return (e % 2 == 0) ? h*h : h*h*b;
> }
> ```
> Και οι δύο: `1073741824`. `power`: **31** κλήσεις (`e = 30 … 0`). `fastPow`: **6** (`30, 15, 7, 3, 1, 0`) – λογαριθμικό, επειδή το `e` **υποδιπλασιάζεται**. Αν γραφόταν `fastPow(b, e/2) * fastPow(b, e/2)` (δύο κλήσεις), θα χανόταν όλο το κέρδος – ίδια παγίδα με το Fibonacci.

### Άσκηση 8

Γράψε `String bin(int n)` που επιστρέφει τη δυαδική αναπαράσταση του `n ≥ 0`. Τι δίνει για `13`, `0`, `8`;

> [!success]- Λύση
> ```java
> static String bin(int n){ if (n < 2) return "" + n; return bin(n/2) + n%2; }
> ```
> `1101`, `0`, `1000`. Το τελευταίο ψηφίο (`n % 2`) μπαίνει **μετά** την αναδρομική κλήση, άρα τα ψηφία βγαίνουν από το σημαντικότερο προς το λιγότερο σημαντικό – ενώ υπολογίζονται ανάποδα.

### Άσκηση 9

Γράψε αναδρομικά `sumArr(int[] a, int i)` (άθροισμα από τη θέση `i` ως το τέλος) και `maxArr(int[] a, int n)` (μέγιστο των πρώτων `n`). Τι γίνεται με κενό πίνακα σε καθεμία;

> [!success]- Λύση
> ```java
> static int sumArr(int[] a, int i){ if (i == a.length) return 0; return a[i] + sumArr(a, i+1); }
> static int maxArr(int[] a, int n){ if (n == 1) return a[0]; return Math.max(a[n-1], maxArr(a, n-1)); }
> ```
> `sumArr({3,1,4,1,5}, 0)` → `14` · `maxArr({3,9,4,1,5}, 5)` → `9`.
> Κενός: `sumArr(new int[0], 0)` → `0` ✓ (η βασική περίπτωση πιάνει αμέσως). `maxArr(new int[0], 0)` → `ArrayIndexOutOfBoundsException` (`a[-1]`): το μέγιστο κενού πίνακα δεν ορίζεται, η βασική περίπτωση `n == 1` δεν το καλύπτει.

### Άσκηση 10

Γράψε **αναδρομική** δυαδική αναζήτηση `bs(int[] a, int key, int lo, int hi)` που επιστρέφει τη θέση ή `-1`. Πόσες κλήσεις κάνει στο `{1,3,5,7,9,11,13}` για το `11` και για το `4`;

> [!success]- Λύση
> ```java
> static int bs(int[] a, int key, int lo, int hi){
>    if (lo > hi) return -1;                           // κενό διάστημα: δεν υπάρχει
>    int mid = (lo + hi) / 2;
>    if (a[mid] == key) return mid;
>    if (a[mid] < key) return bs(a, key, mid+1, hi);   // δεξί μισό
>    return bs(a, key, lo, mid-1);                     // αριστερό μισό
> }
> ```
> `11` → θέση `5`, **2** κλήσεις (`mid = 3` → `7`, μετά `mid = 5`). `4` → `-1`, **4** κλήσεις. Αναδρομή ουράς, «διαίρει και βασίλευε», `log₂N` βήματα ([[06 - Αναζήτηση και break|IV – 06]]).

### Άσκηση 11

**Πύργοι του Ανόι:** μετακίνησε `n` δίσκους από το `A` στο `C` με βοηθητικό το `B` (ένας δίσκος τη φορά, ποτέ μεγάλος πάνω σε μικρό). Γράψε τη `hanoi(n, from, to, via)` που τυπώνει τις κινήσεις. Ποιες είναι για `n = 2`; Πόσες κινήσεις για `n = 10`;

> [!success]- Λύση
> ```java
> static void hanoi(int n, char from, char to, char via){
>    if (n == 0) return;
>    hanoi(n-1, from, via, to);                    // οι n-1 μικροί στο βοηθητικό
>    System.out.print(from + "->" + to + " ");     // ο μεγαλύτερος στον προορισμό
>    hanoi(n-1, via, to, from);                    // οι n-1 πάνω του
> }
> ```
> `n = 2`: `A->B A->C B->C`. Κινήσεις: `M(n) = 2·M(n-1) + 1` → **`2ⁿ − 1`**: `1023` για `n = 10`, `1 048 575` για `n = 20`. Εδώ η εκθετική πολυπλοκότητα **δεν** είναι σπατάλη: τόσες κινήσεις χρειάζονται πράγματι.

## Μέρος Γ — Fibonacci και αποδοτικότητα

### Άσκηση 12

Πόσες κλήσεις συνολικά κάνει η `F(6)` της X-14; Πόσες φορές καλείται η `F(2)`;

> [!success]- Λύση
> Συνολικά **25** = `2·F(7) − 1 = 2·13 − 1`. Η `F(2)` καλείται **5** φορές (= `F(5)`): γενικά η `F(k)` καλείται `F(n−k+1)` φορές μέσα στην `F(n)`.

### Άσκηση 13

Τι επιστρέφουν; (α) `fibTail(1, 1, 5)` (β) `fibTail(0, 1, 5)` (γ) η `fibIter` **χωρίς** το `temp`, δηλαδή με σώμα `a = b; b = b + a; x--;`, για `x = 5`.

> [!success]- Λύση
> (α) `8` = `F(6)`: η ακολουθία ξεκινά «ένα βήμα μπροστά». (β) `5` = `F(5)`. (γ) **`16`**: μετά το `a = b`, το `b + a` είναι `2b` – το `b` διπλασιάζεται: `a` = `1, 2, 4, 8, 16` (`2^{x-1}`). Η σειρά των αναθέσεων μετράει.

### Άσκηση 14

Γράψε Fibonacci με **memoization** (`private static long[] memo`). Γιατί εδώ ο φρουρός `0` είναι ασφαλής, ενώ γενικά θέλει προσοχή;

> [!success]- Λύση
> ```java
> private static long[] memo;
> public static long fibMemo(int n){ memo = new long[n+1]; return fm(n); }
> private static long fm(int n){
>    if (n == 0) return 0;
>    if (n == 1) return 1;
>    if (memo[n] != 0) return memo[n];
>    return memo[n] = fm(n-1) + fm(n-2);
> }
> ```
> `fibMemo(50)` → `12586269025` αμέσως: κάθε `fm(k)` υπολογίζεται μία φορά (≈ `2n` κλήσεις). Ο φρουρός `0` είναι ασφαλής γιατί η μόνη τιμή `0` (`F(0)`) είναι βασική περίπτωση και δεν αποθηκεύεται. Αν μια αποθηκευμένη τιμή μπορούσε να είναι `0`, θα ξαναϋπολογιζόταν κάθε φορά.

### Άσκηση 15

Ποια από τις παρακάτω είναι αναδρομή **ουράς**;
(α) `return x * f(x-1);` (β) `return f(x-1, acc*x);` (γ) `return f(x-1) + 1;` (δ) `if (c) return f(x-1); else return g(x);` (ε) `return f(f(x-1));`

> [!success]- Λύση
> (β) και (δ): η κλήση είναι η τελευταία ενέργεια και το αποτέλεσμά της επιστρέφεται αυτούσιο. Στο (α) και (γ) γίνεται πράξη **μετά**. Στο (ε) η εσωτερική `f(x-1)` **δεν** είναι σε θέση ουράς (το αποτέλεσμά της γίνεται όρισμα), η εξωτερική είναι.

## Μέρος Δ — Συμβολοσειρές και Pascal

### Άσκηση 16

Τι επιστρέφουν για `"Hello!"`;
(α) η εκδοχή ουράς με `r + s.substring(0,1)` στη θέση του `s.substring(0,1) + r`
(β) `if (s.length() <= 1) return s; return s.substring(0,1) + f(s.substring(1));`
(γ) `if (s.length() <= 1) return s; return f(s.substring(1)) + s.charAt(0);` – και τι για `""`;

> [!success]- Λύση
> (α) `"!Hello"` – ο συσσωρευτής χτίζεται με την αρχική σειρά (`H`, `He`, …, `Hello`) και στο τέλος `s + r` = `"!" + "Hello"`.
> (β) `"Hello!"` – ο πρώτος μένει πρώτος σε κάθε επίπεδο.
> (γ) `"!olleH"` ✓ και `""` για `""` – η βασική περίπτωση `<= 1` καλύπτει και το κενό.

### Άσκηση 17

Γράψε αναδρομική `pal(String s)` (παλινδρομικό). Γιατί δεν χρειάζεται `if … else` μετά τη βασική περίπτωση;

> [!success]- Λύση
> ```java
> static boolean pal(String s){
>    if (s.length() <= 1) return true;
>    return s.charAt(0) == s.charAt(s.length()-1) && pal(s.substring(1, s.length()-1));
> }
> ```
> `pal("racecar")` → `true` · `pal("abca")` → `false`. Το `&&` κάνει short-circuit: αν τα άκρα διαφέρουν, το `false` επιστρέφεται χωρίς αναδρομική κλήση – η επιλογή είναι «κρυμμένη» μέσα στον τελεστή.

### Άσκηση 18

Υπολόγισε `compute_element(6, 3)` (X-34). Πόσες κλήσεις κάνει χωρίς memo; Ποιος διωνυμικός συντελεστής είναι;

> [!success]- Λύση
> `10` = C(5, 2) (σειρά 6: `1 5 10 10 5 1`). Κλήσεις: **19** = `2·10 − 1` (κάθε φύλλο του δέντρου επιστρέφει `1`, άρα υπάρχουν 10 φύλλα και 9 εσωτερικοί κόμβοι).

### Άσκηση 19

Στη memoization της X-36, τι πάει στραβά αν: (α) ο `memo` δηλωθεί ως **τοπική** μεταβλητή μέσα στη `compute_element`; (β) γραφτεί `memo = new int[N][N];`; (γ) η τελευταία γραμμή γίνει `return x + y;`;

> [!success]- Λύση
> (α) Νέος, μηδενικός πίνακας σε **κάθε** κλήση: τίποτα δεν «θυμάται» → πάλι εκθετικό (και μνήμη `N²` ανά κλήση).
> (β) Στη σειρά `N` → `memo[N][…]` εκτός ορίων → `ArrayIndexOutOfBoundsException` (οι δείκτες ξεκινούν από 1).
> (γ) Τίποτα δεν αποθηκεύεται: το αποτέλεσμα είναι σωστό αλλά ο χρόνος είναι εκθετικός, όπως χωρίς memo.

### Άσκηση 20

Γράψε την `isEven`/`isOdd` (έμμεση αναδρομή) και εξήγησε τι γίνεται με `isEven(-2)`. Διόρθωσέ τες ώστε να δουλεύουν για κάθε ακέραιο.

> [!success]- Λύση
> Με `isEven(n) { if (n == 0) return true; return isOdd(n-1); }` και συμμετρικά την `isOdd`: `isEven(-2)` ⇒ `isOdd(-3)` ⇒ … – το `n` απομακρύνεται από το `0` → `StackOverflowError`. Διόρθωση: στη δημόσια συνάρτηση `n = Math.abs(n);` πριν την αναδρομή (η αρτιότητα δεν αλλάζει με το πρόσημο). (Πρακτικά, βέβαια, `n % 2 == 0` – η άσκηση δείχνει τη μορφή της έμμεσης αναδρομής.)
